# 模拟测试机制结构化梳理

## 1. 核心定义

模拟测试，是指在 H5 Playable 组装完成之后、正式发布之前，系统用模拟用户、测试脚本、设备环境和事件校验机制，对 `playable_version` 进行发布前质量验证，确认它是否可打开、可开始、可完成、可失败、可分享、可点击 CTA、可触发奖励、可记录数据，并且 Runtime Agent 的动态策略不会突破 `game_rules` 和合规边界。

它不是简单人工试玩，也不是上线后的真实数据复盘，而是发布前的自动化质量闸口。

| 容易误解 | 正确认知 |
|---|---|
| 模拟测试就是人工点一遍 | 应该用模拟用户和测试脚本跑关键路径 |
| 页面能打开就算通过 | 还要检查规则、奖励、CTA、分享、埋点、Agent 和风控 |
| 只测试成功路径 | 还要测试失败、重试、异常、降级和边界路径 |
| 测试结果只给工程看 | 也要给 KOL、运营、发布服务和数据系统使用 |
| 发现问题直接发布后修 | 发布前必须阻止关键路径、奖励、CTA 和埋点错误 |

一句话：

**模拟测试 = 用系统化的模拟用户跑一遍 H5 Playable 的关键路径，生成 `simulation_result`，决定这个版本能不能进入发布。**

## 2. 在完整工作流中的位置

模拟测试发生在 H5 组装之后、正式发布之前。它承接 Builder 输出，也决定发布服务是否可以继续。

| 阶段 | 输入 | 输出 |
|---|---|---|
| KOL 身份识别 | KOL 注册、社媒、历史 campaign、风险信号 | `kol_context` |
| 营销目标选择 | 目标、CTA、指标、渠道 | `campaign_goal` |
| 模板推荐 | 目标、KOL、资产、渠道 | `template_schema` |
| 关键变量填写 | 主题、奖励、任务、CTA、风格 | `template_config` |
| Brief 生成 | 上游意图和约束 | `generation_brief` |
| 内容生成 | Brief、模板、资产库 | `content_assets` |
| 游戏规则生成 | Brief、模板、内容、目标 | `game_rules` |
| Agent 运营策略生成 | 目标、规则、用户路径、风险 | `agent_policy` |
| 约束与合规验证 | 内容、规则、策略、目标、资产 | `validation_report` |
| H5 Playable 组装 | 通过验证的对象、模板代码、资产 | `playable_version` |
| 模拟测试 | 可运行版本、模拟用户、关键路径、事件要求 | `simulation_result` |
| KOL 预览 / 二次编辑 | 测试通过的预览版本、KOL 修改 | `config_patch`、新版本 |
| 发布投放 | 测试通过版本、渠道参数 | `publish_url` |
| 运行时优化 | 用户事件、Agent 策略 | `runtime_decision` |
| 数据反馈 | 事件、结果、Agent 决策 | `kol_memory`、`template_memory` |

关键原则：

1. 没有通过模拟测试，不能进入正式发布。
2. 模拟测试必须基于具体 `playable_version`，不能只测模板。
3. 测试要覆盖成功路径、失败路径、异常路径和降级路径。
4. 测试必须检查关键事件是否被记录。
5. KOL 修改后，受影响路径必须重新测试。

## 3. 模拟测试的核心目标

| 目标 | 说明 |
|---|---|
| 可访问 | `preview_url` 可以打开，H5 不白屏、不 404、不资源缺失 |
| 可交互 | 用户能点击、选择、拖拽、射击、画线或完成模板核心操作 |
| 可完成 | 用户能从开始走到完成状态 |
| 可失败 | 失败、重试、退出、返回路径正常 |
| 可结算 | 得分、结果等级、奖励展示和触发符合 `game_rules` |
| 可转化 | CTA 出现、点击、跳转和归因正常 |
| 可分享 | 分享按钮、分享卡、邀请链接、渠道参数正常 |
| 可追踪 | 曝光、开始、步骤、奖励、分享、CTA、转化、流失事件完整 |
| 可 Agent | Runtime Agent 策略能执行、记录或安全降级 |
| 可风控 | 异常速度、重复提交、刷分、重复钱包等可识别 |
| 可发布 | 达到发布门槛，输出明确 `publish_readiness` |

## 4. 主要输入

| 输入 | 来源 | 用途 |
|---|---|---|
| `playable_version` | H5 Builder | 被测试的具体 H5 版本 |
| `preview_url` | H5 Builder / 预览服务 | 模拟用户访问入口 |
| `build_manifest` | H5 Builder | 确认模板、资产、规则、策略版本 |
| `runtime_config` | H5 Builder | 确认运行时配置和默认策略 |
| `tracking_map` | H5 Builder / Analytics | 决定必须验证的事件 |
| `game_rules` | Rule Agent | 决定成功、失败、奖励、CTA 和反作弊预期 |
| `agent_policy` | Strategy Agent | 决定动态策略和可调边界 |
| `validation_report` | Constraint Service | 确认合规和约束状态 |
| `test_scenarios` | 测试系统 / 模板库 | 定义要跑哪些路径 |
| `simulated_users` | 测试系统 | 定义不同用户状态和行为 |
| `device_matrix` | 测试系统 | 定义手机、浏览器、WebView 和网络环境 |
| `publish_threshold` | 发布服务 / 运营策略 | 决定通过标准 |

## 5. 核心输出

统一输出对象是 `simulation_result`。

| 输出字段 | 含义 |
|---|---|
| `simulation_result_id` | 模拟测试报告 ID |
| `playable_version_id` | 被测试版本 |
| `preview_url` | 测试入口 |
| `test_scope` | 全量、核心路径、Patch 回归、发布前测试 |
| `test_status` | passed、warning、failed、blocked |
| `publish_readiness` | 是否允许发布 |
| `passed_cases` | 通过的测试用例 |
| `failed_cases` | 失败的测试用例 |
| `warning_cases` | 有风险但不阻止发布的用例 |
| `broken_paths` | 跑不通的用户路径 |
| `missing_events` | 缺失的埋点 |
| `agent_policy_issues` | Agent 策略问题 |
| `rule_issues` | 游戏规则执行问题 |
| `performance_warnings` | 加载、卡顿、资源体积问题 |
| `risk_flags` | 风控和异常行为风险 |
| `screenshots` | 关键页面截图，可选 |
| `replay_logs` | 模拟用户行为日志 |
| `fix_suggestions` | 修复建议 |
| `next_action` | 发布、重构建、重生成规则、重测或人工检查 |

## 6. 测试类型总览

| 测试类型 | 目的 | 是否 P0 必需 |
|---|---|---:|
| 可访问测试 | 确认 H5 能打开 | 必须 |
| 核心路径测试 | 确认用户能从开始到结果页 | 必须 |
| 规则执行测试 | 确认 `game_rules` 在前端正确执行 | 必须 |
| 奖励测试 | 确认奖励展示和触发符合规则 | 必须 |
| CTA 测试 | 确认 CTA 展示、点击、跳转和归因正常 | 必须 |
| 埋点测试 | 确认关键事件完整上报 | 必须 |
| Agent 策略测试 | 确认动态策略执行或降级 | 必须 |
| 分享测试 | 确认分享按钮、分享卡和链接正常 | 必须 |
| 失败路径测试 | 确认失败、重试、退出路径正常 | 必须 |
| 风控测试 | 确认异常速度、重复提交、刷分被标记 | 建议 P0，强奖励必需 |
| 性能测试 | 确认首屏加载、交互响应、资源体积 | 建议 |
| 多设备测试 | 确认移动端、WebView、不同尺寸表现 | 建议 |
| 回归测试 | KOL 修改后只测受影响模块 | 建议 |

## 7. 测试准入条件

模拟测试不是所有半成品都能跑。进入模拟测试前，需要满足基本条件。

| 条件 | 是否必须 | 说明 |
|---|---:|---|
| `playable_version_id` 存在 | 必须 | 必须测试具体版本 |
| `preview_url` 可生成 | 必须 | 没有入口无法测试 |
| `build_manifest` 完整 | 必须 | 要知道版本由哪些对象构成 |
| `runtime_config` 可读取 | 必须 | 前端必须能加载配置 |
| `tracking_map` 存在 | 必须 | 否则无法判断事件是否缺失 |
| `game_rules` 已通过验证 | 必须 | 规则本身不通过，不进入测试 |
| `agent_policy` 已通过验证 | 必须 | Agent 边界不清不能测试 |
| `validation_report` 允许继续 | 必须 | blocked 不应进入发布测试 |
| 关键资产可访问 | 必须 | Logo、背景、任务和 CTA 资产不能缺失 |
| 渠道配置可缺省 | 可选 | 预览测试可用默认渠道，发布测试必须补齐 |

## 8. 模拟用户设计

模拟测试要用不同类型的模拟用户，而不是只跑一个理想用户。

| 模拟用户 | 行为特点 | 测试目的 |
|---|---|---|
| 新用户 | 第一次打开，按正常路径玩 | 验证基础体验 |
| 快速完成用户 | 很快点击和提交 | 验证异常速度和防刷 |
| 低耐心用户 | 中途退出或跳过 | 验证流失和重试 |
| 高参与用户 | 完成任务、分享、点击 CTA | 验证完整转化链路 |
| 失败用户 | 故意答错或操作失败 | 验证失败和补救路径 |
| 分享型用户 | 完成后点击分享 | 验证分享链路 |
| CTA 用户 | 看到 CTA 后点击跳转 | 验证转化和归因 |
| 异常用户 | 重复提交、刷分、重复钱包 | 验证风控 |
| Agent 触发用户 | 触发难度、提示、CTA 策略 | 验证 Agent 运行 |
| 回访用户 | 第二次进入或继续任务 | 验证留存路径 |

MVP 阶段至少需要：

1. 正常完成用户。
2. 失败重试用户。
3. 分享用户。
4. CTA 用户。
5. 异常速度用户。
6. Agent 触发用户。

## 9. 测试场景结构

每个测试场景应该结构化，而不是写成自然语言描述。

| 字段 | 含义 |
|---|---|
| `scenario_id` | 场景 ID |
| `scenario_name` | 场景名称 |
| `template_type` | 竞猜、空投、跑酷、塔防、射击、画线、模拟经营等 |
| `user_profile` | 使用哪个模拟用户 |
| `entry_url` | 测试入口 |
| `preconditions` | 进入前条件 |
| `steps` | 模拟用户动作列表 |
| `expected_states` | 预期页面或规则状态 |
| `expected_events` | 预期事件 |
| `expected_agent_decisions` | 预期 Agent 决策或不触发 |
| `expected_result` | 预期结果 |
| `blocking_level` | 失败是否阻止发布 |
| `retry_policy` | 失败是否重试 |

## 10. 核心路径测试

核心路径测试用于确认用户能完成最基本的可玩流程。

| 测试项 | 检查内容 | 阻止发布 |
|---|---|---:|
| 打开 H5 | `preview_url` 返回成功，页面不白屏 | 是 |
| 首屏可见 | 标题、KOL、项目、按钮、免责声明正常 | 是 |
| 点击开始 | 开始按钮可点击，进入游戏状态 | 是 |
| 完成第一步 | 第一个任务、题目或关卡可完成 | 是 |
| 进入中间状态 | 进度、得分、反馈正确 | 是 |
| 完成核心目标 | 用户能到达成功或结果页 | 是 |
| 结果展示 | 分数、等级、奖励、反馈正确 | 是 |
| CTA 展示 | CTA 在正确状态出现 | 是 |
| 分享展示 | 分享按钮或分享卡可见 | 视目标而定 |
| 退出和返回 | 返回、重试、继续路径正常 | 否，除非破坏主路径 |

核心路径失败通常要回到 H5 组装、规则生成或内容生成。

## 11. 游戏规则测试

规则测试确认前端执行逻辑和 `game_rules` 一致。

| 规则模块 | 测试内容 |
|---|---|
| `state_machine` | 状态进入、退出、流转是否正确 |
| `start_condition` | 是否满足开始条件 |
| `step_rules` | 每一步是否按规则推进 |
| `scoring_rules` | 得分是否正确 |
| `success_condition` | 成功状态是否按规则触发 |
| `fail_condition` | 失败状态是否按规则触发 |
| `reward_rules` | 奖励是否按条件展示或触发 |
| `cta_rules` | CTA 是否只在允许状态出现 |
| `anti_abuse_rules` | 异常行为是否标记 |
| `tracking_rules` | 规则状态是否产生对应事件 |

规则测试示例：

| 问题 | 处理 |
|---|---|
| 用户答完所有题但无法进入结果页 | 阻止发布，回到规则或 Builder |
| 得分和答案不一致 | 阻止发布 |
| 失败后没有重试路径 | 要求修复 |
| 奖励条件未满足却展示奖励 | 阻止发布 |
| CTA 出现在规则不允许的位置 | 阻止发布 |

## 12. 奖励测试

奖励是高风险模块，必须独立测试。

| 测试项 | 检查内容 |
|---|---|
| 奖励展示 | 用户是否在正确位置看到奖励说明 |
| 奖励触发 | 是否只在满足条件后触发 |
| 奖励事件 | `reward_view` 和 `reward_granted` 是否区分 |
| 奖励上限 | 是否存在重复领取或无限触发 |
| 奖励文案 | 是否和验证通过的内容一致 |
| 奖励性质 | 是否仍是积分、徽章、资格或抽奖机会 |
| 异常用户 | 是否限制异常领取 |
| 失败用户 | 失败后是否错误获得奖励 |

必须阻止发布的问题：

1. 没完成任务却触发奖励。
2. 完成任务却没有触发应有奖励。
3. 奖励事件缺失。
4. 奖励文案和合规验证版本不一致。
5. 异常用户可以重复领取。

## 13. CTA 测试

CTA 是营销转化的关键出口。

| 测试项 | 检查内容 |
|---|---|
| CTA 展示状态 | 是否在规则允许的位置展示 |
| CTA 文案 | 是否和 `content_assets` 与合规验证一致 |
| CTA 链接 | 是否为授权链接 |
| CTA 参数 | 是否带 campaign、KOL、渠道、版本参数 |
| CTA 点击 | 是否可点击，不被遮挡 |
| CTA 跳转 | 是否能正常跳到目标页面 |
| CTA 事件 | `cta_view`、`cta_click` 是否上报 |
| 转化事件 | 注册、入群、领取、预约等是否能归因 |
| Agent CTA | 动态 CTA 是否在边界内触发 |

CTA 测试失败的典型处理：

| 失败 | 处理 |
|---|---|
| CTA 不出现 | 回到 `game_rules` 或 Builder |
| CTA 出现太早 | 回到 `game_rules` 或 `agent_policy` |
| CTA 链接错误 | 回到渠道配置 |
| CTA 点击无事件 | 阻止发布，修复 `tracking_map` |
| CTA 跳转未授权 | 阻止发布，回到约束验证 |

## 14. 分享测试

分享测试确认 KOL 传播链路可用。

| 测试项 | 检查内容 |
|---|---|
| 分享按钮 | 是否可见、可点击 |
| 分享卡 | 图片、文案、KOL、活动信息是否正确 |
| 分享链接 | 是否包含 KOL 和渠道参数 |
| 分享事件 | `share_click` 是否上报 |
| 结果分享 | 分数、等级或成就是否正确写入 |
| 邀请参数 | 邀请码、referral、campaign 参数是否存在 |
| 平台适配 | Telegram、X、Discord 等渠道表现是否可用 |
| 合规提示 | 分享卡是否避免夸大奖励 |

如果当前 campaign 的主目标是裂变传播，分享测试失败应阻止发布。

## 15. 埋点测试

埋点测试是模拟测试的核心之一。没有事件，就无法复盘，也无法证明 Agentic 策略有效。

MVP 必须检查的事件：

| 事件 | 必须出现的场景 |
|---|---|
| `playable_impression` | H5 加载并可见 |
| `playable_start` | 用户点击开始 |
| `scene_view` | 进入首屏、游戏页、结果页等关键页面 |
| `user_action` | 点击、选择、拖拽、射击、画线等关键操作 |
| `step_complete` | 完成题目、任务、关卡、波次 |
| `reward_view` | 用户看到奖励提示 |
| `reward_granted` | 奖励或资格触发 |
| `share_click` | 点击分享 |
| `cta_view` | CTA 曝光 |
| `cta_click` | 点击 CTA |
| `conversion` | 完成目标动作 |
| `drop_off` | 用户在关键节点流失 |
| `agent_decision_applied` | Agent 策略被应用 |

事件参数必须包含：

| 参数 | 作用 |
|---|---|
| `campaign_id` | campaign 归因 |
| `kol_id` / `kol_ref` | KOL 归因 |
| `playable_version_id` | 版本归因 |
| `template_id` | 模板归因 |
| `session_id` | 会话归因 |
| `user_segment` | 用户分群 |
| `scene_id` | 页面或状态 |
| `component_id` | 组件 |
| `rule_state` | 当前规则状态 |
| `agent_policy_id` | Agent 策略版本 |
| `decision_id` | Agent 决策 ID |
| `channel` | 渠道 |
| `experiment_id` | 实验 ID，可为空 |

埋点失败的阻断规则：

1. `playable_impression` 缺失，阻止发布。
2. `playable_start` 缺失，阻止发布。
3. CTA 目标活动缺少 `cta_click`，阻止发布。
4. 奖励活动缺少 `reward_granted`，阻止发布。
5. Agentic 活动缺少 `agent_decision_applied`，阻止发布或降级为非 Agentic。

## 16. Agent 策略测试

Agent 策略测试确认 Runtime Agent 在允许范围内影响体验。

| 策略 | 测试内容 |
|---|---|
| 分群策略 | 不同模拟用户是否进入正确分群 |
| 难度策略 | 难度调整是否在 `game_rules` 范围内 |
| 提示策略 | 提示是否在合适时机出现 |
| 奖励策略 | 奖励提示是否不改变奖励性质 |
| CTA 策略 | CTA 时机和文案是否符合目标和规则 |
| 分享策略 | 分享文案是否合规且可追踪 |
| 风控策略 | 异常用户是否进入更严格路径 |
| 实验策略 | 实验分组和事件是否记录 |
| 降级策略 | Agent 不可用时是否回到默认策略 |

Agent 策略必须记录：

| 记录 | 说明 |
|---|---|
| `decision_id` | 决策 ID |
| `agent_policy_id` | 策略版本 |
| `user_segment` | 用户分群 |
| `decision_type` | 难度、提示、奖励、CTA、风控等 |
| `before_state` | 调整前状态 |
| `after_state` | 调整后状态 |
| `reason_code` | 调整原因 |
| `boundary_check` | 是否通过边界检查 |

必须阻止发布的问题：

1. Agent 改变主目标。
2. Agent 改变奖励性质。
3. Agent 绕过 `game_rules`。
4. Agent 在未授权状态展示 CTA。
5. Agent 决策没有事件记录。
6. Agent 失败时没有默认策略。

## 17. 风控与异常行为测试

风控测试用于模拟刷量、异常完成、重复领取、重复点击等风险。

| 异常行为 | 测试方式 | 预期 |
|---|---|---|
| 极快完成 | 1 秒内完成全部步骤 | 标记异常或限制奖励 |
| 重复提交 | 连续提交同一任务 | 去重或限制 |
| 重复钱包 | 多次用同一钱包领取 | 触发风控 |
| 重复设备 | 同设备多账号参与 | 标记风险 |
| 异常高分 | 超过合理分数上限 | 标记或拒绝 |
| CTA 刷量 | 高频点击 CTA | 限制或标记 |
| 分享刷量 | 大量无效分享 | 标记无效传播 |
| 断网重试 | 网络失败后重复提交 | 不重复发奖励 |

高奖励、空投、排行榜、抽奖、邀请裂变活动必须有风控测试。

## 18. 性能和稳定性测试

性能会直接影响开始率和完成率。

| 测试项 | 检查内容 |
|---|---|
| 首屏加载 | 页面是否快速可见 |
| 首次可交互 | 开始按钮是否尽快可点 |
| 资源加载 | 图片、音效、动画是否失败 |
| 包体大小 | 是否过大 |
| 动画流畅 | 移动端是否卡顿 |
| 内存占用 | 长时间或复杂玩法是否崩溃 |
| 错误捕获 | JS 错误、资源错误是否记录 |
| 网络降级 | 慢网或断网是否有提示 |
| WebView 适配 | Telegram / App 内 WebView 是否可运行 |

MVP 不需要一开始做复杂性能实验，但至少要避免白屏、资源失败、按钮不可点和核心路径卡死。

## 19. 设备与环境测试

H5 Playable 的主要消费场景是移动端，因此设备矩阵要以移动端为主。

| 环境 | 测试重点 |
|---|---|
| iOS Safari | 触控、音频、viewport、安全区 |
| Android Chrome | 资源加载、性能、输入行为 |
| Telegram WebView | 分享、跳转、返回、深链 |
| Discord 内置浏览器 | 链接、分享、权限 |
| 广告 WebView | 跳转限制、加载速度、事件上报 |
| 小屏手机 | 文案溢出、按钮遮挡 |
| 大屏手机 | 布局留白、视觉比例 |
| 慢网络 | loading、重试、降级 |

MVP 可以先用少量设备代表：

1. iPhone 竖屏。
2. Android 竖屏。
3. Telegram WebView。
4. 慢网络模拟。

## 20. 可视化回归检查

模拟测试也要检查页面是否“看起来能用”。

| 检查项 | 示例 |
|---|---|
| 首屏是否非空 | 不能白屏、黑屏、只显示 loading |
| 文案是否溢出 | 标题、按钮、奖励说明不能超出容器 |
| 关键按钮是否可见 | 开始、分享、CTA、重试按钮不能被遮挡 |
| 视觉资产是否正常 | Logo、头像、背景、奖励图不能错位 |
| 安全区是否适配 | 刘海屏、底部手势区域不遮挡 |
| 结果页是否完整 | 得分、奖励、CTA、分享完整 |
| 免责声明是否可见 | 合规提示不能被遮挡 |
| 动态状态是否正确 | 进度条、分数、任务状态同步 |

如果截图或视觉检查发现关键按钮不可见，即使事件存在，也不能发布。

## 21. 模拟测试流程

标准流程如下：

| 步骤 | 动作 | 输出 |
|---|---|---|
| 1. 创建测试任务 | 读取 `playable_version`、`preview_url`、`build_manifest` | `simulation_job` |
| 2. 读取测试计划 | 根据模板、目标、渠道选择 `test_scenarios` | 测试计划 |
| 3. 初始化模拟用户 | 创建正常、失败、分享、CTA、异常用户 | `simulated_users` |
| 4. 打开 H5 | 访问 `preview_url` 并检查加载 | 可访问结果 |
| 5. 跑核心路径 | 点击开始、完成任务、进入结果页 | 路径结果 |
| 6. 跑失败路径 | 答错、撞障碍、失败、重试 | 失败路径结果 |
| 7. 跑奖励路径 | 触发奖励、检查奖励事件和上限 | 奖励结果 |
| 8. 跑 CTA 路径 | 展示 CTA、点击、跳转、归因 | CTA 结果 |
| 9. 跑分享路径 | 点击分享、检查分享卡和链接 | 分享结果 |
| 10. 跑 Agent 路径 | 触发动态难度、提示、CTA 或风控 | Agent 结果 |
| 11. 检查事件 | 对比 `tracking_map` 和实际事件 | 事件差异 |
| 12. 检查性能 | 首屏、交互、错误、资源 | 性能结果 |
| 13. 生成报告 | 汇总通过、失败、警告和建议 | `simulation_result` |
| 14. 决定下一步 | 发布、重构建、重生成、人工检查 | `next_action` |

## 22. 发布门槛

模拟测试应该给出明确发布判断。

| 状态 | 含义 | 下一步 |
|---|---|---|
| `passed` | 所有 P0 用例通过 | 可进入发布 |
| `passed_with_warnings` | 核心路径通过，有非阻断警告 | 可发布或建议优化 |
| `failed` | 存在阻断问题 | 不可发布，返回修复 |
| `blocked` | 版本不可访问、规则严重错误、合规状态异常 | 阻止发布 |
| `needs_manual_check` | 自动测试无法判断 | 人工复查 |

P0 阻断项：

| 阻断项 | 原因 |
|---|---|
| H5 无法打开 | 用户无法访问 |
| 开始按钮不可用 | 核心体验断裂 |
| 核心路径无法完成 | Playable 不可玩 |
| 结果页无法出现 | 无法结算 |
| 奖励触发错误 | 激励和风控风险 |
| CTA 缺失或不可点 | 营销目标无法完成 |
| 关键事件缺失 | 无法复盘和归因 |
| Agent 策略越界 | Agentic 风险 |
| 分享主目标下分享不可用 | 裂变目标失败 |
| 合规提示缺失 | 发布风险 |

## 23. 失败回流机制

模拟测试失败后，要明确回到哪个环节。

| 失败类型 | 回流环节 |
|---|---|
| H5 打不开 | H5 组装 / 预览服务 |
| 资源缺失 | H5 组装 / 资产生成 |
| 文案缺失 | 内容生成 |
| 任务无法完成 | 游戏规则生成 / H5 组装 |
| 状态机错误 | 游戏规则生成 |
| 奖励触发错误 | 游戏规则生成 / 约束验证 |
| CTA 链接错误 | 关键变量 / 渠道配置 |
| CTA 时机错误 | `game_rules` / `agent_policy` |
| 埋点缺失 | H5 组装 / `tracking_map` |
| Agent 策略越界 | Agent 运营策略生成 / 约束验证 |
| 性能问题 | H5 组装 / 资产处理 |
| 风控缺失 | 约束验证 / Agent 策略 |

不要把所有失败都丢给 Builder。模拟测试要能定位是内容问题、规则问题、策略问题、组装问题还是发布配置问题。

## 24. 与 KOL 预览的关系

模拟测试和 KOL 预览不是同一件事。

| 对比项 | 模拟测试 | KOL 预览 |
|---|---|---|
| 使用者 | 系统、运营、发布服务 | KOL、项目方、运营 |
| 目的 | 验证能不能发布 | 确认内容是否满意 |
| 方法 | 自动化脚本、模拟用户、事件校验 | 人工体验和编辑 |
| 输出 | `simulation_result` | 修改意见、`config_patch` |
| 关注点 | 可玩、可追踪、可发布 | 语气、视觉、品牌、分享意愿 |
| 阻断权 | 可阻止发布 | 可要求修改 |

推荐顺序：

1. H5 组装生成预览版本。
2. 模拟测试跑基础质量。
3. 通过后给 KOL 预览。
4. KOL 修改后生成补丁。
5. 对受影响模块做回归测试。
6. 再进入发布。

## 25. 与发布服务的关系

发布服务应该读取 `simulation_result`，而不是只看 Builder 是否成功。

| 发布前检查 | 来源 |
|---|---|
| 版本是否构建成功 | `playable_version`、`build_manifest` |
| 是否通过约束验证 | `validation_report` |
| 是否通过模拟测试 | `simulation_result` |
| 是否有阻断失败 | `failed_cases`、`blocked_cases` |
| 是否缺关键事件 | `missing_events` |
| 是否可发布 | `publish_readiness` |
| 是否需要人工确认 | `needs_manual_check` |
| 是否有回滚版本 | 发布服务 |

发布服务不应该发布：

1. 没有 `simulation_result` 的版本。
2. 测试状态为 `failed` 或 `blocked` 的版本。
3. 缺少关键事件的版本。
4. 核心路径无法完成的版本。
5. Agent 策略越界的版本。

## 26. 与数据反馈的关系

模拟测试不是只保证发布，还能提前发现数据闭环问题。

| 数据问题 | 模拟测试如何发现 |
|---|---|
| 开始率无法计算 | 缺少 `playable_impression` 或 `playable_start` |
| 完成率无法计算 | 缺少 `step_complete` 或结果状态 |
| 分享率无法计算 | 缺少 `share_click` |
| CTA 点击率无法计算 | 缺少 `cta_view` 或 `cta_click` |
| 转化无法归因 | 缺少 campaign、KOL、channel、version 参数 |
| Agent 效果无法评估 | 缺少 `agent_decision_applied` |
| 流失点无法定位 | 缺少 `scene_view` 或 `drop_off` |
| 奖励滥用无法发现 | 缺少 `reward_granted` 和风控维度 |

模拟测试通过后，数据看板至少能回答：

1. 用户是否看到了 H5？
2. 用户是否点击开始？
3. 用户在哪一步流失？
4. 用户是否完成？
5. 用户是否看到奖励？
6. 用户是否分享？
7. 用户是否点击 CTA？
8. Agent 是否影响了体验？

## 30. 示例：竞猜模板模拟测试

| 测试路径 | 步骤 | 预期 |
|---|---|---|
| 正常完成 | 打开 H5 -> 开始 -> 答 3 题 -> 结果页 | 结果页展示分数、奖励和 CTA |
| 答错路径 | 开始 -> 答错 -> 查看解释 -> 继续 | 能进入下一题，事件完整 |
| 高分用户 | 答对多数题 -> 结果页 | 展示高分反馈和分享 CTA |
| 低分用户 | 答错多数题 -> 结果页 | 展示学习提示，不推荐交易 |
| 分享路径 | 结果页 -> 分享 | 分享卡和 `share_click` 正常 |
| CTA 路径 | 结果页 -> 加入社群 | `cta_view`、`cta_click`、渠道参数正常 |
| Agent 路径 | 低分用户触发提示 | `agent_decision_applied` 记录原因 |

必须失败的情况：

| 问题 | 原因 |
|---|---|
| 答完题不进入结果页 | 核心路径断裂 |
| 高分用户 CTA 跳到交易页面 | CTA 与合规边界冲突 |
| Agent 推荐买入 | Agent 越界 |
| 每题选择没有事件 | 无法分析题目表现 |

## 31. 示例：空投任务模板模拟测试

| 测试路径 | 步骤 | 预期 |
|---|---|---|
| 正常任务 | 打开 -> 开始 -> 完成任务 1 -> 完成任务 2 | 进度正确更新 |
| 入群 CTA | 点击 Telegram CTA | 跳转正常，事件上报 |
| 分享任务 | 点击分享 -> 返回任务页 | 分享事件和邀请参数正常 |
| 钱包任务 | 连接钱包或模拟授权 | 授权说明可见，失败路径正常 |
| 奖励资格 | 完成核心任务 -> 结果页 | 展示资格或积分，不承诺必中 |
| 重复领取 | 重复完成奖励路径 | 不重复触发奖励 |
| 异常速度 | 极快完成全部任务 | 标记异常或进入强验证 |

必须失败的情况：

| 问题 | 原因 |
|---|---|
| 未完成任务就发奖励 | 奖励滥用风险 |
| 钱包授权没有说明 | 隐私风险 |
| 重复钱包可重复领取 | 风控失败 |
| 分享任务没有事件 | 裂变数据断裂 |

## 32. 与 KOL 二次编辑的回归测试

KOL 修改后不一定需要全量模拟测试，但必须做受影响路径回归。

| KOL 修改 | 回归测试范围 |
|---|---|
| 改标题 | 首屏可见、文案溢出、合规提示 |
| 改开始按钮 | 开始点击、`playable_start` |
| 改题目 | 对应题目展示、选择、答案、事件 |
| 改任务 | 任务完成、进度、奖励、事件 |
| 改奖励文案 | 奖励展示、免责声明、`reward_view` |
| 改奖励条件 | 规则测试、奖励测试、风控测试 |
| 改 CTA 文案 | CTA 展示、点击、事件 |
| 改 CTA 链接 | 链接、跳转、参数、授权 |
| 改分享卡 | 分享展示、分享事件、合规提示 |
| 改 Agent 策略 | Agent 策略测试、决策日志、降级 |
| 改模板 | 全量测试 |

回归测试的目标是缩短修改后的验证时间，同时不放过影响发布质量的关键路径。

## 34. 不建议的做法

| 不建议做法 | 问题 |
|---|---|
| H5 构建成功就直接发布 | 构建成功不等于可玩、可追踪、可转化 |
| 只测正常路径 | 失败、重试、异常和风控问题会遗漏 |
| 只人工预览 | 难以稳定发现埋点和边界问题 |
| 只看页面，不看事件 | 数据闭环可能断裂 |
| 只测模板，不测版本 | KOL 配置可能破坏具体版本 |
| 缺事件也允许发布 | 后续复盘无法补救 |
| Agent 策略不测 | 动态策略可能越界 |
| 奖励不测重复触发 | 容易被刷和滥用 |
| 测试失败没有回流对象 | 问题无法定位到内容、规则、策略或 Builder |
| 预览测试数据混入正式看板 | 污染真实运营数据 |

## 35. 结论

模拟测试是 Agentic Playable 从“能生成 H5”走向“能安全发布和复盘”的发布前质量闸口。

它要回答五个问题：

| 问题 | 对应机制 |
|---|---|
| 用户能不能打开并玩完？ | 可访问测试和核心路径测试 |
| 规则和奖励是否正确？ | `game_rules` 测试和奖励测试 |
| CTA、分享和转化是否可用？ | CTA 测试和分享测试 |
| 数据能不能回收？ | `tracking_map` 和埋点测试 |
| Agent 策略是否安全有效？ | `agent_policy` 测试和决策日志 |

MVP 阶段最重要的是：

1. 每个 `playable_version` 发布前都必须有 `simulation_result`。
2. P0 先跑可访问、核心路径、奖励、CTA、分享、埋点和 Agent 决策测试。
3. 关键事件缺失、核心路径断裂、奖励错误、CTA 不可用、Agent 越界必须阻止发布。
4. KOL 二次编辑后做受影响路径回归测试。
5. 测试失败要能明确回流到内容生成、规则生成、Agent 策略、H5 组装、约束验证或发布配置。

这样，Airvana 的 Agentic Playable 才能避免“看起来生成了，但用户玩不完、数据收不到、奖励跑错、CTA 点不了”的发布事故。
