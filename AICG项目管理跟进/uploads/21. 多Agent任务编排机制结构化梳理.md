# 多 Agent 任务编排机制结构化梳理

## 1. 核心定义

多 Agent 任务编排机制，是 Airvana Agent OS 的流程控制层。

它负责把“生成一个 Agentic Playable 并完成业务闭环”的大任务，拆成多个 Agent 可以执行、可以校验、可以回退、可以追踪的子任务。

核心产物：

| 产物 | 说明 |
|---|---|
| `workflow_state` | 当前工作流状态 |
| `agent_task_plan` | Agent 任务分配 |
| `artifact_manifest` | 全链路产物清单 |
| `approval_checkpoints` | 需要人工审核的节点 |
| `error_recovery_plan` | 失败回退方案 |

## 2. 所处位置

| 上游 | 当前环节 | 下游 |
|---|---|---|
| 目标、生成模式、RAG 上下文、模型路由 | 多 Agent 编排 | 模板 / AI 生成规划、生成、校验、构建、运行、复盘 |

编排器不直接生成内容。

它决定谁生成、何时生成、生成后交给谁、失败后回到哪里。

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 串联全链路 | 从输入到发布到复盘形成闭环 |
| 管理任务状态 | 清楚每个活动走到哪一步 |
| 控制 Agent 权限 | 不允许 Agent 越权改线上版本 |
| 支持回退 | 生成失败、校验失败、构建失败能回到对应环节 |
| 支持人工介入 | 高风险节点进入审核 |
| 保证产物一致 | 每个 Agent 输出被统一记录 |

## 4. 关键 Agent

| Agent | 负责环节 |
|---|---|
| Identity Agent | 身份和项目上下文 |
| Goal Agent | 目标识别 |
| Generation Mode Agent | 生成模式选择 |
| Retrieval Agent | RAG 检索 |
| Template Agent | 模板推荐和 schema 读取 |
| Brief Agent | 创作 Brief |
| Strategy Agent | 玩法和营销策略 |
| Generation Agent | 文案、视觉、任务内容 |
| Rule Agent | 游戏规则 |
| Policy Agent | Agent 运营策略 |
| Constraint Agent | 约束和合规校验 |
| Builder Agent | 调用 H5 Builder |
| Simulation Agent | 模拟测试 |
| Publish Agent | 发布投放 |
| Runtime Agent | 运行时动态运营 |
| Diagnosis Agent | 数据复盘 |
| Memory Agent | 写入 Memory 和模板更新 |

## 5. 工作流状态

| 状态 | 说明 |
|---|---|
| `created` | 活动已创建 |
| `context_ready` | 身份和项目上下文已完成 |
| `goal_ready` | 目标和生成模式已确定 |
| `retrieval_ready` | RAG 上下文已准备 |
| `planned` | 玩法和生成计划已完成 |
| `generated` | 内容、规则、策略已生成 |
| `validated` | 约束校验通过 |
| `built` | H5 已构建 |
| `tested` | 模拟测试通过 |
| `reviewed` | KOL 或运营已确认 |
| `published` | 已发布 |
| `running` | 正在运行和动态运营 |
| `diagnosed` | 已复盘 |
| `memory_updated` | 已写入 Memory 和模板 |

## 6. 编排模式

| 模式 | 用途 |
|---|---|
| 顺序编排 | MVP 默认，从目标到发布按顺序走 |
| 并行生成 | 文案、视觉、题目可并行生成 |
| 校验回退 | 校验失败回到对应 Agent 修复 |
| 人工确认 | 高风险奖励、CTA、发布前需要确认 |
| Runtime 分支 | 发布后进入实时运营链路 |
| Feedback 回写 | 复盘后回写模板和 Memory |

## 7. 关键系统模块

| 系统 | 作用 |
|---|---|
| Workflow Orchestrator | 主编排器 |
| Task Queue | 任务队列 |
| Artifact Store | 存储每一步产物 |
| State Store | 存储 workflow 状态 |
| Approval Service | 人工审核节点 |
| Event Bus | 事件驱动和状态通知 |
| Audit Log | 审计所有 Agent 行为 |
| Permission Service | 控制 Agent 和用户权限 |

## 9. 回退逻辑

| 失败点 | 回退到 |
|---|---|
| 目标识别失败 | 用户补充目标 |
| RAG 缺少资料 | 资料补全或低置信生成 |
| 模板不适配 | 重新推荐模板 |
| 内容不合规 | Generation Agent 修复 |
| 规则不可执行 | Rule Agent 修复 |
| 策略越界 | Policy Agent 修复 |
| Builder 失败 | 模板配置修复 |
| 模拟测试失败 | 回到内容、规则或策略 |
| 发布失败 | Publish Agent 重试或换渠道 |
| Runtime 异常 | 回退默认策略 |

## 10. 约束边界

| 约束 | 说明 |
|---|---|
| Agent 不能跳过校验 | 生成后必须进入 Constraint Service |
| Agent 不能直接发布 | 发布需要审核状态 |
| Agent 不能修改已发布版本 | 必须生成新版本 |
| Runtime Agent 不能改核心规则 | 只能在边界内动态运营 |
| Diagnosis Agent 不能直接改全局模板 | 需要审核和版本化 |

## 11. MVP 范围

| P0 能力 | 说明 |
|---|---|
| 线性编排 | 支持从生成到发布的顺序流程 |
| 状态记录 | 每个活动有 workflow 状态 |
| 产物清单 | 每一步产物可追踪 |
| 校验回退 | 校验失败能回到生成 |
| 人工确认点 | 发布前、奖励、CTA 高风险点 |
| 审计日志 | 记录 Agent 执行动作 |

## 12. P1 / P2 扩展

| 阶段 | 能力 |
|---|---|
| P1 | 并行生成、自动修复、多 Agent 协商 |
| P2 | 自适应编排、跨活动策略复用、多 Agent 自动复盘 |

## 13. 验收标准

| 验收项 | 标准 |
|---|---|
| 状态清晰 | 活动走到哪一步可见 |
| 产物完整 | 每一步输出都有记录 |
| 可回退 | 失败能回到对应环节 |
| 可审核 | 高风险节点有人工确认 |
| 可审计 | 每个 Agent 行为有日志 |

## 14. 最终结论

多 Agent 编排是 Agent OS 的骨架。

没有编排器，多 Agent 会变成散乱调用；有了编排器，Airvana 才能把生成、校验、构建、发布、运行和复盘串成稳定闭环。
