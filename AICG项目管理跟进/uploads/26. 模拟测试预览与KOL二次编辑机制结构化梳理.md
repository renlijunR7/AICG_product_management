# 模拟测试、预览与 KOL 二次编辑机制结构化梳理

## 1. 核心定义

模拟测试、预览与 KOL 二次编辑机制，是 Agentic Playable 发布前的体验确认和质量闸口。

它负责在正式发布前，通过模拟用户、自动测试、KOL 预览和安全编辑，确认 H5 可玩、可转化、可追踪、可发布。

核心产物：

| 产物 | 说明 |
|---|---|
| `simulation_result` | 模拟测试结果 |
| `preview_feedback` | KOL 或运营反馈 |
| `config_patch` | 二次编辑补丁 |
| `approval_status` | 发布前确认状态 |

## 2. 所处位置

| 上游 | 当前环节 | 下游 |
|---|---|---|
| `playable_version`、`preview_url` | 模拟测试、预览、二次编辑 | 发布投放与媒体连接器 |

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 验证可玩性 | 用户能打开、开始、完成 |
| 验证转化路径 | CTA 能展示、点击、跳转、归因 |
| 验证埋点 | 后续数据反馈可用 |
| 验证 Runtime | Agent 决策能触发和记录 |
| 降低 KOL 风险 | 让 KOL 能确认内容符合自身表达 |
| 支持安全修改 | 只允许结构化补丁，不改代码 |

## 4. 输入数据

| 输入 | 用途 |
|---|---|
| `playable_version` | 被测试版本 |
| `validation_report` | 校验结果 |
| `tracking_map` | 埋点清单 |
| `agent_policy` | Runtime 策略 |
| `game_rules` | 游戏规则 |
| `kol_context` | KOL 预览和编辑边界 |

## 5. 关键 Agent

| Agent | 职责 |
|---|---|
| Simulation Agent | 跑模拟用户路径 |
| QA Agent | 检查可玩性和关键错误 |
| Tracking Test Agent | 检查埋点 |
| Runtime Test Agent | 检查 Agent 决策触发 |
| Patch Agent | 把 KOL 修改转为 `config_patch` |
| Review Agent | 判断能否发布 |

## 6. 模拟测试范围

| 测试 | 说明 |
|---|---|
| 加载测试 | H5 是否可打开 |
| 首屏测试 | 文案、按钮、项目和 KOL 信息正确 |
| 主路径测试 | 开始、任务、完成、结果页 |
| 奖励测试 | 奖励展示和触发条件 |
| 分享测试 | 分享卡和归因 |
| CTA 测试 | CTA 展示、点击、跳转 |
| 风控测试 | 异常用户、重复领取、限频 |
| Runtime 测试 | 动态提示、CTA、难度、日志 |
| 埋点测试 | 核心事件是否上报 |

## 7. KOL 二次编辑范围

| 可编辑 | 不建议开放 |
|---|---|
| 标题、副标题、按钮文案 | 核心玩法代码 |
| KOL 语气和粉丝称呼 | 完成条件 |
| 分享文案和结果反馈 | 奖励性质 |
| CTA 文案和已授权链接 | 未授权 CTA |
| 部分提示和难度偏好 | 风控底线 |
| 视觉主题和头像露出 | 埋点字段删除 |

## 8. `config_patch` 类型

| Patch | 说明 |
|---|---|
| `content_patch` | 文案、题目、反馈、分享 |
| `visual_patch` | 视觉主题、头像、背景 |
| `cta_patch` | CTA 文案、链接、时机 |
| `reward_patch` | 奖励表达和展示 |
| `agent_policy_patch` | 提示、难度、CTA 策略 |
| `tracking_patch` | 埋点补充 |

## 9. 发布前判断

| 状态 | 说明 |
|---|---|
| `ready_to_publish` | 可发布 |
| `passed_with_warning` | 可发布但有提示 |
| `repair_required` | 必须修复 |
| `manual_review_required` | 需人工审核 |
| `blocked` | 阻止发布 |

## 10. 约束边界

| 约束 | 说明 |
|---|---|
| KOL 不改代码 | 只能改结构化字段 |
| 修改必须重新校验 | Patch 后回归测试 |
| 已发布版本不原地覆盖 | 发布后修改生成新版本 |
| 高风险修改需审核 | 奖励、CTA、合规表达 |
| 埋点不能被删除 | 否则无法复盘 |

## 11. MVP 范围

| P0 能力 | 说明 |
|---|---|
| 主路径模拟测试 | 打开、开始、完成、结果页 |
| CTA 和分享测试 | 链路和归因 |
| 埋点测试 | 核心事件 |
| Runtime 决策测试 | 至少测试动态提示和 CTA |
| KOL 可视化编辑 | 文案、CTA、分享、视觉 |
| Patch 校验 | 修改后重新验证 |

## 12. P1 / P2 扩展

| 阶段 | 能力 |
|---|---|
| P1 | 多用户分群模拟、自动修复建议 |
| P2 | AI 试玩、压力测试、跨设备自动截图评审 |

## 13. 验收标准

| 验收项 | 标准 |
|---|---|
| 主路径通过 | 模拟用户能完成 |
| 转化可追踪 | CTA 和 conversion 事件存在 |
| Agent 可复盘 | `agent_decision_applied` 正常记录 |
| KOL 可确认 | KOL 能理解和修改关键字段 |
| 发布安全 | 无阻断问题 |

## 14. 最终结论

这个环节是发布前的最后一道产品质量关。

它保证 Airvana 不是只生成一个 H5，而是生成一个能被 KOL 接受、能被用户完成、能被数据复盘的 Agentic Playable。
