# 内容、玩法、规则与 Agent 策略生成机制结构化梳理

## 1. 核心定义

内容、玩法、规则与 Agent 策略生成机制，是把 Playable 蓝图转成可体验、可执行、可运营的结构化产物。

它不是单纯生成文案，也不是单纯写游戏规则，而是同时生成：

| 产物 | 说明 |
|---|---|
| `content_assets` | 用户看到的文案、题目、任务、反馈、分享卡 |
| `game_rules` | 用户如何玩、如何完成、如何领奖 |
| `agent_policy` | Runtime Agent 如何动态调整难度、提示、CTA、奖励 |

## 2. 所处位置

| 上游 | 当前环节 | 下游 |
|---|---|---|
| `playable_blueprint`、`template_schema`、`template_config_draft` | 内容 / 玩法 / 规则 / 策略生成 | 约束、合规与质量验证 |

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 生成可体验内容 | 用户能理解、能玩、愿意完成 |
| 生成可执行规则 | 系统知道状态、完成条件、奖励条件 |
| 生成可运营策略 | Runtime Agent 能动态优化体验 |
| 保持结构化 | 下游 Builder 和 Constraint 能消费 |
| 保持可追踪 | 每个关键行为有事件和指标 |

## 4. 输入数据

| 输入 | 用途 |
|---|---|
| `playable_blueprint` | 决定整体玩法 |
| `template_schema` | 决定字段和组件边界 |
| `template_config_draft` | 决定关键变量 |
| `retrieval_context` | 提供 KOL、项目、案例、合规知识 |
| `campaign_goal` | 决定内容和策略优化方向 |
| `risk_profile` | 限制奖励、CTA、表达 |

## 5. 关键 Agent

| Agent | 职责 |
|---|---|
| Generation Agent | 生成文案、题目、任务、反馈、分享卡 |
| Gameplay Agent | 细化玩法结构和场景流程 |
| Rule Agent | 生成 `game_rules` |
| Policy Agent | 生成 `agent_policy` |
| Tracking Agent | 生成事件和埋点要求 |
| Critic Agent | 检查目标一致性和风险 |

## 6. 内容生成范围

| 内容 | 示例 |
|---|---|
| 首屏文案 | 标题、副标题、开始按钮 |
| 任务说明 | 用户下一步要做什么 |
| 题目内容 | 竞猜题、问答题、项目知识题 |
| 成功反馈 | 完成、命中、高分反馈 |
| 失败反馈 | 错误、失败、重试提示 |
| 提示文案 | 卡点提示、新手提示 |
| 奖励文案 | 积分、资格、抽奖、白名单说明 |
| 分享卡文案 | 成绩、挑战、邀请 |
| CTA 文案 | 入群、关注、领取、访问官网 |
| 免责声明 | 风险提示和合规说明 |

## 7. 游戏规则生成范围

| 规则 | 说明 |
|---|---|
| `state_machine` | 页面和游戏状态 |
| `completion_rules` | 完成条件 |
| `scoring_rules` | 分数和评级 |
| `reward_rules` | 奖励触发条件 |
| `cta_rules` | CTA 展示条件 |
| `share_rules` | 分享触发条件 |
| `risk_rules` | 反作弊和异常处理 |
| `tracking_rules` | 必需事件和参数 |

## 8. Agent 策略生成范围

| 策略 | 说明 |
|---|---|
| `difficulty_policy` | 动态难度 |
| `hint_policy` | 动态提示 |
| `reward_policy` | 奖励节奏 |
| `cta_policy` | CTA 时机和文案 |
| `share_policy` | 分享触发和分享卡 |
| `segmentation_policy` | 用户分群 |
| `risk_policy` | 风控策略 |
| `retention_policy` | 留存和复玩 |
| `runtime_boundaries` | Runtime 可调整边界 |

## 9. 产物关系

| 产物 | 下游用途 |
|---|---|
| `content_assets` | Builder 渲染页面和素材 |
| `game_rules` | Runtime 和 Constraint 判断玩法边界 |
| `agent_policy` | Runtime Agent 执行动态运营 |
| `tracking_requirements` | Analytics 和 Diagnosis 复盘 |

## 10. 约束边界

| 约束 | 说明 |
|---|---|
| 内容必须符合项目事实 | 不能编造项目能力 |
| 奖励不能夸大 | 不能承诺收益或真实 Token |
| 规则必须可执行 | 状态机可达、无死循环 |
| 策略不能越过规则 | Agent 只能在 `game_rules` 范围内调整 |
| CTA 必须授权 | 不能生成未验证链接 |
| 埋点必须完整 | 否则无法复盘 |

## 11. MVP 范围

| P0 能力 | 说明 |
|---|---|
| 首屏、题目、任务、结果页内容 | 让用户能玩完 |
| 基础 `game_rules` | 完成条件、奖励条件、CTA 条件 |
| 基础 `agent_policy` | 动态提示、CTA、简单风控 |
| 事件要求 | 曝光、开始、完成、分享、CTA、转化、Agent 决策 |
| 两个模板 | 先支持竞猜和空投任务 |

## 12. P1 / P2 扩展

| 阶段 | 能力 |
|---|---|
| P1 | 跑酷、塔防、射击、画线、模拟经营策略 |
| P2 | 多轮剧情、长期任务链、跨活动策略优化 |

## 13. 验收标准

| 验收项 | 标准 |
|---|---|
| 内容可读 | 用户能理解任务和目标 |
| 规则可执行 | Builder 和 Runtime 能消费 |
| 策略可运营 | Runtime Agent 有明确策略 |
| 约束可校验 | Constraint 能检查所有核心产物 |
| 数据可复盘 | 事件和策略日志完整 |

## 14. 最终结论

这个环节是 Agentic Playable 的生成核心。

它必须同时产出内容、规则和策略，才能让 Playable 从“看起来能玩”变成“可运营、可验证、可复盘”的营销系统。
