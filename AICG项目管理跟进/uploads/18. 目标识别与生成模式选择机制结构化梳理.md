# 目标识别与生成模式选择机制结构化梳理

## 1. 核心定义

目标识别与生成模式选择，是 Airvana Agent OS 决定“为什么生成”和“怎么生成”的环节。

它把 KOL 或项目方的自然语言意图、结构化选择和上下文，转成明确的营销目标和生成路径。

核心产物：

| 产物 | 说明 |
|---|---|
| `campaign_goal` | 活动主目标、次目标、指标 |
| `generation_mode` | 模板生成、AI 辅助模板、AI 生成玩法草案、混合生成 |
| `goal_constraints` | 目标带来的规则和限制 |
| `success_metrics` | 后续判断成败的指标 |

## 2. 所处位置

| 上游 | 当前环节 | 下游 |
|---|---|---|
| `kol_context`、`project_context`、用户意图 | 目标识别与生成模式选择 | RAG 检索、模板 / AI 生成规划 |

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 识别营销目的 | 拉新、教育、社群增长、空投预热、产品转化、留存 |
| 选择生成路径 | 判断该走模板、AI、还是混合 |
| 降低用户成本 | 用户不必理解所有模板和字段 |
| 控制生成风险 | 高风险目标优先使用模板承接 |
| 支撑后续归因 | 每次生成都绑定成功指标 |

## 4. 生成模式定义

| 模式 | 说明 | 适用场景 |
|---|---|---|
| `template_based` | 用户直接选择已有模板 | 用户目标明确、模板成熟 |
| `ai_assisted_template` | AI 推荐模板并辅助填写 | 用户知道目标但不知道选什么模板 |
| `ai_generated_playable` | AI 生成玩法草案，再结构化 | 用户有创新玩法想法 |
| `hybrid` | AI 生成方案 + 模板 schema 承接 | MVP 推荐默认模式 |

## 5. 输入数据

| 输入 | 用途 |
|---|---|
| `kol_context` | 判断 KOL 粉丝和传播方式 |
| `project_context` | 判断项目表达和合规边界 |
| 用户自然语言 | 提取活动意图 |
| 用户选择 | 目标、渠道、奖励、模板偏好 |
| 历史表现 | 判断该 KOL 更适合什么目标 |
| 资产状态 | 判断是否能支持高复杂模板 |

## 6. 关键 Agent

| Agent | 职责 |
|---|---|
| Goal Agent | 抽取和确认营销目标 |
| Generation Mode Agent | 判断生成模式 |
| Metric Agent | 给目标绑定指标 |
| Risk-Aware Router | 根据风险决定是否限制自由生成 |
| Clarification Agent | 信息不足时生成最少追问 |

## 7. 决策逻辑

| 条件 | 推荐结果 |
|---|---|
| 用户已选模板 | `template_based` |
| 用户只说目标 | `ai_assisted_template` |
| 用户要求原创玩法 | `ai_generated_playable` 后 schema 化 |
| 奖励或 Web3 风险高 | `hybrid` 或 `template_based` |
| 资产不足 | 推荐轻资产模板 |
| KOL 新手 | 推荐 `ai_assisted_template` |
| 平台冷启动 | 默认 `hybrid`，避免完全自由生成 |

## 8. 目标与指标映射

| 目标 | 主指标 | 辅助指标 |
|---|---|---|
| 项目认知 | 完成率、停留时长 | 正确率、分享 |
| 用户教育 | 正确率、完成率 | 提示使用率 |
| 拉新激活 | Start Rate、首次任务完成 | CTR |
| 社群增长 | CTA 点击、入群转化 | 分享率 |
| 空投预热 | 任务完成、资格领取 | 风险率 |
| 产品转化 | Conversion、CTA 点击 | ROAS |
| 留存复玩 | 回访、复玩 | 连续任务完成 |

## 9. 输出对象结构

| 字段 | 说明 |
|---|---|
| `goal_id` | 目标 ID |
| `primary_goal` | 主目标 |
| `secondary_goal` | 次目标 |
| `generation_mode` | 生成模式 |
| `recommended_templates` | 候选模板 |
| `success_metrics` | 成功指标 |
| `risk_constraints` | 风险限制 |
| `required_inputs` | 后续必须补充字段 |
| `confidence` | 识别置信度 |

## 10. 约束边界

| 约束 | 说明 |
|---|---|
| 主目标只能有一个 | 避免生成冲突 |
| 高风险活动不能完全自由生成 | 必须落到模板和规则 |
| 不能用收益承诺做目标 | Web3 场景尤其需要控制 |
| 生成模式必须可解释 | 用户和运营要知道为什么推荐 |
| 目标必须可追踪 | 没有指标不能进入发布 |

## 11. MVP 范围

| P0 能力 | 说明 |
|---|---|
| 目标识别 | 支持 6-8 类标准营销目标 |
| 生成模式选择 | 支持 `template_based`、`ai_assisted_template`、`hybrid` |
| 指标绑定 | 每个目标自动绑定核心指标 |
| 模式解释 | 告诉用户为什么推荐该模式 |
| 风险限制 | 高风险目标默认走模板承接 |

## 12. P1 / P2 扩展

| 阶段 | 能力 |
|---|---|
| P1 | 根据历史数据推荐目标、自动比较目标冲突 |
| P2 | 多目标分层策略、预算目标、生命周期目标自动规划 |

## 13. 验收标准

| 验收项 | 标准 |
|---|---|
| 目标明确 | 每次生成都有主目标 |
| 模式明确 | 每次生成都有 `generation_mode` |
| 指标明确 | 后续数据反馈可判断目标是否达成 |
| 风险可控 | 高风险活动不会进入完全自由生成 |
| 下游可用 | RAG、模板推荐、Brief 生成能读取结果 |

## 14. 最终结论

这个环节是 Agent OS 的业务路由层。

它决定 Airvana 是按模板稳态生成，还是由 AI 辅助生成方案，并保证所有生成都围绕明确营销目标，而不是变成无约束创意输出。
