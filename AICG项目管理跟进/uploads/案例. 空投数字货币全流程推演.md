# 案例 · 空投数字货币 · 全流程推演

> 本文档为 2026-08 重建稿（原稿遗失），依据工作台内既有案例结构与数据整理，待审校。

## 1. 案例设定

| 设定项 | 内容 |
|---|---|
| 品牌方 | Gate（沿用工作台品牌合作中的签约方）× 新代币项目方联合空投：项目代币（下称 `$TOKEN`）上所前预热，上所交易所为 Gate |
| 统一模板 | 空投「定时掉落 · 点击领取」（模板库 tp2），同一 `template_schema`：完成任务解锁领取资格，奖励接平台积分或代币白名单 |
| 品牌方目标 | 主目标：**注册 + 入金**（领取与提现承接到交易所账户）；次目标：社群增长、钱包绑定、上所前话题热度 |
| 预算与边界 | 活动期只发**平台积分 + 代币白名单资格**；`$TOKEN` 实际发放在周期结算环节统一执行，活动期只展示预估额度；任何文案不承诺收益、不暗示币价 |
| 结算原则 | 平台根据**已验证的营销结果**（扣除女巫与刷量）统一结算 KOL 与玩家两端；代币发放带归属期（详见第 5.4 / 6 章） |
| 统一漏斗 | **任务 → 领取资格 → 注册 → 入金**，逐层归因；「提现 / 领币需交易所账户」是注册的天然动机 |
| 唯一变量 | KOL 是谁 —— 任务清单、语言、奖励叙事、裂变策略全部由 `kol_context` 推导 |
| 渠道原则 | 每个媒体渠道独立闭环：各自链接、归因、运营、看板，互不引流；本案例主场为 Telegram（空投玩法的原生阵地） |

本案例要证明的一件事：**空投是「玩 → 注册 → 入金」转化路径最短的拉新模型**（对标 DOGS：注册 5,300 万+、零操作领取、交易所开户提现承接），但路径越短越吸引刷子——女巫防护与结算前置是把预算从机器人手里夺回来的唯一手段。

## 2. 参与角色设定

| 角色 | 设定 | 对推演的作用 |
|---|---|---|
| 品牌方 Gate × 项目方 | 锁定字段：代币总池、积分→代币映射比例、合规文案、上所信息、埋点 | 边界签署方与核销确认方 |
| 主路 KOL · F | 越南 TG 社群主 · 福利型 · 4 万粉 · 任务参与度高 · 刷量风险偏高 | 验证任务链 + 女巫防护的主战场 |
| 对照路 KOL · G | 华语 TG 频道主 · 教育解读型 · 10 万粉 · 完成率高 | 验证「教育型空投」的注册质量上限 |
| 空投裂变 Agent | 平台侧运营智能体，目标对齐工作台在营活动：TG 社群 7 日拉新 10,000 注册 | 承载动态运营与变体淘汰 |

F 与 G 同在 Telegram：延续案例 01 的**同平台对照组**方法——平台相同、画像不同，验证 `kol_context` 对空投产物的决定作用。

## 3. 全流程逐环节推演（15 步机制）

列定义：操作方实际做了什么（具体输入）→ 系统产物 → 空投特有要点。

### 3.1 输入层（环节 1-4）

| # | 环节 | 操作（实际输入） | 系统产物 | 空投特有要点 |
|---|---|---|---|---|
| 1 | KOL 身份识别 | F 授权 TG 社群；G 授权 TG 频道 | `kol_context`：F 福利型 · 越南语 · 刷量风险偏高；G 教育型 · 华语 · 完成率高 | F 路系统自动把风控等级调至最高档，领取校验全开 |
| 2 | 营销目标 | 品牌方设定：注册 + 入金为主 KPI；KOL 选择社群增长为中间站 | `campaign_goal`：领取资格做钩子、注册为收口、入金为延伸 | 「领 `$TOKEN` 白名单需交易所账户」写进目标约束 |
| 3 | 模板推荐 | 系统推荐空投模板（理由：拉新 + 交易所 → 空投 / 竞猜优先的玩法映射规则） | 锁定 tp2 `template_schema`：定时掉落 + 点击领取 + 任务解锁 | F 路推「任务链 + 组队掉落」变体；G 路推「答题解锁掉落」变体 |

## 4. 营销 Agentic 化 · 空投触发器手册

原则沿用案例 01：**边界内自动执行，超边界需品牌方确认**。

| 触发条件 | Agent 营销动作 | 档位 | 品牌方视角 |
|---|---|---|---|
| 掉落时段参与率 < 20% | 自动平移掉落时段至社群活跃峰值 | 自动 | 掉落不浪费在无人在线的时间 |
| 任务链某步流失 > 40% | 调整任务顺序或降低该步门槛 | 自动 | 转化漏斗保底 |
| 邀请系数 K 值 > 1.5 且新增账户设备聚集 | 收紧领取校验、延迟发分、标记名单 | 自动 | 裂变热度不被女巫吃掉 |
| 领取→注册转化 < 30%（24h） | 领取页 CTA 从「稍后绑定」改为「注册后立即入账」 | 自动 | 最短路径不断在注册层 |
| 注册→入金转化 < 15%（48h） | 对已注册未入金用户推首充返赠提示（文案走合规模板） | 确认 | 入金主目标有专属抓手，激励不越合规线 |
| 7 日注册进度 < 目标 50% | 建议追加白名单名额或阶梯保底，附 ROI 预估 | 确认 | 加码决策留在品牌方手里 |
| 单钱包 / 单设备领取频次异常 | 冻结领取资格、转人工复核 | 自动 | 代币池资金安全 |
| 变体 A/B 数据分化明显 | 自动淘汰低效变体，流量并入高效变体 | 自动 | 预算持续流向有效素材 |
| 周期结算日到达 | 自动跑归因 + 女巫终审，生成两端对账单 | 自动 | 结算透明、可核对 |

## 5. 空投特有环节

### 5.1 钱包地址收集与校验

| 步骤 | 机制 | 拦截目标 |
|---|---|---|
| 收集时机 | 完成首个任务后才弹出钱包绑定，不在进入时索要 | 降低首屏流失，避免裸收地址 |
| 格式校验 | 链上格式 + 校验和验证，错误地址即时驳回 | 手滑损耗与故意脏数据 |
| 唯一性校验 | 同一钱包地址仅可绑定一个活动账户；同设备绑定数设上限 | 一人多号的最低成本手法 |
| 链上画像 | 查询地址年龄、历史交互数、是否批量归集地址 | 新铸空钱包批量刷领取 |
| 敏感名单 | 命中制裁名单 / 混币器关联地址直接拒绝并留痕 | AML 义务（结算涉加密货币的 KYC / AML） |
| 变更规则 | 绑定后改地址触发 48h 冷静期 + 重新校验 | 结算前夜换收币地址的套利窗口 |

### 5.2 任务体系（关注 / 转发 / 入群 / 交易）

| 任务 | 验证方式 | 归因事件 | 额度权重 |
|---|---|---|---|
| 关注官方账号 | 平台 API 回查关注状态 | `follow_verified` | 低（门槛任务） |
| 转发活动内容 | 转发链接带唯一参数，回查存续 24h | `share_verified` | 低 |
| 加入官方社群 | 入群后答题验证（延续案例 01 C 路经验：答题验证 + 延迟发分） | `join_verified` | 中 |
| 邀请好友 | 被邀请人完成注册才计入，邀请加成系数封顶 | `invite_converted` | 中 |
| 注册交易所 | 归因参数 + 品牌方核销回传 | `register` | 高 |
| 入金 / 首笔交易 | 品牌方核销回传（金额分档） | `deposit` / `trade` | 最高（决定白名单档位） |

任务设计原则：**低权重任务给参与感，高权重额度只跟着注册与入金走**——空投额度的大头必须押在品牌方真正付钱的转化事件上。

### 5.3 女巫攻击（Sybil）防护

| 攻击手法 | 识别信号 | 处置 |
|---|---|---|
| 批量小号领取 | 设备指纹聚集、IP 段聚集、注册时间簇 | 降权 → 冻结领取资格 → 名单标记 |
| 脚本化完成任务 | 任务完成间隔恒定、秒级完成、无页面停留 | 该批任务事件作废，不进结算 |
| 新铸钱包矩阵 | 地址无历史交互、同源资金归集 | 链上画像降权，白名单资格取消 |
| 互刷邀请 | 邀请闭环图谱（A 邀 B、B 邀 A 的环状结构） | 邀请加成清零，K 值统计剔除 |
| 结算前集中提现 / 拆单 | 同设备高频小额、地址变更潮 | 冻结该批结算转人工复核，保留申诉通道 |

防护分三道闸：**领取时**（设备 / 钱包校验）、**运行中**（行为风控触发器）、**结算前**（女巫终审）——与结算原则「只为已验证的营销结果付钱」互为表里。

### 5.4 代币发放与归属期

| 规则 | 内容 |
|---|---|
| 活动期 | 玩家只见平台积分与白名单预估额度，不做实时发币 |
| 结算日映射 | 女巫终审 + 品牌方核销通过后，积分按锁定比例映射 `$TOKEN` 额度 |
| 归属期（Vesting） | 上所日解锁 40%，其余 60% 分 3 个月线性解锁；解锁额度进入可提现余额 |
| 领取通道 | 解锁代币提至交易所账户（注册 + 入金的最终承接）；链上直提仅对完成 KYC 的地址开放 |
| 未达门槛 | 可提现余额不足 $10 跨活动累计，与工作台统一提现规则一致 |
| 违约回收 | 归属期内查实女巫的账户，未解锁部分作废回池 |

归属期的营销意义：把「领完即走」拉长为 3 个月的回访与交易窗口，空投从一次性成本变成留存工具。

### 5.5 合规红线（证券化风险 · 地区屏蔽）

| 红线 | 内容 | 系统处置 |
|---|---|---|
| 证券化表述 | 不得出现收益承诺、回报率、保本表述；美国（SEC 证券认定）、欧盟（MiCA）、中国大陆（全面禁止）对代币激励定性各异 | Constraint Agent 全量扫描，命中即拦截改写 |
| 地区屏蔽 | 空投裂变玩法在部分地区构成非法促销或博彩；对高风险司法辖区做 IP + KYC 双重屏蔽 | 屏蔽名单由品牌方法务确认后锁定，KOL 不可见不可改 |
| KYC / AML | 结算涉加密货币的 KYC / AML 义务：大额解锁强制 KYC，敏感地址拒绝 | 结算流程前置条件，不通过不入账 |
| 白名单表述 | 「白名单资格」不得表述为已获得代币；预估额度必须带「以结算核定为准」 | 文案模板锁定字段 |
| 品牌方锁定字段 | 代币总池、映射比例、合规文案、埋点、归因参数——与案例 01 不可改边界完全一致 | 编辑器置灰 / 只读 / 系统托管 |

## 6. 结算与复盘

### 6.1 结算流程

| 阶段 | 发生什么 | 玩家视角 | KOL 视角 |
|---|---|---|---|
| 活动进行 | 积分与白名单预估额度实时累计 | 余额与预估可见、不可提 | 数据看板实时更新 |
| 周期结算日 | 平台跑归因 + 女巫终审 | 无感 | 收到预结算通知 |
| 品牌方核销确认 | 品牌方核对注册 / 入金结果并确认 | 无感 | 争议期可提异议 |
| 入账 | 积分转可提现余额；白名单映射 `$TOKEN` 进入归属期；KOL 分成入钱包 | 余额可提 + 代币按期解锁 | 分成到账（T+7） |
| 提现 | 满 $10 发起提现申请，小额自动审核、大额 KYC，T+3 到账 | 统一提现规则 | 钱包提现走平台通道 |

### 6.2 KOL 结算规则

| 规则 | 内容 |
|---|---|
| 计酬方式 | 归因到本路的有效转化：注册按 CPA + 入金按 CPS 混合计酬；女巫剔除量不计酬 |
| 账期 | 核销确认后 T+7 到账 |
| 对账单 | 附归因明细：转化事件、女巫剔除量与依据、单价 |
| 争议期 | 对账单发出后 72h 内可提异议，平台仲裁 |

### 6.3 双路漏斗对比（推演目标值，非实测）

| 指标 | F · TG 福利任务链 | G · TG 答题空投 |
|---|---|---|
| 任务开始率 | 58% | 44% |
| 任务链完成率 | 47% | 62% |
| 邀请系数 K 值 | 1.8（女巫剔除后 1.2） | 0.6 |
| 领取→注册转化 | 34% | 41% |
| 注册→入金转化 | 14% | 29% |
| 女巫拦截率（占领取申请） | 31% | 9% |
| 归属期 3 个月留存 | 12% | 26% |

### 6.4 对照结论（F vs G）

同在 Telegram：F（福利型）拉新数量与裂变占优，但近三分之一领取申请被女巫终审剔除，入金转化偏低；G（教育型）数量少一档，但注册质量、入金转化与归属期留存全面占优。结论与案例 01 一致且更尖锐：**空投场景下 kol_context 不仅决定产物，还直接决定预算的真实损耗率**——主目标是入金时，教育型路线的每有效转化成本反而更低。

### 6.5 沉淀动作

| 沉淀对象 | 内容 |
|---|---|
| 模板权重 | 「答题解锁掉落」变体在「入金目标 × TG 频道」组合下权重上调 |
| 女巫特征库 | 本期识别的设备簇、地址簇、互刷图谱模式入库，跨活动共享 |
| 触发器库 | 第 4 章验证有效的触发实例升级为空投模板通用规则 |
| KOL memory | 两路的高转化任务顺序、掉落时段、文案敏感点入库 |
| 下一次生成 | 同类空投活动首版直接携带女巫防护参数与任务权重经验 |

## 7. 与塔防 / Tap-to-Earn 案例的差异

| 维度 | 塔防案例（01） | Tap-to-Earn 案例（03） | 空投案例（本篇） |
|---|---|---|---|
| 玩法深度 | 策略局，内容变体差异化 | 极轻点击，经济系统差异化 | 近零玩法，任务与额度设计差异化 |
| 转化路径 | 玩→注册→入金，靠玩法钩子 | 点击→代币→上所交易 | **最短**：领取资格直接绑注册 |
| 核心风险 | 内容合规 | 代币映射合规 + 机器人 | **女巫攻击 + 证券化表述 + 地区合规** |
| 预算损耗点 | 无效流量 | 点击机器人 | 批量小号与新铸钱包矩阵 |
| 最强渠道 | 五平台各有打法 | Telegram 主场 | Telegram 主场（TG 冷启动标配模板） |

## 8. 结论

1. 空投模板验证了平台漏斗的下限速度：任务 → 领取 → 注册 → 入金四层，转化路径三个模板中最短，「领币需交易所账户」是最硬的注册动机。
2. 路径越短、刷子越多：女巫防护必须三道闸（领取时 / 运行中 / 结算前）全开，且与「只为已验证营销结果结算」的平台原则互为表里——这是空投预算安全的唯一解。
3. 代币归属期把空投从一次性拉新成本改造成 3 个月的留存与交易窗口，同时天然规避「活动期实时发币」的合规与挤兑风险。
4. 合规是空投模板的生死线：证券化表述、地区屏蔽、KYC / AML 三项全部走系统锁定字段，KOL 与运营 Agent 均无权触碰。
5. 同平台对照再次成立：kol_context 决定产物与损耗率，入金目标下教育型路线的有效转化成本低于福利型——预算配比应按画像而非按平台。
6. 本案例与塔防（内容深度型）、Tap-to-Earn（经济裂变型）构成模板库三角：空投验证「路径最短型」，三套推演覆盖交易所品牌方从拉新到入金的主要目标组合。
