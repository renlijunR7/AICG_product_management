# 数据反馈、Memory 与模板更新机制结构化梳理

## 1. 核心定义

数据反馈、Memory 与模板更新机制，是 Airvana Agent OS 的学习层。

它把真实运行数据、Agent 决策效果、渠道表现、KOL 编辑行为和转化结果，沉淀回 KOL Memory、Template Memory、内容池、策略库和模板默认值。

核心产物：

| 产物 | 说明 |
|---|---|
| `performance_report` | 活动表现报告 |
| `diagnosis_result` | 诊断结果 |
| `kol_memory` | KOL 长期偏好和表现 |
| `template_memory` | 模板效果和默认策略 |
| `template_update_proposal` | 模板更新建议 |
| `agent_policy_patch` | 策略补丁 |

## 2. 所处位置

| 上游 | 当前环节 | 下游 |
|---|---|---|
| Runtime 事件、转化、渠道、Agent 决策 | 数据反馈、Memory 与模板更新 | 下一轮生成、模板推荐、策略优化 |

这是业务闭环的终点，也是下一轮生成的起点。

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 解释结果 | 判断为什么好或不好 |
| 证明 Agent 价值 | 评估 Runtime 决策是否提升指标 |
| 沉淀 KOL 偏好 | 下次生成更贴合 KOL |
| 优化模板 | 更新默认字段、玩法、CTA、分享 |
| 优化策略 | 更新 `agent_policy` |
| 沉淀负样本 | 避免重复失败和违规 |

## 4. 输入数据

| 输入 | 用途 |
|---|---|
| `runtime_events` | 用户路径和漏斗 |
| `agent_decision_applied` | Agent 决策归因 |
| `conversion_events` | 目标转化 |
| `channel_metrics` | 渠道质量 |
| `config_patch_log` | KOL 编辑偏好 |
| `risk_events` | 风控表现 |
| `validation_report` | 生成和发布阶段问题 |
| `simulation_result` | 上线前预估和真实表现对比 |

## 5. 关键 Agent / 系统

| 模块 | 职责 |
|---|---|
| Analytics Service | 计算漏斗和指标 |
| Diagnosis Agent | 诊断原因和建议 |
| Memory Agent | 写入 KOL / Template / Campaign Memory |
| Template Ops Agent | 生成模板更新建议 |
| Policy Update Agent | 生成策略补丁 |
| Negative Example Manager | 沉淀失败和违规案例 |

## 6. 核心指标

| 指标 | 说明 |
|---|---|
| CTR | 外部点击率 |
| Start Rate | 开始率 |
| Completion Rate | 完成率 |
| Drop-off Rate | 流失率 |
| Share Rate | 分享率 |
| CTA Rate | CTA 点击率 |
| Conversion Rate | 转化率 |
| Reward Claim Rate | 奖励领取 |
| Risk Rate | 异常率 |
| Retention | 回访和复玩 |
| Agent Uplift | Agent 策略增量 |

## 7. 诊断范围

| 诊断对象 | 问题 |
|---|---|
| 漏斗 | 用户在哪一步流失 |
| 内容 | 文案、题目、反馈是否影响结果 |
| 玩法 | 难度、任务长度是否合理 |
| CTA | 时机、文案、目标是否有效 |
| 分享 | 是否带来二跳用户 |
| 渠道 | 哪个渠道质量高 |
| KOL | 粉丝行为和 KOL 编辑偏好 |
| Agent 策略 | 哪些动态策略有效 |
| 风控 | 是否刷量或误伤 |
| 模板 | 是否应该更新默认值 |

## 8. Memory 类型

| Memory | 记录内容 |
|---|---|
| `kol_memory` | KOL 偏好、渠道、语气、成功配置、风险 |
| `template_memory` | 模板适合目标、默认难度、CTA、分享、风险 |
| `campaign_memory` | 单次活动表现和复盘 |
| `content_memory` | 高表现文案、题目、分享卡 |
| `negative_examples` | 低效、违规、失败案例 |

## 9. 模板更新对象

| 更新对象 | 示例 |
|---|---|
| 默认字段 | 默认标题、难度、任务数量 |
| 字段优先级 | KOL 常改字段前置 |
| 内容池 | 高表现标题、分享卡、CTA 文案 |
| Agent 策略 | 提示、难度、CTA、风控 |
| 风控规则 | 限频、重复领取、钱包校验 |
| 合规规则 | 禁止表达、免责声明 |
| 推荐权重 | 模板和渠道推荐排序 |

## 10. 回写流程

| 步骤 | 说明 |
|---|---|
| 1 | 收集事件和转化 |
| 2 | 对齐版本、KOL、渠道和模板 |
| 3 | 计算漏斗和核心指标 |
| 4 | 评估 Agent 决策效果 |
| 5 | Diagnosis Agent 生成诊断 |
| 6 | Memory Agent 写入记忆 |
| 7 | Template Ops Agent 生成更新建议 |
| 8 | 高风险更新进入审核 |
| 9 | 低风险更新进入候选默认值 |
| 10 | 下一轮生成读取 Memory |

## 11. 约束边界

| 约束 | 说明 |
|---|---|
| 不用小样本污染模板 | 单次低样本只写观察 |
| 高风险更新需审核 | 奖励、CTA、风控、合规 |
| Memory 要带置信度 | 不把偶然结果当规律 |
| 模板更新要版本化 | 方便归因和回滚 |
| 风控优先 | 增长策略不能压过风险 |

## 12. MVP 范围

| P0 能力 | 说明 |
|---|---|
| 基础漏斗 | 曝光、开始、完成、分享、CTA、转化 |
| Agent 决策复盘 | 决策后结果追踪 |
| KOL Memory | 记录偏好和有效配置 |
| Template Memory | 记录默认值和表现 |
| 简单 Diagnosis | 输出主要问题和建议 |
| 模板更新建议 | 先建议，不自动上线 |

## 13. P1 / P2 扩展

| 阶段 | 能力 |
|---|---|
| P1 | A/B 分析、渠道评分、内容池自动优化 |
| P2 | 自动模板版本更新、跨 KOL 智能推荐、长期生命周期运营 |

## 14. 验收标准

| 验收项 | 标准 |
|---|---|
| 数据完整 | 事件、版本、渠道、KOL 归因齐全 |
| 决策可复盘 | Agent 决策能关联后续结果 |
| 诊断可解释 | 每个建议有数据证据 |
| Memory 可用 | 下一次生成能读取历史经验 |
| 更新可控 | 模板更新有审核、版本和回滚 |

## 15. 最终结论

数据反馈、Memory 与模板更新，是 Agent OS 真正形成业务闭环的关键。

它让每一次生成和投放不只是结束于报表，而是变成下一次更准生成、更好模板、更强策略和更低风险的经验资产。
