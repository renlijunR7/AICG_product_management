# 案例 · 塔防模板 × 5 KOL 全流程推演

## 1. 案例设定

| 设定项 | 内容 |
|---|---|
| 品牌方 | Gate（沿用工作台品牌合作中的签约方），新公链活动预热 |
| 统一模板 | 塔防「守护金库 · 抵御风险」，同一 `template_schema` |
| 品牌方目标 | 主目标：**注册 + 入金（充值）**；次目标：品牌教育与裂变曝光 |
| 预算与边界 | 每路等额预算；活动期只发**平台积分**（+ 白名单资格），结算后按规则转为可提现余额；首充返赠等入金激励文案需合规审校，不承诺收益 |
| 结算原则 | 平台根据**已验证的营销结果**统一结算 KOL 与玩家两端；玩家可提现余额满门槛后发起提现申请（详见第 6 章） |
| 统一漏斗 | 五路各有平台化的中间 CTA，但末端统一收口：**玩 → 注册 → 入金**，逐层归因 |
| 唯一变量 | KOL 是谁 —— 平台、语言、素材形态、玩法变体全部由 `kol_context` 推导 |
| 渠道原则 | 每个媒体渠道独立闭环：各自链接、归因、运营、看板，互不引流 |

本案例要证明的一件事：**同一个塔防模板 × 不同 kol_context = 五套完全不同的素材、玩法和运营策略**，且全程由工作流的 15 步机制自动承载。

#### 3.6.2 单元素修改（点对点操作）

| # | 操作组 | 可改项 | 编辑器入口 | 影响范围 | 重新验证 | 生效速度 |
|---|---|---|---|---|---|---|
| 1 | 文案类 | 首屏标题 / 按钮文字 / 波次提示 / 结果页 / 分享卡文案 | 点选文本直接改 | 单文案节点 | 敏感词自动扫 | 秒级热更 |
| 2 | 视觉类 | 单个塔 / 敌人 / 背景 / 图标替换、颜色微调 | 点选元素替换 | 单素材节点 | 素材扫描 | 秒级热更 |
| 3 | 数值类 | 波次数、敌人密度、难度曲线、局时长、奖励数值与节奏 | 数值滑杆 | 规则引擎参数 | 超出模板安全区间时触发 | 秒级热更 |
| 4 | 玩法结构类 | 任务顺序调整、关卡增删、CTA 位置与触发时机 | 结构编辑器（拖拽） | 任务链 / 关卡模块 | 是（可玩性模拟） | 分钟级重建 |
| 5 | 规则类 | 胜负条件、组队人数、邀请加成系数；**奖励通证化配置**（见下） | 规则面板 | 规则引擎 + 风控 | 是 | 分钟级重建 |

**奖励通证化配置（规则类特殊项）**：局内金币可映射为品牌方 Token——比例由品牌方在活动创建时设定；结果页 / 奖励页可挂品牌方 App 下载入口，形成"玩 → 赚 → 下载 → 交易"承接链。属于**品牌方确认级**操作：KOL 只能开 / 关和选择展示位，不能改映射比例；任何改动必触发合规重验（收益表述、地区法规、核销规则）。注意：Token 映射在**周期结算环节**统一执行（见第 6 章），活动期内玩家看到的是积分与预估价值，不做实时发币。

> 案例示例：A 路用操作 3 给第 2 波敌人减速 15%；C 路用操作 4 把"入群"从任务第 2 步移到第 3 步；C / E 路开启奖励通证化，结果页挂 Gate App 下载入口，注册与核销数据回流品牌方看板。

#### 3.6.4 不可改边界（品牌方锁定字段）

| 锁定字段 | 原因 | KOL 触碰时的处理 |
|---|---|---|
| 合规文案（免责声明 / 风险提示） | 法务底线 | 编辑器置灰，不可选 |
| 奖励总量与 Token 映射比例 | 预算与资产安全 | 只读展示，改动需品牌方确认流程 |
| 品牌 Logo 使用规范（位置 / 最小尺寸） | 品牌资产保护 | 替换时自动校验，违规回退 |
| 数据埋点（开始 / 完成 / 分享 / CTA / 流失） | 归因与结算依据 | 对 KOL 不可见，系统托管 |
| 归因参数结构 | 多路对比与分成结算 | 自动生成，不可手改 |

触发**全量重新验证**的改动类型：奖励规则、Token 相关、任务链结构、跨语言替换；其余走增量校验，保证"改一处、验一处、秒级见效"的编辑体验。

## 4. 核心二 · 营销 Agentic 化（触发器手册）

原则：**边界内自动执行，超边界需品牌方确认**。品牌方在活动创建时签署边界（预算上限、奖励池、合规红线），Agent 在边界内自主运营。

### 4.1 权限两档

| 档位 | 范围 | 示例 |
|---|---|---|
| 自动执行 | 不动预算、不动奖励总池、不碰合规边界的优化 | 换文案变体、调难度、改 CTA 时机、调任务顺序 |
| 需品牌方确认 | 追加预算、提高奖励、延长活动、跨档策略 | 追投建议、奖励加码、活动延期 |

### 4.2 通用触发器总表

| 触发条件 | Agent 营销动作 | 档位 | 品牌方视角（目标如何被合理达成） |
|---|---|---|---|
| 上线 1h 开始率 < 25% | 自动切换首屏文案 A/B 变体 | 自动 | 预算不浪费在低效入口 |
| 完成率 > 60% 且分享率 < 8% | 分享卡加成绩钩子 + 完局弹分享提示 | 自动 | 裂变目标自动补位 |
| 任务链某步流失 > 40% | 调整任务顺序或降低该步门槛 | 自动 | 转化漏斗保底 |
| 单日转化达标 120% | 生成追投建议 + 预估 ROI 报告 | 确认 | 加码决策留在品牌方手里 |
| 检测异常刷量（设备聚集/秒完成） | 收紧验证、暂缓奖励发放、标记名单 | 自动 | 空投与核销资金安全 |
| 活动过半、注册进度 < 50% | 建议把奖励从抽奖改为阶梯保底 | 确认 | 核心 KPI 有挽救手段 |
| 注册→入金转化 < 15%（48h） | 对已注册未入金用户推首充返赠提示（文案走合规模板） | 确认 | 入金主目标有专属抓手，激励不越合规线 |
| 单用户入金金额异常集中 | 触发反洗钱校验、暂缓返赠发放 | 自动 | 入金激励不被套利 |
| KOL 内容互动衰减（发布 48h） | 提醒 KOL 发第二波素材，附数据依据 | 自动 | 内容节奏由数据驱动 |
| 周期结算日到达 | 自动跑归因 + 风控终审，生成 KOL / 玩家两端对账单 | 自动 | 结算透明、可核对 |
| 品牌方核销确认超时 48h | 提醒品牌方确认，逾期升级人工跟进 | 自动 | 结算不卡在核销环节 |
| 玩家提现请求异常（拆单 / 设备聚集） | 自动冻结该批提现并转人工复核 | 自动 | 提现资金安全 |

### 4.3 每路触发实例

| KOL | 触发场景 | Agent 动作 | 预期影响 |
|---|---|---|---|
| A | 转发率高但点进试玩低 | 试玩卡片换成结果卡样式（先看别人战绩） | 开始率 +5~8 pts |
| B | 群内讨论热但第 4 波流失高 | 第 4 波知识卡提前弹提示 | 完成率回升，教育目标不打折 |
| C | 邀请完成率高、真实入群低 | 入群校验改为答题验证 + 延迟发分 | 刷量下降，有效入群占比上升 |
| D | 成绩卡晒出量大但话题分散 | 统一话题标签自动附到分享卡 | 话题聚合，社团二次传播 |
| E | 晚间开赛在线不足 | 战报提前 2h 推送 + Boss 血条播报 | 到场率提升，注册窗口拉长 |

## 5. 核心三 · 玩法 Agentic 化（塔防内的智能体）

| 智能体 | 使用路 | 触发时机 | 行为 | 预期结果 | 指标影响 |
|---|---|---|---|---|---|
| 智能 NPC 指挥官 | 全路 | 开局 / 连续失误 / 高分 | 以 KOL 语气分身播报：提示、鼓励、口头禅嘲讽 | 玩家感到"KOL 在陪玩" | 完成率、停留时长 ↑ |
| NPC 知识讲师（B 变体） | B | 每波开始前 | 出知识题、讲解本波卖点 | 玩=学，答对得加成 | 教育完成度、入群意愿 ↑ |
| 智能主持人 | C / E | 组队开赛 / Boss 波 / 榜单变化 | 实时播报战况、点名表扬、召集下一场 | 集体氛围与仪式感 | 回访率、组队率 ↑ |
| 智能客服 | C / D | 玩家询问规则 / 奖励 / 核销 / 提现进度与门槛 | 多语言即时答疑（含"还差多少可提现"），超纲转人工 | 客诉不外溢到评论区 | 流失率、差评率 ↓ |
| 动态难度调节 | 全路 | 连败 2 局 / 三星通关 | 降波次密度 / 追加挑战波 | 新手不弃坑、高手不无聊 | 完成率、复玩率 ↑ |
| 动态奖励节奏 | 全路 | 完成率偏离目标区间 | 调整积分发放节奏与提示强度 | 激励贴着数据走 | CTA 转化 ↑ |

所有玩法智能体共用一条约束：**行为必须落在 `agent_policy` 声明的策略边界内**（不新增奖励总量、不改变合规文案、不伪造数据），每次干预记录为决策事件，供复盘归因。

## 6. 奖励结算与提现机制

### 6.1 结算原则

1. 活动期内玩家赚到的都是**平台积分**（局内金币按规则折算），余额实时可见但不可提。
2. 周期结算日，平台根据**已验证的营销结果**（注册、入金等归因事件，扣除刷量与无效转化）**统一结算两端**：KOL 分成 + 玩家奖励。
3. 结算前置条件：反作弊终审通过 + 品牌方核销确认，资金才从品牌方预算池划出。

### 6.2 结算流程

| 阶段 | 发生什么 | 玩家视角 | KOL 视角 |
|---|---|---|---|
| 活动进行 | 积分实时累计，展示预估价值 | 余额可见、不可提 | 数据看板实时更新 |
| 周期结算日 | 平台跑归因 + 风控终审 | 无感 | 收到预结算通知 |
| 品牌方核销确认 | 品牌方核对转化结果并确认 | 无感 | 争议期可提异议 |
| 入账 | 积分按结算汇率转为可提现余额；KOL 分成入钱包 | 余额变为可提现 | 分成到账（T+7） |
| 提现 | 玩家满门槛发起提现申请 | 见 6.3 | 钱包提现走平台通道 |

### 6.3 玩家提现规则

| 规则 | 内容 |
|---|---|
| 提现门槛 | 可提现余额 ≥ $10 才能发起提现申请；未达门槛跨活动累计 |
| 审核分档 | 小额（<$50）自动审核；大额触发 KYC 验证 |
| 到账时效 | 审核通过后 T+3 内到账 |
| 防拆单 | 同一账户 / 设备高频小额提现自动合并审核 |
| 异常处理 | 疑似刷量账户冻结提现，保留申诉通道，人工复核后放行或没收 |

### 6.4 KOL 结算规则

| 规则 | 内容 |
|---|---|
| 计酬方式 | 归因到本路的有效转化：注册按 CPA + 入金按 CPS 混合计酬 |
| 账期 | 核销确认后 T+7 到账 |
| 对账单 | 每期附归因明细（转化事件、扣除的无效量、单价） |
| 争议期 | 对账单发出后 72h 内可提异议，平台仲裁 |

### 6.5 每路结算实例

| KOL | 玩家积分来源 | 结算依据 | 玩家提现场景 |
|---|---|---|---|
| A | 快局通关 + 转发加成 | 结果卡注册归因 | 美国玩家多局累计满 $10 提现 |
| B | 教学局完成 + 答题加成 | 入群→注册→首充归因 | 华语玩家学习奖励结算后提现 |
| C | 任务链 + 组队通关积分 | 空投任务完成 + 注册归因 | 越南玩家组队积分满门槛集中提现（风控重点路） |
| D | 限时冲分 + 挑战加成 | 抽奖注册归因 | 巴西玩家中奖金额直接入可提现余额 |
| E | Boss 战贡献 + 公会加成 | 注册 + 入金双层归因 | 中东玩家公会补给结算后提现 |

### 7.2 同平台对照结论（B vs C）

同在 Telegram：B（教育型）注册质量与注册→入金转化最高（教育完成的用户敢入金），C（福利型）注册数量与裂变占优但入金转化偏低。结论：**平台不决定产物，kol_context 决定产物**；主目标是入金时应加重教育型画像的预算配比，而不是按平台选人。

## 8. 结论

1. 创作 AI 化：五路 KOL 在同一模板上仅通过结构化输入与局部编辑，产出五套完全不同的素材与玩法，全程无人改代码。
2. 营销 Agentic 化：触发器手册 + 两档权限，让品牌方目标在无人值守时也被"合理地"推进——自动优化守下限，确认类建议抬上限。
3. 玩法 Agentic 化：NPC / 主持人 / 客服 / 动态难度让 Playable 从素材变成"有人运营的场子"，直接抬升完成、留存与转化。
4. 主目标「注册 + 入金」的落法：五路各用平台原生的钩子做入口（转发 / 入群 / 组队 / 晒分 / 公会），但末端统一收口到 注册 → 入金 双层漏斗，层层可归因；入金激励一律走合规模板并带反套利风控。
5. 奖励结算平台统一：玩家先赚积分、结算后转可提现余额、满门槛发起提现——两端资金都以"已验证的营销结果"为唯一依据，品牌方预算安全，玩家激励可信。
6. 数据回流让这套推演变成飞轮：每一路的经验都沉淀为下一次生成的起点。
