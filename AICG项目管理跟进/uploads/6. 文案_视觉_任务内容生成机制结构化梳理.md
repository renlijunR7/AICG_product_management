# 文案、视觉、任务内容生成机制结构化梳理

## 1. 核心定义

文案、视觉、任务内容生成，是指在创作 Brief 已经确定之后，系统把 `generation_brief` 转换成用户真正能看见、能理解、能点击、能完成的内容素材。

它属于 Agentic Playable 的“内容层”，不是完整游戏规则，也不是运行时 Agent 策略。

| 不是 | 是 |
|---|---|
| 不是游戏规则生成 | 是生成页面文案、视觉素材和任务内容 |
| 不是 Builder 组装 | 是给 Builder 提供可组装的素材包 |
| 不是 Agentic 运行策略 | 是给用户体验提供可展示内容 |
| 不是纯文案输出 | 同时包含视觉、任务、题目、反馈、分享和 CTA 内容 |

一句话：

**文案、视觉、任务内容生成 = 把创作 Brief 变成用户可见、可读、可操作的内容素材包。**

## 2. 在完整工作流中的位置

| 阶段 | 输入 | 输出 |
|---|---|---|
| 创作 Brief 生成 | `kol_context`、`campaign_goal`、`template_config`、合规边界 | `generation_brief` |
| 文案、视觉、任务内容生成 | `generation_brief`、`template_schema`、`asset_inventory` | `content_assets` |
| 游戏规则生成 | `generation_brief`、`template_config` | `game_rules` |
| Agent 策略生成 | `campaign_goal`、用户路径、风险边界 | `agent_policy` |
| 约束验证 | `content_assets`、`game_rules`、`agent_policy` | `validation_report` |
| H5 组装 | `content_assets`、`game_rules`、`agent_policy`、模板代码 | `playable_version` |

这个阶段负责回答：

1. 用户第一眼看到什么？
2. 用户每一步读到什么？
3. 用户要完成什么任务？
4. 用户完成后看到什么反馈？
5. 用户为什么愿意分享？
6. 用户在什么时候被引导 CTA？

## 3. 和相邻阶段的区别

| 环节 | 负责什么 | 不负责什么 |
|---|---|---|
| 创作 Brief 生成 | 确定创作方向和任务说明 | 不生成最终页面内容 |
| 文案生成 | 标题、按钮、说明、结果、分享、CTA 文案 | 不决定玩法胜负规则 |
| 视觉生成 | 背景、角色、图标、奖励图、分享卡、风格提示 | 不写游戏逻辑 |
| 任务内容生成 | 题目、任务、关卡目标、敌人设定、道具说明 | 不决定运行时动态策略 |
| 游戏规则生成 | 胜负条件、计分、奖励触发、反作弊 | 不负责具体文案风格 |
| Agent 策略生成 | 动态难度、提示、奖励、CTA 时机 | 不负责基础素材生成 |
| Builder 组装 | 把素材、规则和模板组合成 H5 | 不创作内容本身 |

## 4. 主要输入

| 输入对象 | 关键字段 | 作用 |
|---|---|---|
| `generation_brief` | 创作目标、用户对象、语气、内容任务、规则任务、合规边界 | 决定生成方向 |
| `template_schema` | 页面结构、必需字段、可编辑字段、资产槽位 | 决定内容要填到哪里 |
| `template_config` | 主题、奖励、CTA、任务数量、难度 | 决定本次活动具体内容 |
| `kol_context` | KOL 语气、粉丝画像、历史偏好 | 决定表达方式和分享感 |
| `asset_inventory` | Logo、头像、图标、角色、题库、背景、奖励图 | 决定能复用什么素材 |
| `project_context` | 项目卖点、功能、风险提示、活动规则 | 决定知识和任务内容 |
| `compliance_constraints` | 禁止表达、免责声明、奖励边界 | 决定内容安全边界 |
| `channel_context` | X、Telegram、TikTok、Discord、广告投放 | 决定文案长度和视觉比例 |

## 5. 核心输出

这个阶段最终输出统一对象 `content_assets`。

| 输出对象 | 内容 |
|---|---|
| `copy_assets` | 首屏标题、副标题、按钮、任务说明、反馈、结果页、CTA、免责声明 |
| `visual_assets` | 背景、角色、图标、奖励图、任务图标、分享卡、视觉风格提示 |
| `task_content` | 题目、任务列表、关卡目标、敌人设定、道具说明、教育节点 |
| `share_assets` | 分享标题、分享描述、分享卡视觉、邀请语 |
| `feedback_assets` | 成功、失败、部分完成、奖励获得、风险提示、下一步建议 |
| `localization_assets` | 不同语言和渠道的文案版本 |
| `content_metadata` | 来源、版本、生成时间、使用的 Brief、风险标记 |

`content_assets` 必须能被 Builder 直接读取，而不是一段散乱文本。

## 6. 文案生成

文案生成负责所有用户可读文本。

### 6.1 文案类型

| 文案类型 | 示例 | 作用 |
|---|---|---|
| 首屏标题 | 测测你是不是懂行情的玩家 | 决定开始率 |
| 首屏副标题 | 完成 3 道题，解锁 KOL 专属活动资格 | 解释价值 |
| 按钮文案 | 开始挑战、立即参与、领取资格 | 驱动操作 |
| 任务说明 | 加入 Telegram 并完成项目问答 | 告诉用户做什么 |
| 题目文案 | 这个项目主要解决哪类问题？ | 承载玩法内容 |
| 选项文案 | 交易安全 / 游戏资产 / 社群治理 | 形成互动 |
| 成功反馈 | 答对了，你理解了项目核心场景 | 给用户正反馈 |
| 失败反馈 | 这题容易混淆，看看提示再试一次 | 降低流失 |
| 奖励文案 | 完成后获得抽奖资格，奖励以官方规则为准 | 激励并控风险 |
| CTA 文案 | 加入 Telegram 查看活动进度 | 引导转化 |
| 分享文案 | 我完成了 KOL 专属 Web3 挑战 | 引导裂变 |
| 免责声明 | 本活动不构成投资建议 | 合规 |

### 6.2 文案生成原则

| 原则 | 说明 |
|---|---|
| 目标一致 | 文案必须服务 `campaign_goal` |
| KOL 语气一致 | 不能像平台官方冷冰冰地说话 |
| 用户水平匹配 | 新手少术语，专业用户可增加深度 |
| 行动明确 | 每一步都要告诉用户下一步做什么 |
| 奖励克制 | 奖励表达不能误导或承诺收益 |
| CTA 自然 | CTA 要跟用户当前状态匹配 |
| 可分享 | 结果文案要能形成社交表达 |
| 可验证 | 文案要能通过合规和品牌校验 |

### 6.3 文案输出结构

| 字段 | 说明 |
|---|---|
| `hero_title` | 首屏主标题 |
| `hero_subtitle` | 首屏副标题 |
| `start_button` | 开始按钮 |
| `instruction_copy` | 玩法说明 |
| `task_copy` | 任务说明 |
| `question_copy` | 题目和选项 |
| `feedback_copy` | 成功/失败/提示反馈 |
| `reward_copy` | 奖励说明 |
| `cta_copy` | CTA 文案 |
| `share_copy` | 分享文案 |
| `disclaimer_copy` | 合规提示 |

## 7. 视觉生成

视觉生成负责所有可见视觉素材或视觉生成指令。MVP 阶段可以先用现有资产 + 模板化视觉，后续再做 AI 图像生成。

### 7.1 视觉类型

| 视觉类型 | 示例 | 作用 |
|---|---|---|
| 品牌视觉 | 项目 Logo、主色、Slogan | 建立识别 |
| KOL 视觉 | KOL 头像、签名、专属房间名 | 建立信任和专属感 |
| 背景视觉 | 太空、链上世界、赛道、基地、战场 | 包装主题 |
| 角色视觉 | 玩家角色、KOL 化身、项目角色 | 增强代入 |
| 玩法视觉 | 题卡、任务卡、敌人、塔、武器、道具 | 支撑玩法 |
| 经济视觉 | Token、积分、徽章、奖励卡、资格卡 | 支撑激励 |
| 结果视觉 | 分数卡、等级卡、成就页 | 支撑反馈 |
| 分享视觉 | 社媒分享卡、邀请卡、排行榜卡 | 支撑裂变 |
| 合规视觉 | 规则入口、免责声明、活动条款图标 | 支撑信任 |

### 7.2 视觉生成方式

| 方式 | 适用场景 |
|---|---|
| 复用已有资产 | 项目 Logo、KOL 头像、Token 图标、官方背景 |
| 模板化组合 | 将 Logo、头像、标题、奖励图组合成分享卡 |
| AI 生成辅助资产 | 背景、角色、道具、敌人、奖励图 |
| 图标库 / 素材库 | 任务图标、按钮图标、通用道具 |
| 降级占位 | 缺少视觉资产时先用品牌色和简单图形 |

### 7.3 视觉资产字段

| 字段 | 说明 |
|---|---|
| `brand_logo` | 项目 Logo |
| `kol_avatar` | KOL 头像 |
| `background_image` | 背景图 |
| `character_assets` | 角色图 |
| `game_object_assets` | 道具、敌人、收集物、塔、武器 |
| `reward_assets` | 奖励、徽章、资格卡 |
| `task_icons` | 任务图标 |
| `share_card_image` | 分享卡图 |
| `result_card_image` | 结果卡图 |
| `visual_style_prompt` | AI 视觉生成提示 |
| `asset_fallbacks` | 缺失资产时的替代方案 |

### 7.4 视觉优先级

| 优先级 | 视觉内容 |
|---|---|
| P0 | 项目 Logo、KOL 头像、首屏背景、奖励图、分享卡 |
| P1 | 角色、任务图标、结果卡、排行榜头像、道具 |
| P2 | 高级背景、多状态角色、动画帧、复杂场景 |

MVP 不要一开始追求全量视觉自动生成，先保证首屏、任务、奖励、结果和分享能成立。

## 8. 任务内容生成

任务内容生成负责用户在 Playable 中实际要完成的内容。它介于“文案”和“游戏规则”之间：它定义用户看到的任务是什么，但不完全定义底层规则如何执行。

### 8.1 任务内容类型

| 任务类型 | 示例 | 适合目标 |
|---|---|---|
| 知识问答 | 回答项目知识题 | 用户教育、项目认知 |
| 行情竞猜 | 判断行情或事件方向 | 拉新、互动、社群讨论 |
| 空投任务 | 关注、入群、答题、分享 | 社群增长、转化领取 |
| 收集任务 | 收集 Token、积分、徽章 | 拉新、裂变、留存 |
| 防守任务 | 抵御风险、保护资产 | 教育、留存、项目叙事 |
| 射击任务 | 击中目标、清除风险 | 激活、娱乐传播 |
| 路径任务 | 画线到达目标、避开障碍 | 教育、轻互动 |
| 经营任务 | 升级建筑、管理资源、完成增长 | 深度教育、留存 |
| 分享任务 | 分享结果、邀请好友 | 裂变传播 |
| CTA 任务 | 入群、注册、关注、领取 | 转化 |

### 8.2 任务内容字段

| 字段 | 说明 |
|---|---|
| `task_id` | 任务 ID |
| `task_type` | 问答、分享、入群、收集、击中、画线等 |
| `task_title` | 任务标题 |
| `task_description` | 任务说明 |
| `task_goal` | 用户要完成什么 |
| `task_success_feedback` | 成功反馈 |
| `task_failure_feedback` | 失败反馈 |
| `task_reward_hint` | 奖励提示 |
| `task_cta` | 任务完成后的下一步动作 |
| `task_risk_flags` | 风险标记 |
| `tracking_event` | 对应埋点事件 |

### 8.3 任务内容生成原则

| 原则 | 说明 |
|---|---|
| 任务少而清晰 | MVP 不要一开始堆太多任务 |
| 先低门槛再高价值 | 先让用户开始，再引导入群/注册 |
| 每个任务都有反馈 | 完成、失败、跳过都要有文案 |
| 每个任务可追踪 | 能记录完成、流失、点击和异常 |
| 任务和奖励绑定 | 用户知道完成任务有什么结果 |
| 任务和目标一致 | 不为互动而互动 |
| 任务可局部替换 | KOL 二次编辑时只改任务内容，不重跑全链 |

## 9. 三类内容的关系

| 内容层 | 回答的问题 | 示例 |
|---|---|---|
| 文案 | 用户读到什么 | 标题、说明、反馈、CTA |
| 视觉 | 用户看到什么 | 背景、角色、图标、分享卡 |
| 任务内容 | 用户做什么 | 答题、入群、收集、击中、画线 |

三者必须一致。

| 不一致情况 | 问题 |
|---|---|
| 文案说空投，任务是纯答题 | 用户预期落差 |
| 视觉是高收益金融感，合规要求不能承诺收益 | 合规风险 |
| 任务是入群，CTA 却是购买 | 转化路径冲突 |
| 分享卡强调高收益，实际奖励只是积分 | 误导用户 |
| KOL 语气轻松，但项目方要求严肃金融披露 | 品牌和合规冲突 |

## 10. 不同模板的内容生成重点

### 10.1 竞猜 / 预测模板

| 内容类型 | 生成重点 |
|---|---|
| 文案 | 首屏挑战感、题目解释、结果分型、分享卡 |
| 视觉 | 题卡、币种图标、结果卡、KOL 头像、分享卡 |
| 任务内容 | 题目、选项、正确/错误反馈、提示 |
| 合规重点 | 不预测收益，不构成投资建议 |
| 数据重点 | 每题完成率、正确率、流失点、分享率 |

### 10.2 空投任务模板

| 内容类型 | 生成重点 |
|---|---|
| 文案 | 任务说明、奖励说明、规则说明、入群 CTA |
| 视觉 | 奖励卡、任务图标、KOL 专属活动卡、分享卡 |
| 任务内容 | 关注、入群、答题、分享、钱包验证 |
| 合规重点 | 不保证空投，不承诺收益，奖励以官方规则为准 |
| 数据重点 | 任务完成率、入群点击、分享、异常行为 |

### 10.3 跑酷模板

| 内容类型 | 生成重点 |
|---|---|
| 文案 | 开始挑战、收集提示、结果等级、分享文案 |
| 视觉 | 角色、赛道、障碍物、收集物、结果卡 |
| 任务内容 | 收集 Token、避开障碍、到达终点 |
| 合规重点 | 收集物不能暗示实际收益 |
| 数据重点 | 开始率、完赛率、收集率、失败点 |

### 10.4 塔防模板

| 内容类型 | 生成重点 |
|---|---|
| 文案 | 防守目标、敌人解释、防御塔说明、胜利反馈 |
| 视觉 | 地图、敌人、防御塔、技能、Boss、基地 |
| 任务内容 | 建塔、升级、防守波次、击败 Boss |
| 合规重点 | 项目能力表达不能夸大 |
| 数据重点 | 波次流失、升级选择、胜利率、CTA |

### 10.5 射击模板

| 内容类型 | 生成重点 |
|---|---|
| 文案 | 目标说明、连击反馈、分数等级、分享文案 |
| 视觉 | 目标物、武器、特效、分数卡、结果卡 |
| 任务内容 | 击中目标、连击、清除风险、获得分数 |
| 合规重点 | 目标和奖励表达不能误导 |
| 数据重点 | 命中率、连击、完赛率、分享率 |

### 10.6 画线 / 路径规划模板

| 内容类型 | 生成重点 |
|---|---|
| 文案 | 起点说明、终点目标、障碍提示、路径反馈 |
| 视觉 | 地图、路径区域、障碍物、目标点、成功标记 |
| 任务内容 | 画线、连接目标、避开风险、收集资源 |
| 合规重点 | 不能表达确定收益路径 |
| 数据重点 | 路径完成率、失败点、提示使用、CTA |

### 10.7 模拟经营模板

| 内容类型 | 生成重点 |
|---|---|
| 文案 | 资源说明、建筑说明、升级提示、经营报告 |
| 视觉 | 建筑、资源、角色、事件卡、经营面板 |
| 任务内容 | 生产资源、升级建筑、处理事件、完成增长目标 |
| 合规重点 | 经济系统不能变成收益承诺 |
| 数据重点 | 升级路径、资源消耗、复访、任务完成 |

## 11. 内容生成流程

推荐生成流程如下：

1. 读取 `generation_brief`，确认目标、用户、语气和生成任务。
2. 读取 `template_schema`，确认页面槽位、任务槽位、视觉槽位。
3. 读取 `asset_inventory`，判断哪些视觉和内容可以复用。
4. 生成 `copy_assets`：首屏、任务、反馈、CTA、分享、免责声明。
5. 生成 `task_content`：题目、任务、关卡目标、教育节点。
6. 生成 `visual_assets`：视觉引用、视觉组合、AI 生成提示、缺失资产方案。
7. 对文案、视觉、任务做一致性校验。
8. Constraint Service 做合规和品牌校验。
9. 输出统一 `content_assets`。
10. Builder 读取 `content_assets` 组装 H5。

## 12. 内容生成后的校验

### 12.1 文案校验

| 校验项 | 说明 |
|---|---|
| 目标一致 | 是否服务 `campaign_goal` |
| 语气一致 | 是否符合 KOL 和项目要求 |
| CTA 一致 | 是否和目标动作匹配 |
| 奖励合规 | 是否误导奖励或承诺收益 |
| 可理解 | 新手是否能看懂 |
| 可操作 | 每一步是否有明确动作 |
| 可分享 | 分享文案是否自然 |

### 12.2 视觉校验

| 校验项 | 说明 |
|---|---|
| 品牌一致 | Logo、颜色、项目名是否正确 |
| KOL 一致 | 头像、昵称、语气是否匹配 |
| 资产完整 | 必需图片或图标是否缺失 |
| 模板适配 | 视觉是否符合模板槽位 |
| 合规安全 | 视觉是否暗示收益、误导奖励或侵权 |
| 移动端可读 | 分享卡和首屏是否适合手机 |

### 12.3 任务内容校验

| 校验项 | 说明 |
|---|---|
| 任务可完成 | 用户是否知道怎么完成 |
| 任务可追踪 | 是否对应埋点事件 |
| 任务顺序合理 | 是否先低门槛后高价值 |
| 任务与奖励匹配 | 奖励是否和任务难度匹配 |
| 任务与 CTA 匹配 | 任务是否自然导向 CTA |
| 风险可控 | 高奖励任务是否有反作弊和限制 |

|---|---|
| `content_asset_id` | 内容资产 ID |

| `template_id` | 对应模板 |
| `copy_assets` | 文案资产 |

## 14. 与 Builder 的接口

Builder 不应该读取散文式内容，而应该读取结构化的 `content_assets`。

| Builder 需要什么 | 来自哪里 |
|---|---|
| 页面槽位内容 | `copy_assets` |
| 图片和图标 | `visual_assets` |
| 任务列表 | `task_content` |
| 结果页内容 | `feedback_assets` |
| 分享卡 | `share_assets` |
| CTA | `cta_assets` |
| 合规提示 | `disclaimer_assets` |
| 缺失资产降级 | `fallback_assets` |

如果 Builder 无法找到必需字段，应该返回内容缺失报告，而不是生成半成品。

## 15. KOL 二次编辑机制

KOL 二次编辑通常发生在内容层，而不是规则层。

| KOL 修改 | 更新对象 | 是否需要重生成规则 |
|---|---|---:|
| 改首屏标题 | `copy_assets.hero_title` | 否 |
| 改分享文案 | `share_assets` | 否 |
| 改任务说明 | `task_content.task_description` | 视情况 |
| 改题目内容 | `task_content.question_items` | 可能 |
| 改奖励表达 | `copy_assets.reward_copy`、合规校验 | 可能 |
| 改角色/背景 | `visual_assets` | 否 |
| 改 CTA 文案 | `cta_assets` | 否 |
| 改 CTA 目标 | `campaign_goal`、`template_config` | 是，需要上游重算 |

推荐流程：

1. KOL 在预览页修改某个内容。
2. 系统生成 `content_patch`。
3. 判断是否只影响文案/视觉/任务内容。
4. 如果只影响内容层，只重生成相关资产。
5. 如果影响规则、奖励或 CTA 目标，回到 Brief 或关键变量层。
6. Constraint Service 校验后生成新版本。

## 16. 合规和品牌边界

内容层最容易出现合规和品牌风险，尤其是 Web3、金融、奖励和空投场景。

| 风险 | 示例 | 处理 |
|---|---|---|
| 收益承诺 | 完成任务必赚、必中空投 | 禁止生成或自动改写 |
| 投资建议 | 现在买入、未来涨幅 | 禁止生成 |
| 奖励误导 | 完成即可获得真实 Token | 改为资格、积分或抽奖机会 |
| 虚假背书 | 官方保证、交易所认证 | 需要项目方确认 |
| 品牌不一致 | Logo 错误、项目名错误、语气不符 | 阻止发布 |
| 分享误导 | 分享卡夸大奖励 | 强化审核 |
| 未披露推广 | KOL 广告未标注 | 根据地区和平台规则加披露 |

内容生成必须内置 `do_not_claim` 和 `required_disclaimers`。

## 17. 数据追踪要求

内容生成阶段也要考虑埋点，因为用户接触的是内容。

| 内容 | 推荐事件 |
|---|---|
| 首屏标题 | `playable_impression`、`playable_start` |
| 任务卡 | `scene_view`、`user_action` |
| 题目 | `question_view`、`answer_submit` |
| 任务完成 | `step_complete` |
| 奖励提示 | `reward_view`、`reward_granted` |
| 分享卡 | `share_card_view`、`share_click` |
| CTA | `cta_view`、`cta_click` |
| 失败反馈 | `drop_off`、`retry_click` |

复盘时要能回答：

1. 首屏文案是否影响开始率？
2. 哪个任务导致流失？
3. 哪个视觉/分享卡带来更多分享？
4. 哪个奖励表达带来转化但也带来风险？
5. 哪个 KOL 语气更适合该受众？

## 21. 不建议的做法

| 不建议事项 | 原因 |
|---|---|
| 只生成文案，不生成任务内容 | Builder 无法形成可玩体验 |
| 只换视觉皮肤，不改任务和 CTA | 不能真正影响营销结果 |
| 让视觉先行决定玩法 | 容易变成好看的空壳 |
| 文案脱离 KOL 语气 | KOL 不愿意分享 |
| 分享卡夸大奖励 | 合规和信任风险高 |
| 任务内容不可追踪 | 后续无法复盘 |
| 内容层修改后重跑全部链路 | 成本高且容易引入新错误 |

## 22. 结论

文案、视觉、任务内容生成是 Agentic Playable 从“任务书”进入“用户体验素材”的关键阶段。

它要解决三件事：

| 问题 | 解决方式 |
|---|---|
| 用户看什么 | 生成首屏、结果、反馈、CTA、分享文案 |
| 用户看到什么视觉 | 生成或选择背景、角色、图标、奖励图、分享卡 |
| 用户做什么 | 生成题目、任务、关卡目标、路径、敌人、道具说明 |

MVP 阶段最重要的是：

1. 先把 `content_assets` 结构定义清楚。
2. P0 先支持竞猜、空投、盲盒、任务闯关。
3. 视觉先用已有资产和模板化组合，不要过早追求复杂 AI 生成。
4. 每个内容都要能通过合规校验，并能绑定埋点。
5. KOL 二次编辑优先做内容层 Patch，不要每次重跑整条链路。

这样，文案、视觉、任务内容生成才不是“生成几句文案”，而是把 Brief 稳定转成可组装、可发布、可运营、可复盘的内容资产层。
