# H5 Builder 构建与版本管理机制结构化梳理

## 1. 核心定义

H5 Builder 构建与版本管理机制，是 Airvana Agent OS 的交付构建层。

它负责把模板 schema、配置、内容资产、游戏规则、Agent 策略和埋点要求，组装成一个可预览、可测试、可发布、可追踪的 H5 Agentic Playable。

核心产物：

| 产物 | 说明 |
|---|---|
| `playable_version` | 可运行的 H5 版本 |
| `preview_url` | 预览链接 |
| `runtime_config` | 运行时配置 |
| `tracking_map` | 事件和归因映射 |
| `version_manifest` | 版本清单 |

## 2. 所处位置

| 上游 | 当前环节 | 下游 |
|---|---|---|
| `validation_report` 通过后的生成产物 | H5 Builder 构建与版本管理 | 模拟测试、预览、KOL 二次编辑 |

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 生成真实可玩的 H5 | 不是只生成配置或设计稿 |
| 保证版本可追踪 | 每次修改都有版本 |
| 保证事件可回收 | 运行和复盘需要埋点 |
| 保证 Runtime 可用 | 支持动态策略槽位 |
| 保证可回滚 | 已发布版本不能原地覆盖 |

## 4. 输入数据

| 输入 | 用途 |
|---|---|
| `template_schema` | 组件和页面结构 |
| `template_config` | 关键变量 |
| `content_assets` | 文案、题目、分享卡、视觉 |
| `game_rules` | 状态机、完成条件、奖励 |
| `agent_policy` | Runtime 动态运营策略 |
| `tracking_requirements` | 埋点要求 |
| `validation_report` | 校验通过证明 |

## 5. 关键系统

| 系统 | 作用 |
|---|---|
| H5 Builder | 组装页面、玩法和配置 |
| Asset Pipeline | 处理图片、音频、视觉资源 |
| Config Compiler | 把结构化配置编译成 Runtime 配置 |
| Version Manager | 管理版本、发布状态、回滚 |
| Preview Service | 生成预览链接 |
| Runtime SDK | 埋点、状态、动态策略应用 |
| Tracking Injector | 注入事件和归因参数 |

## 6. 关键 Agent

| Agent | 职责 |
|---|---|
| Builder Agent | 调用 Builder 并处理构建结果 |
| Version Agent | 生成和管理版本 |
| Tracking Agent | 确认埋点注入 |
| Asset Agent | 检查素材可用性 |
| Build Critic | 检查构建产物是否可发布 |

## 7. 构建流程

| 步骤 | 说明 |
|---|---|
| 1 | 读取模板 schema |
| 2 | 合并 `template_config` |
| 3 | 注入 `content_assets` |
| 4 | 编译 `game_rules` |
| 5 | 注入 `agent_policy` |
| 6 | 注入 `tracking_map` |
| 7 | 生成 H5 包 |
| 8 | 生成 `preview_url` |
| 9 | 写入 `playable_version` |
| 10 | 进入模拟测试 |

## 8. 版本对象

| 版本 | 说明 |
|---|---|
| `playable_version_id` | H5 版本 |
| `template_version_id` | 模板版本 |
| `config_version_id` | 配置版本 |
| `content_version_id` | 内容版本 |
| `game_rules_version_id` | 规则版本 |
| `agent_policy_version_id` | 策略版本 |
| `tracking_schema_version_id` | 埋点版本 |

## 9. Runtime 支撑能力

| 能力 | 说明 |
|---|---|
| 状态管理 | 当前页面、分数、进度、失败次数 |
| 事件上报 | 曝光、开始、完成、分享、CTA、转化 |
| 动态槽位 | 提示、难度、CTA、奖励、分享卡 |
| 决策应用 | 接收 `runtime_decision` 并应用 |
| 降级策略 | Runtime 失败时使用默认配置 |

## 10. 约束边界

| 约束 | 说明 |
|---|---|
| 未通过验证不能构建 | 必须有 `validation_report` |
| 已发布版本不能原地覆盖 | 修改必须生成新版本 |
| 构建产物必须可追踪 | 缺事件不能发布 |
| Runtime 槽位必须受控 | 不能让前端自由改规则 |
| 外部链接必须校验 | CTA 和分享链接要安全 |

## 11. MVP 范围

| P0 能力 | 说明 |
|---|---|
| 固定模板构建 | 先支持 1-2 个模板 |
| 配置驱动 | 不手写每个版本 |
| 预览链接 | 给 KOL 和运营查看 |
| 基础埋点注入 | 核心事件完整 |
| 版本记录 | 每次生成有版本 ID |
| Runtime 基础槽位 | 提示、CTA、风控 |

## 12. P1 / P2 扩展

| 阶段 | 能力 |
|---|---|
| P1 | 多模板 Builder、灰度发布、自动回滚 |
| P2 | 可视化模板编辑器、插件式玩法组件、跨端构建 |

## 13. 验收标准

| 验收项 | 标准 |
|---|---|
| 可打开 | H5 预览链接可访问 |
| 可玩 | 主路径能完成 |
| 可追踪 | 事件正常上报 |
| 可动态 | Runtime 策略能应用 |
| 可回滚 | 版本可以恢复 |

## 14. 最终结论

Builder 是 Agent OS 从“生成内容”走向“交付产品”的关键层。

没有 Builder，AI 产物只是文档；有了 Builder，Airvana 才能生成真实可发布的 Agentic Playable。
