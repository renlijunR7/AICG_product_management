# RAG 上下文检索与知识注入机制结构化梳理

## 1. 核心定义

RAG 上下文检索与知识注入，是 Airvana Agent OS 的知识层。

它让每个 Agent 在生成、规划、校验和复盘时，不只依赖模型参数，而是读取 KOL、项目、模板、合规、案例和历史表现等业务知识。

核心产物：

| 产物 | 说明 |
|---|---|
| `retrieval_context` | 本次任务检索到的上下文包 |
| `source_trace` | 知识来源记录 |
| `context_bundle` | 给 Agent 使用的压缩上下文 |
| `negative_examples_context` | 失败和违规案例 |

## 2. 所处位置

| 上游 | 当前环节 | 下游 |
|---|---|---|
| `campaign_goal`、`generation_mode`、`kol_context`、`project_context` | RAG 检索与知识注入 | 多 Agent 任务编排、策略生成、约束验证 |

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 提供业务上下文 | 让生成贴合 KOL、项目、模板和行业 |
| 降低幻觉 | 重要事实来自可追溯资料 |
| 支撑合规 | 检索禁止表达和负样本 |
| 复用经验 | 读取历史成功和失败案例 |
| 支撑个性化 | 让 KOL 专属表达和模板默认值可复用 |

## 4. RAG 库拆分

| RAG 库 | 内容 | 用途 |
|---|---|---|
| KOL Knowledge | KOL 语气、粉丝、历史活动、偏好 | 个性化生成 |
| Project Knowledge | 项目信息、品牌、卖点、链接、条款 | 项目表达和题目生成 |
| Template Knowledge | 模板 schema、玩法结构、字段、可调项 | 模板推荐和生成承接 |
| Compliance Knowledge | 禁止表达、免责声明、平台规则 | 合规校验 |
| Case Knowledge | 成功案例、失败案例、行业玩法 | 策略参考 |
| Performance Knowledge | 历史数据、渠道效果、Agent 策略效果 | 推荐和复盘 |

## 5. 输入数据

| 输入 | 用途 |
|---|---|
| `kol_context` | 检索 KOL 历史和语气 |
| `project_context` | 检索项目事实和资产 |
| `campaign_goal` | 检索目标相关案例和模板 |
| `generation_mode` | 判断需要检索模板还是创意案例 |
| `template_id` | 检索模板 schema 和历史表现 |
| `risk_profile` | 检索合规规则和负样本 |

## 6. 关键 Agent

| Agent | 职责 |
|---|---|
| Retrieval Agent | 根据任务生成检索计划 |
| Context Composer | 合并、压缩和排序上下文 |
| Source Verifier | 检查来源可信度和版本 |
| Negative Example Retriever | 检索失败和违规案例 |
| Context Guard | 防止未审核内容进入生成 |

## 7. 检索策略

| 策略 | 用途 |
|---|---|
| 精确检索 | 项目名、模板 ID、KOL ID、活动 ID |
| 语义检索 | 相似案例、相似玩法、相似目标 |
| 规则检索 | 合规条款、禁止表达、风控规则 |
| 负样本检索 | 审核失败、投诉、低效案例 |
| 历史表现检索 | 模板、渠道、CTA、Agent 策略效果 |

## 8. 上下文注入方式

| 注入对象 | 注入内容 |
|---|---|
| Brief Agent | KOL、项目、目标、历史偏好 |
| Strategy Agent | 模板案例、目标策略、历史表现 |
| Generation Agent | 项目资料、KOL 语气、内容池 |
| Rule Agent | 模板规则、奖励规则、风控规则 |
| Constraint Agent | 合规规则、负样本、审核案例 |
| Diagnosis Agent | 历史指标、策略效果、模板表现 |

## 9. 数据对象结构

| 字段 | 说明 |
|---|---|
| `retrieval_id` | 检索 ID |
| `query_plan` | 检索计划 |
| `sources` | 来源列表 |
| `chunks` | 检索片段 |
| `source_type` | KOL、模板、合规、案例、表现 |
| `confidence` | 可信度 |
| `freshness` | 新鲜度 |
| `usage_scope` | 可用于生成、校验、复盘还是展示 |
| `blocked_sources` | 被阻止使用的来源 |

## 10. 约束边界

| 约束 | 说明 |
|---|---|
| 不注入未授权项目资料 | 防止泄露和误用 |
| 不把用户上传内容直接当事实 | 需要来源标记 |
| 不把过期规则用于合规判断 | 合规知识要版本化 |
| 不把低置信检索当强证据 | 诊断和生成要标注置信度 |
| 不让 RAG 替代约束系统 | RAG 提供知识，Constraint 负责裁决 |

## 11. MVP 范围

| P0 能力 | 说明 |
|---|---|
| KOL RAG | KOL 基础信息和历史活动 |
| Template RAG | 模板 schema 和示例配置 |
| Compliance RAG | 禁止表达、免责声明、奖励规则 |
| Negative Examples | 审核失败和高风险表达 |
| Source Trace | 每次检索记录来源 |

## 12. P1 / P2 扩展

| 阶段 | 能力 |
|---|---|
| P1 | Case RAG、Performance RAG、跨活动模板表现 |
| P2 | 实时市场数据、自动知识更新、知识置信度评估 |

## 13. 验收标准

| 验收项 | 标准 |
|---|---|
| 可检索 | Agent 能读取 KOL、模板、合规知识 |
| 可追溯 | 生成和校验能追踪来源 |
| 可过滤 | 未授权或高风险内容不会注入 |
| 可复用 | 成功案例和负样本能被下次使用 |
| 可评估 | 能判断 RAG 是否改善生成质量 |

## 14. 最终结论

RAG 是 Agent OS 的知识注入层。

它的价值不是“给模型塞资料”，而是让每次生成、校验和复盘都带有可追溯的业务上下文。
