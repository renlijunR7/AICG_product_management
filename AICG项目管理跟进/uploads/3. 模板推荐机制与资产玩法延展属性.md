# 模板推荐机制与资产玩法延展属性

## 1. 核心结论

Airvana 的模板推荐不应该只是“给用户选一个游戏类型”，而应该是一个由 `campaign_goal`、`kol_context`、项目资产、用户画像、玩法复杂度、合规风险和历史数据共同驱动的推荐系统。

模板要被拆成四层：

| 层级 | 说明 | 示例 |
|---|---|---|
| 营销适配层 | 这个模板适合解决什么营销目标 | 拉新、教育、社群增长、转化、裂变、留存 |
| 核心玩法层 | 用户实际玩什么 | 竞猜、塔防、射击、跑酷、画线、模拟经营、空投任务 |
| 资产承载层 | 这个模板需要哪些项目/KOL/视觉资产 | 项目 Logo、KOL 头像、Token 图标、角色、地图、奖励图 |
| 玩法延展层 | 这个模板可以被扩展成哪些任务、关卡、奖励和 Agentic 策略 | 难度、关卡、道具、排行榜、任务链、动态 CTA |

一句话：**模板推荐 = 选择最适合当前营销目标和资产条件的可扩展玩法容器。**

## 2. 模板推荐的输入

| 输入对象 | 关键字段 | 对推荐的影响 |
|---|---|---|
| `campaign_goal` | 主目标、次目标、CTA、核心指标 | 决定优先推荐哪类玩法 |
| `kol_context` | KOL 类型、粉丝画像、内容风格、历史表现 | 决定模板是否适合该 KOL 传播 |
| `project_context` | 项目类型、行业、产品卖点、合规边界 | 决定玩法表达方式和风险 |
| `asset_inventory` | 可用 Logo、角色、图标、视频、题库、地图、奖励图 | 决定模板能否快速生成 |
| `template_schema` | 模板字段、锁定字段、可编辑字段、Agentic 字段 | 决定生成稳定性 |
| `performance_history` | 历史点击、开始、完成、分享、CTA、转化 | 决定推荐排序 |
| `risk_profile` | 金融、奖励、刷量、品牌和合规风险 | 决定是否限制模板或 CTA |
| `channel_context` | X、TikTok、Telegram、Discord、广告投放等 | 决定时长、节奏和分享形式 |

## 3. 推荐维度

每个模板都应该被打上可计算的推荐维度。

| 维度 | 说明 |
|---|---|
| 目标适配度 | 是否适合当前 campaign 目标 |
| 粉丝适配度 | KOL 粉丝是否容易理解和参与 |
| 资产准备度 | 当前项目资产是否足够生成该模板 |
| 制作成本 | 生成和调试成本高不高 |
| 完玩概率 | 用户是否容易完成 |
| 分享潜力 | 是否天然适合晒结果、邀请、排行榜 |
| 转化承接力 | 是否适合自然插入 CTA |
| Agentic 潜力 | 是否有足够多可动态调整的策略点 |
| 合规风险 | 是否容易出现收益承诺、奖励误导或刷量 |
| 历史表现 | 同类 KOL、同类项目、同类目标下是否表现好 |

推荐排序不应该只看“玩法好不好玩”，而应该看“在这个营销目标下，这个玩法能不能带来可解释、可优化、可复用的数据结果”。

## 4. 模板总览

| 模板 | 核心玩法 | 最适合目标 | 资产要求 | 玩法延展能力 | MVP 优先级 |
|---|---|---|---|---|---|
| 竞猜 / 预测 | 用户对行情、项目、知识题做判断 | 教育、拉新、转化 | 题库、项目信息、币种图标、结果文案 | 高 | P0 |
| 空投任务 | 用户完成任务获得资格或积分 | 社群增长、转化、裂变 | 任务清单、奖励图、社群链接、钱包规则 | 高 | P0 |
| 画线 / 路径规划 | 用户画路径、连线、引导角色完成目标 | 教育、轻互动、分享 | 地图、目标点、障碍物、角色/物品 | 中高 | P1 |
| 跑酷 | 用户躲避障碍、收集资产、到达终点 | 拉新、裂变、品牌曝光 | 角色、赛道、障碍、收集物、结果卡 | 高 | P1 |
| 塔防 | 用户布置防御，抵御攻击或保护资产 | 教育、留存、项目叙事 | 地图、敌人、塔、技能、资源图标 | 很高 | P1 |
| 射击 | 用户射击目标、收集奖励、清除风险 | 拉新、娱乐传播、风险教育 | 角色、武器、目标、特效、奖励 | 高 | P1 |
| 模拟经营 | 用户经营项目、升级资产、完成增长目标 | 教育、留存、深度转化 | 建筑、资源、角色、经济系统、任务 | 很高 | P2 |
| 盲盒 / 抽奖 | 用户开盒、抽奖、收集权益 | 激活、转化、裂变 | 奖励图、稀有度、权益说明、规则 | 中 | P0/P1 |
| 排行榜挑战 | 用户竞争分数或完成度 | 裂变、社群、留存 | 榜单、头像、积分、分享图 | 中高 | P1 |
| 任务闯关 | 用户逐步完成任务链 | 教育、转化、社群增长 | 任务、奖励、进度、结果反馈 | 高 | P0 |

## 5. 模板一：竞猜 / 预测

### 5.1 适配场景

| 适配项 | 说明 |
|---|---|
| 适合目标 | 项目教育、拉新激活、转化领取、社群讨论 |
| 适合 KOL | Web3 教育型、交易观点型、项目解读型、行情评论型 |
| 适合渠道 | X、Telegram、Discord、直播间、项目社区 |
| 用户心理 | 用户愿意判断、下注式参与、看结果、分享观点 |

### 5.2 资产需求

| 资产 | 是否必需 | 用途 |
|---|---:|---|
| 项目 Logo | 必需 | 首屏和结果页识别 |
| 币种 / 项目图标 | 必需 | 竞猜对象 |
| 题库 / 判断题 | 必需 | 核心玩法 |
| 行情或事件素材 | 建议 | 增强真实感 |
| KOL 头像和语气 | 建议 | 建立信任 |
| 结果反馈文案 | 必需 | 解释用户选择 |
| 分享卡 | 必需 | 带动传播 |

### 5.3 玩法延展属性

| 延展点 | 说明 |
|---|---|
| 单题竞猜 | 适合冷启动和低门槛传播 |
| 多题闯关 | 适合用户教育和完赛数据 |
| 限时预测 | 适合活动感和实时话题 |
| KOL 专属观点 | KOL 先给观点，用户选择是否认同 |
| 结果分型 | 把用户分成新手、高手、风险偏好型等 |
| 排行榜 | 适合社群竞争 |
| 分享结果卡 | 适合裂变 |

### 5.4 Agentic 可调项

| 可调项 | 调整逻辑 |
|---|---|
| 题目难度 | 新手降低难度，老用户提高难度 |
| 提示强度 | 流失风险高时增加提示 |
| 结果反馈 | 根据用户选择给不同解释 |
| CTA 时机 | 用户连续答对或完成后触发 |
| 奖励节奏 | 首题完成给小奖励，多题完成给资格 |

## 6. 模板二：空投任务

### 6.1 适配场景

| 适配项 | 说明 |
|---|---|
| 适合目标 | 社群增长、转化领取、裂变传播、拉新激活 |
| 适合 KOL | Web3 项目型、社区型、福利型、活动型 KOL |
| 适合渠道 | Telegram、Discord、X、项目官网、钱包入口 |
| 用户心理 | 用户愿意完成任务换资格、积分、白名单或抽奖机会 |

### 6.2 资产需求

| 资产 | 是否必需 | 用途 |
|---|---:|---|
| 活动规则 | 必需 | 明确任务和资格 |
| 奖励图 / 权益说明 | 必需 | 激励参与 |
| 社群链接 | 必需 | 目标承接 |
| KOL 专属邀请码 | 建议 | 归因和裂变 |
| 钱包连接规则 | 可选 | Web3 任务和反作弊 |
| 项目 Logo / Token 图标 | 必需 | 品牌识别 |
| 分享卡 | 必需 | 传播 |

### 6.3 玩法延展属性

| 延展点 | 说明 |
|---|---|
| 单任务领取 | 低门槛快速转化 |
| 多任务链 | 关注、入群、答题、分享、钱包验证 |
| 积分系统 | 为后续留存和排行榜做准备 |
| 白名单资格 | 适合项目活动 |
| 邀请加成 | 适合裂变 |
| 反作弊校验 | 必须和奖励强度匹配 |

### 6.4 Agentic 可调项

| 可调项 | 调整逻辑 |
|---|---|
| 任务顺序 | 先做低门槛任务，再引导高价值动作 |
| 奖励提示 | 根据完成进度调整激励文案 |
| 风控强度 | 异常流量高时增加验证 |
| CTA 位置 | 在完成关键任务后触发 |
| 分享机制 | 高意愿用户强化邀请任务 |

## 7. 模板三：塔防

### 7.1 适配场景

| 适配项 | 说明 |
|---|---|
| 适合目标 | 项目教育、品牌叙事、留存、社群竞争 |
| 适合 KOL | 游戏型、项目解读型、生态讲解型、社区型 KOL |
| 适合渠道 | 社群、Web 页面、游戏社区、直播演示 |
| 用户心理 | 用户通过防守、升级和策略选择理解项目价值 |

塔防适合把抽象卖点做成“保护资产 / 抵御风险 / 建设生态”的可视化体验。

### 7.2 资产需求

| 资产 | 是否必需 | 用途 |
|---|---:|---|
| 地图 / 路径 | 必需 | 核心战场 |
| 防御塔 / 技能图标 | 必需 | 用户选择 |
| 敌人 / 风险对象 | 必需 | 表达攻击或挑战 |
| 资源图标 | 必需 | 升级和消耗 |
| 项目资产图标 | 建议 | 生态叙事 |
| KOL 角色或指挥官 | 可选 | KOL 专属感 |
| 胜利 / 失败反馈 | 必需 | 结果解释 |

### 7.3 玩法延展属性

| 延展点 | 说明 |
|---|---|
| 波次系统 | 逐步提高挑战 |
| 塔升级 | 表达项目能力升级 |
| 技能释放 | 增加操作感 |
| Boss 关 | 适合表达重大风险或关键事件 |
| 多路线地图 | 增强策略深度 |
| 防守评分 | 适合排行榜和分享 |

### 7.4 Agentic 可调项

| 可调项 | 调整逻辑 |
|---|---|
| 波次难度 | 根据玩家表现动态调整 |
| 敌人类型 | 根据教育目标展示不同风险 |
| 升级推荐 | 新手给建议，高级玩家放开策略 |
| 失败补救 | 连续失败时降低难度或给提示 |
| CTA 时机 | 胜利、升级完成或 Boss 后触发 |

| 用户心理 | 快速开始、即时反馈、击中目标、获得奖励 |

### 8.2 资产需求

| 资产 | 是否必需 | 用途 |

| 目标物 | 必需 | 射击对象 |

## 10. 模板六：画线 / 路径规划

## 11. 模板七：模拟经营

### 11.1 适配场景

| 适配项 | 说明 |
|---|---|
| 适合目标 | 深度教育、留存、长期转化、项目生态解释 |
| 适合 KOL | 项目解读型、策略型、GameFi、社区运营型 KOL |
| 适合渠道 | Web 页面、社群活动、系列化 campaign |
| 用户心理 | 用户通过建设、升级、经营理解项目系统 |

模拟经营适合表达“项目生态如何增长”“资源如何流转”“用户如何参与建设”，但制作成本和规则复杂度较高，不适合 MVP 第一个模板。

### 11.2 资产需求

| 资产 | 是否必需 | 用途 |
|---|---:|---|
| 建筑 / 模块 | 必需 | 经营对象 |
| 资源图标 | 必需 | 经济系统 |
| 角色 / 用户群 | 建议 | 生态代入 |
| 升级路径 | 必需 | 成长感 |
| 任务系统 | 必需 | 引导用户 |
| 事件卡 | 可选 | 增强变化 |
| 数据结果页 | 必需 | 展示经营成果 |

### 11.3 玩法延展属性

| 延展点 | 说明 |
|---|---|
| 资源生产 | 表达项目增长 |
| 建筑升级 | 表达能力升级 |
| 用户增长 | 表达社群增长 |
| 事件系统 | 模拟市场或社区变化 |
| 多目标经营 | 增加策略深度 |
| 长线任务 | 适合留存 |

### 11.4 Agentic 可调项

| 可调项 | 调整逻辑 |
|---|---|
| 任务推荐 | 根据用户当前状态推荐下一步 |
| 资源产出 | 控制节奏和难度 |
| 事件触发 | 根据目标引导用户体验项目卖点 |
| 新手引导 | 降低理解成本 |
| 复访激励 | 引导用户回来继续经营 |

## 12. 模板推荐规则

### 12.1 按营销目标推荐

| 主目标 | 优先推荐模板 | 不优先推荐 |
|---|---|---|
| 项目认知 | 竞猜、答题、画线、模拟经营 | 纯抽奖、强转化模板 |
| 用户教育 | 竞猜、画线、模拟经营、塔防 | 过快的射击、盲盒 |
| 拉新激活 | 跑酷、射击、竞猜、盲盒 | 复杂模拟经营 |
| 社群增长 | 空投任务、排行榜、任务闯关、竞猜 | 单机弱分享模板 |
| 转化领取 | 空投任务、盲盒、任务闯关、竞猜 | 复杂长流程玩法 |
| 裂变传播 | 跑酷、排行榜、射击、分享卡竞猜 | 低分享结果模板 |
| 留存复活 | 塔防、模拟经营、连续任务、排行榜 | 一次性抽奖模板 |

### 12.2 按资产准备度推荐

| 资产状态 | 推荐模板 |

| 有 Token 图标、项目素材、题库 | 竞猜、答题、画线、空投任务 |
| 有角色、场景、动画素材 | 跑酷、射击、塔防 |
| 有完整世界观和生态叙事 | 塔防、模拟经营 |
| 有社群链接和奖励规则 | 空投任务、排行榜、邀请挑战 |
| 有地图、路线、流程图资产 | 画线、路径规划、跑酷 |

### 12.3 按 KOL 类型推荐

| Web3 教育型 KOL | 竞猜、答题、画线、模拟经营 |
| 行情观点型 KOL | 竞猜、预测、排行榜挑战 |
| 游戏娱乐型 KOL | 跑酷、射击、塔防 |
| 社区运营型 KOL | 空投任务、排行榜、任务闯关 |
| 福利活动型 KOL | 空投、盲盒、抽奖、邀请挑战 |

## 13. 模板 schema 需要记录的属性

每个模板进入平台库时，至少要记录以下属性。

| 属性组 | 字段 |
|---|---|
| 基础信息 | 模板名称、模板类型、版本、适用行业、适用渠道 |
| 营销属性 | 适合目标、核心 CTA、核心指标、转化路径 |
| 玩法属性 | 核心操作、平均时长、难度范围、失败机制、胜利机制 |
| 资产属性 | 必需资产、可选资产、资产尺寸、替换规则、缺失降级方案 |
| 可编辑属性 | KOL 可改字段、项目方可锁字段、运营可覆盖字段 |
| Agentic 属性 | 可动态调整字段、触发条件、策略边界 |
| 数据属性 | 必需埋点、核心漏斗、结果事件、Agent 决策事件 |
| 风险属性 | 合规风险、刷量风险、奖励风险、品牌风险 |
| 复用属性 | 适合复投场景、可系列化程度、模板记忆字段 |

## 14. 资产属性设计

资产不要只按“图片/视频/音频”分类，而要按模板生成用途分类。

| 资产类型 | 示例 | 用途 |
|---|---|---|
| 品牌资产 | Logo、主色、项目名、Slogan | 品牌识别 |
| KOL 资产 | 头像、昵称、语气、签名、口头禅 | 专属感和信任 |
| 玩法资产 | 角色、敌人、塔、武器、赛道、地图、障碍物 | 构成游戏体验 |
| 经济资产 | Token 图标、积分、奖励、徽章、资格卡 | 激励和结果反馈 |
| 内容资产 | 题库、知识点、项目卖点、风险提示 | 教育和表达 |
| 社交资产 | 分享卡、邀请语、排行榜头像、社群入口 | 裂变和社群增长 |
| 合规资产 | 免责声明、奖励规则、活动条款、风险提示 | 上线约束 |

资产准备度会直接影响推荐：

| 准备度 | 推荐策略 |
|---|---|
| 低 | 推荐竞猜、空投任务、盲盒这类轻资产模板 |
| 中 | 推荐画线、跑酷、射击这类可替换素材模板 |
| 高 | 推荐塔防、模拟经营这类资产消耗更高但表现力强的模板 |

## 15. 玩法延伸属性设计

玩法延伸属性用于判断一个模板是否能从“一次性素材”升级为“可运营系统”。

| 延伸属性 | 说明 |
|---|---|
| 关卡延伸 | 是否能扩展多关、多波次、多任务 |
| 难度延伸 | 是否能动态调整难度 |
| 奖励延伸 | 是否能做积分、徽章、资格、抽奖、排行榜 |
| 社交延伸 | 是否能邀请、分享、组队、PK、排行榜 |
| 教育延伸 | 是否能承载知识点、解释、反馈 |
| 经济延伸 | 是否能表达资源、收益、成本、升级，但不能做收益承诺 |
| 叙事延伸 | 是否能表达项目世界观、生态、风险和使命 |
| Agentic 延伸 | 是否有可动态调整的策略点 |
| 数据延伸 | 是否能产生清晰漏斗和决策事件 |

## 16. 推荐输出形式

平台不应该只推荐一个模板，而应该推荐一个“主推荐 + 备选 + 推荐理由”的组合。

| 输出 | 内容 |
|---|---|
| 主推荐模板 | 当前最适合的模板 |
| 推荐理由 | 为什么适合该目标、KOL、资产和渠道 |
| 生成预期 | 用户会玩什么、完成什么、看到什么 CTA |
| 所需资产 | 已有资产、缺失资产、可自动生成资产 |
| 风险提示 | 是否涉及奖励、金融、刷量或合规 |
| 备选模板 | 低成本备选、强表现备选、强转化备选 |

示例：

| 字段 | 内容 |
|---|---|
| 主推荐 | 空投任务链 |
| 推荐理由 | 当前目标是社群增长，且已具备社群链接、奖励规则和 KOL 分享入口 |
| 备选 1 | 单题竞猜 |
| 备选理由 | 更轻量，适合快速验证首屏和分享率 |
| 备选 2 | 跑酷收集 |
| 备选理由 | 更适合短视频传播，但需要角色和赛道资产 |

## 17. MVP 实施建议

### 17.1 P0 先做

| 模块 | 要求 |
|---|---|
| 模板库基础分类 | 竞猜、空投任务、盲盒、任务闯关 |
| 模板 schema | 每个模板定义必需字段、可编辑字段、锁定字段 |
| 资产准备度判断 | 判断当前资产是否能生成该模板 |
| 目标适配推荐 | 根据 `campaign_goal` 推荐模板 |
| 推荐理由展示 | 告诉 KOL 为什么推荐这个模板 |
| 缺失资产提示 | 告诉用户还需要补什么 |
| 基础埋点要求 | 每个模板必须有开始、完成、CTA、分享、流失事件 |

### 17.2 P1 再做

| 模块 | 要求 |
|---|---|
| 塔防 / 跑酷 / 射击 / 画线模板 | 加入强互动和强传播玩法 |
| KOL 历史偏好推荐 | 根据 KOL 常用模板和历史效果排序 |
| 渠道适配推荐 | 根据 X、Telegram、TikTok 等渠道调整模板 |
| Agentic 可调项 | 难度、奖励、CTA、提示、任务顺序 |
| 模板效果看板 | 比较不同模板在不同目标下的表现 |

### 17.3 P2 平台化后做

| 模块 | 要求 |
|---|---|
| 模拟经营模板 | 支撑深度教育和长期留存 |
| 自动资产生成 | 根据模板自动生成角色、地图、敌人、分享卡 |
| 模板组合 | 竞猜 + 空投、跑酷 + 排行榜、塔防 + 社群任务 |
| 复盘反推模板 | Diagnosis Agent 判断下一次换模板还是改玩法 |
| 行业模板库 | Web3、GameFi、交易所、钱包、NFT 等垂直模板 |

## 18. 推荐决策流程

推荐流程建议如下：

1. 读取 `campaign_goal`，确定主目标和 CTA。
2. 读取 `kol_context`，判断 KOL 类型、粉丝画像和历史表现。
3. 读取 `asset_inventory`，判断现有资产能支持哪些模板。
4. 读取 `template_schema`，过滤不适配目标、资产或合规要求的模板。
5. 对候选模板打分：目标适配、资产准备、粉丝适配、制作成本、Agentic 潜力、历史表现。
6. 输出主推荐模板和 2 个备选模板。
7. 展示推荐理由、缺失资产和预计生成效果。
8. KOL 确认模板或切换备选。
9. Builder 根据模板 schema 生成首版 Playable。
10. 发布后根据真实数据更新模板推荐权重。

## 19. 不建议的做法

| 不建议事项 | 原因 |
|---|---|
| 只按游戏类型推荐 | 忽略营销目标、资产条件和 KOL 受众 |
| 一开始上线所有复杂模板 | 塔防和模拟经营制作成本高，容易拖慢 MVP |
| 没有资产准备度判断 | 用户选择模板后生成不出来或质量很差 |
| 把视觉皮肤当模板核心 | 核心应该是玩法结构和营销路径 |
| 不记录 Agentic 可调项 | 后续无法运行时优化 |
| 不记录模板表现数据 | 下一次推荐无法变聪明 |
| 高奖励模板没有风控 | 空投、抽奖、排行榜容易被刷 |

## 20. 结论

模板推荐应该从“游戏类型选择器”升级为“营销目标驱动的玩法推荐系统”。

MVP 阶段建议：

1. P0 先做竞猜、空投任务、盲盒、任务闯关。
2. P1 再加入塔防、射击、跑酷、画线。
3. P2 再做模拟经营和复杂模板组合。
4. 每个模板必须记录资产需求、玩法延展、Agentic 可调项和数据埋点。
5. 推荐结果必须解释为什么适合当前 KOL、目标、资产和渠道。

这样 Airvana 的模板库才不是简单素材市场，而是能持续生成、运营、复盘和迭代的 Agentic Playable 玩法系统。
