# 案例 · Hamster Kombat 型 Tap-to-Earn 模板推演

## 1. 参考对象与核心逻辑

参考 Hamster Kombat（Telegram 现象级 Tap-to-Earn 游戏）：

| 要素 | Hamster Kombat 的做法 |
|---|---|
| 核心操作 | 点击屏幕（仓鼠 CEO）赚游戏金币 |
| 成长线 | 金币升级"交易所业务卡"，提升每小时被动产出 |
| 价值承接 | 游戏金币按规则映射链上代币 **HMSTR**，在 **Gate、OKX 等交易所**上市交易 |
| 增长引擎 | Telegram 原生裂变：邀请返利 + 每日任务 + 社群 Combo 口令 |
| 留存机制 | 能量条限制单次点击量，逼出"每天回来点几次"的习惯 |

一句话核心逻辑：**点击 → 赚金币 → 金币映射链上代币 → 交易所交易**——玩的动作直接通向"注册交易所 + 入金交易"，天然贴合平台"玩 → 注册 → 入金"的统一漏斗。

## 2. 模板化拆解（进入平台模板库）

把它抽象为 **Tap-to-Earn 模板** 的 `template_schema`：

| 字段层 | 内容 |
|---|---|
| 可编辑字段（KOL） | 点击对象形象、主题皮肤、文案语气、每日任务清单、分享卡、KOL 专属加成卡 |
| 锁定字段（品牌方） | 金币 → 代币映射比例、代币总池、合规文案、上所信息（Gate / OKX 入口）、埋点 |
| Agentic 字段 | 点击收益曲线、能量恢复速度、任务顺序、Combo 口令节奏、CTA 触发时机 |
| 必需资产 | 点击主体形象（角色 / 吉祥物）、升级卡图标、代币图标、结果分享卡 |
| 核心埋点 | 点击、升级、任务完成、邀请、注册、入金 / 交易 |

## 3. 版本延伸（同一模板 × 不同主题皮肤）

用「整体替换素材包」机制，一套玩法延伸多个版本——素材包 + 叙事换，数值引擎与结算逻辑不动：

| 版本 | 点击对象 | 成长线叙事 | 适配场景 |
|---|---|---|---|
| 原版 · 交易所大亨 | 点击吉祥物赚金币 | 升级交易所业务卡 | 交易所品牌方（Gate / OKX 联名） |
| **太空版本** | 点击发射火箭 / 采集星尘 | 升级飞船、空间站、殖民地 | 新公链"探索宇宙"叙事、Meme 币社区 |
| 矿工版本 | 点击挖矿出块 | 升级矿机、矿场、算力 | PoW 项目、算力概念品牌 |
| 厨房版本 | 点击煎饼出餐 | 升级餐车、连锁店 | 泛娱乐 / 拉美东南亚下沉市场 |
| 公会战版本 | 点击为公会累计战力 | 公会排行、赛季奖励 | Discord 社区、中东公会型 KOL |

KOL 二次创作仍走三类操作：整体替换（换版本皮肤）、单元素修改（收益数值 / 任务）、个人元素注入（KOL 形象做点击对象、专属加成卡、口头禅播报）。

## 4. 营销与价值闭环

```
点击赚金币 → 每日任务 / 邀请裂变（TG 原生）→ 金币映射 HMSTR 型代币（结算环节统一执行）
     → 注册交易所（Gate / OKX 入口内嵌）→ 入金 / 交易 → 品牌方核销 → 平台统一结算
```

| 环节 | 与平台机制的对齐 |
|---|---|
| 金币 → 代币映射 | 属于奖励通证化配置：比例品牌方锁定，结算日统一执行，活动期只展示预估价值 |
| 注册 / 入金承接 | 结果页与升级页内嵌交易所注册入口；"提现 HMSTR 需交易所账户"即注册动机 |
| 玩家提现 | 遵循统一结算：积分（金币）→ 可提现余额 / 代币 → 满门槛发起提现申请 → 分档审核 |
| KOL 结算 | 归因到 KOL 房间码的注册 CPA + 入金 CPS，T+7 对账 |

## 5. Agentic 运营点

| 智能体 / 触发器 | 行为 | 目的 |
|---|---|---|
| 收益曲线调节 | 按玩家活跃度动态调整点击收益与能量恢复 | 新手爽、老手有追求，控制通胀 |
| 每日任务编排 | 按转化目标排任务顺序（先关注 → 后注册 → 再入金） | 漏斗逐层推进 |
| Combo 口令播报 | 按 KOL 发布节奏投放每日口令，NPC 语气播报 | 拉回访 + 给 KOL 内容素材 |
| 防点击机器人 | 点击频率 / 设备指纹异常 → 降收益、冻结映射资格 | 代币池与核销资金安全 |
| 入金转化触发 | 已注册未入金玩家达阈值 → 推首充返赠提示（需品牌方确认） | 主目标"入金"专属抓手 |

## 6. 与塔防案例的差异

| 维度 | 塔防案例 | Tap-to-Earn 案例 |
|---|---|---|
| 玩法深度 | 策略局，靠内容变体差异化 | 极轻操作，靠经济系统与裂变差异化 |
| 时长与频次 | 单局 1–5 分钟，活动期集中 | 单次 30 秒，全天多次回访 |
| 核心风险 | 内容合规 | 代币映射合规 + 刷量 / 机器人 |
| 最强渠道 | 五平台各有打法 | Telegram 绝对主场（Bot 原生） |
| 入金动机 | 奖励 / 资格驱动 | **代币上所交易驱动（最直接）** |

## 7. 结论

1. Tap-to-Earn 是"玩 → 注册 → 入金"漏斗最短的模板：代币上所（Gate / OKX）本身就是入金动机。
2. 版本延伸（太空 / 矿工 / 厨房 / 公会战）用素材包整体替换即可实现，一套数值与结算引擎复用。
3. 风险重心从内容合规转向经济系统：代币映射比例锁定、防机器人、防通胀是 Constraint Agent 与风控的主战场。
4. 建议与塔防案例组成模板库的两极：塔防验证"内容深度型"，Tap-to-Earn 验证"经济裂变型"，两套推演覆盖大多数品牌方目标。
