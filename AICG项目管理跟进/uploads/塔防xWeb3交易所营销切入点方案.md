## 1. 方案背景与目标客户

### 1.1 背景

塔防是模板库中「内容深度型」的代表：玩家布置防御塔抵御波次进攻，塔位 / 敌人皮肤可整体替换为品牌元素，单局 60 秒至 5 分钟（按变体），支持难度递增与排行榜。案例 01 已验证同一塔防 `template_schema` × 不同 `kol_context` 可产出五套完全不同的素材与玩法。本方案回答的问题是：**面向 Web3 交易所品牌方，塔防模板具体从哪里切进对方的营销预算**。

### 1.2 目标客户

| 客户类型 | 代表对象 | 核心诉求 | 塔防的对位价值 |
|---|---|---|---|
| 头部 CEX | Gate（已签约）、OKX 等 | 注册拉新、入金转化、新链 / 新币活动预热 | 玩法承载品牌教育，末端收口注册 + 入金 |
| 上新驱动型 CEX | Gate Startup 打新类业务线 | 打新 / 上新话题的即时流量 | 教学局把「新币卖点」做成波次内容 |
| DEX / 链上协议 | 永续、聚合器类协议 | 钱包连接、交易任务、社区留存 | 公会 / 组队变体绑定链上任务 |

交易所自营先例已证明品类可行：OKX Racer 上线首月注册 1,000 万+，验证了「轻游戏 → 绑定账户 → 开户核销」的闭环。塔防的差异化在于内容深度——能承载观点、教育与社区叙事，而不只是即时刺激。

## 2. 为什么是塔防

玩法机制与金融概念存在天然映射，品牌植入不破坏游戏性：

| 塔防机制 | 金融概念映射 | 营销用法 |
|---|---|---|
| 守护金库（基地血量） | 守护仓位 / 资产安全 | 首屏叙事「Defend Your Bag」，品牌方=金库守护者 |
| 波次进攻的敌人 | FUD 谣言、插针、貔貅盘、市场黑天鹅 | 敌人命名即风险教育，波次剧情可挂 KOL 观点 |
| 选塔与布阵 | 选观点（做多 / 做空 / 观望）、资产配置 | 选塔即表态，结果卡输出「操盘风格分型」做转发钩子 |
| 波动防御（难度曲线） | 行情波动与风控 | 动态难度对应「行情突变」，教育风控意识 |
| 通关奖励 | 平台积分 → 结算后兑换 | 对接核销与统一结算，不承诺收益 |

三条结构性理由：

- 内容深度型玩法是交易所「品牌教育 + 高质量入金用户」的主要来源——案例 01 中教育型路线注册→入金转化 35%，为五路最高。
- 塔防的塔 / 敌人 / 背景 / NPC 全部是可替换素材位，品牌资产包（Logo / Token 图标 / 合规文案）整包替换、分钟级重建，一套引擎服务多个交易所客户。
- 玩法智能体（NPC 指挥官 / 讲师 / 主持人 / 客服）让活动从素材变成「有人运营的场子」，直接抬升完成率与回访。

## 3. 切入点设计

五个可落地切入点，均基于同一塔防 `template_schema`，靠变体与 `kol_context` 差异化。

### 3.1 切入点一 · 行情观点快局「抵御 FUD」

| 要素 | 设计 |
|---|---|
| 玩法映射 | 3 波 90 秒快局；敌人=FUD 谣言 / 插针 / 貔貅盘；塔=做多 / 做空 / 观望三种观点塔，选塔即表态 |
| 品牌植入位 | 金库=交易所资产保护叙事；结果卡挂品牌 Logo 与注册入口 |
| 转化钩子 | 结果卡「操盘风格分型」做转发钩子；「解锁完整操盘报告→注册」 |
| KOL 角色 | 行情观点型 KOL（X 主场），观点做成波次剧情，热点行情即时蹭量 |

### 3.2 切入点二 · 新币上线教学局「玩完=学完」

| 要素 | 设计 |
|---|---|
| 玩法映射 | 5 波教学局，每波绑定一个知识点（共识机制 / Gas / 桥 / 钱包安全 / 生态），通关解锁知识卡 |
| 品牌植入位 | 知识卡内容=新币 / 新链卖点；结果页「你的链上知识等级」带品牌背书 |
| 转化钩子 | 教育完成即引导注册；学习奖励结算后兑换；首充引导走合规模板 |
| KOL 角色 | 教育解读型 KOL（TG 主场），知识卡成为群内讨论素材；配合 Startup 打新 / 上新节奏投放 |

### 3.3 切入点三 · 空投预热组队任务链

| 要素 | 设计 |
|---|---|
| 玩法映射 | 组队塔防 + 4 步任务链（试玩→入群→邀请→组队通关），玩法即任务载体 |
| 品牌植入位 | 任务奖励=平台积分 + 空投白名单资格；排行榜播报带品牌露出 |
| 转化钩子 | 组队奖励需注册领取；积分兑换绑定入金账户；与空投模板（tp2）联动做上所预热 |
| KOL 角色 | 社区福利型 KOL / 社群主（TG 主场）；刷量风险偏高，风控等级自动上调 |

### 3.4 切入点四 · 交易大赛限时冲分

| 要素 | 设计 |
|---|---|
| 玩法映射 | 60 秒单波高密度冲分 + 连击加分 + 成绩卡，节奏对标交易大赛 |
| 品牌植入位 | 成绩卡=品牌方交易大赛视觉；挑战话题标签统一聚合 |
| 转化钩子 | 晒分裂变做入口，抽奖资格需注册；中奖发放走入金账户完成首充破冰 |
| KOL 角色 | 娱乐短内容型 KOL（Reels / 短视频主场），成绩卡天然适配剪辑传播 |

### 3.5 切入点五 · 公会金库保卫战

| 要素 | 设计 |
|---|---|
| 玩法映射 | 公会协作 Boss 波（Boss=市场黑天鹅），全服共享血条 + 个人贡献榜 |
| 品牌植入位 | 公会补给=品牌权益包；每日战报模板带品牌方活动信息 |
| 转化钩子 | 注册=领公会补给资格，入金=补给升级——转化动作嵌进公会叙事，阻力最小 |
| KOL 角色 | 游戏公会型 KOL（Discord 主场），晚间黄金档开打，次日回访为各切入点最高 |

### 3.6 切入点选择建议

| 品牌方主目标 | 首选切入点 | 次选 |
|---|---|---|
| 注册数量（拉新冲量） | 四 · 限时冲分 | 三 · 组队任务链 |
| 入金质量（高价值用户） | 二 · 教学局 | 五 · 公会保卫战 |
| 新币 / 新链预热 | 二 · 教学局 + 三 · 任务链联动 | 一 · 观点快局 |
| 社区留存与回访 | 五 · 公会保卫战 | 三 · 组队任务链 |
| 热点行情即时流量 | 一 · 观点快局 | 四 · 限时冲分 |

## 4. 漏斗设计（玩 → 注册 → 入金）

各切入点入口不同，末端统一收口到「玩 → 注册 → 入金」，逐层归因：

| 漏斗层 | 转化机制 | 归因事件 | 保底手段（Agent 触发器） |
|---|---|---|---|
| 曝光 → 玩 | KOL 内容挂试玩入口（卡片 / Bot / 频道活动） | 开始事件 | 上线 1h 开始率 < 25% 自动切首屏文案变体 |
| 玩 → 完成 | 玩法智能体（NPC / 动态难度）托住完成率 | 完成事件 | 某波流失偏高自动调难度或提前弹提示 |
| 完成 → 注册 | 结果卡 / 奖励领取 / 补给资格绑定注册动作 | 注册归因 | 活动过半注册进度 < 50%，建议阶梯保底（需品牌方确认） |
| 注册 → 入金 | 积分兑换绑定入金账户、补给升级、首充返赠（合规模板） | 入金核销回传 | 注册→入金 < 15%（48h）推首充返赠提示（需品牌方确认） |

漏斗设计的两条铁律：

- 每个媒体渠道独立闭环——各自链接、归因、运营、看板，互不引流，保证多 KOL 对比与分成结算干净。
- 注册与入金激励一律带反套利风控：入金金额异常集中触发反洗钱校验并暂缓返赠发放。

## 5. 积分与激励边界

与工作台既有结算原则完全一致，本方案不新设任何激励通道：

| 边界 | 内容 |
|---|---|
| 活动期激励 | 只发**平台积分**（+ 白名单资格），余额实时可见但不可提；不做实时发币 |
| 兑换时点 | 周期结算日，平台按**已验证的营销结果**（扣除刷量与无效转化）统一结算两端 |
| 结算前置 | 反作弊终审通过 + 品牌方核销确认，资金才从品牌方预算池划出 |
| 玩家提现 | 可提现余额满 $10 发起提现申请；小额自动审核，大额 KYC；T+3 到账 |
| KOL 分成 | 注册 CPA + 入金 CPS 混合计酬，核销后 T+7，附对账单，72h 争议期 |
| 收益表述 | 任何文案不承诺收益；首充返赠类入金激励文案需合规审校 |
| Token 映射 | 若品牌方开启奖励通证化：比例由品牌方锁定、结算日统一执行，KOL 只能开 / 关与选展示位 |

## 6. 风险与合规要点

| 风险 | 说明 | 处置 |
|---|---|---|
| 激励定性风险 | 代币 / 积分激励在美国（SEC 证券认定）、欧盟（MiCA）、中国大陆（全面禁止）定性各异 | 合规文案为品牌方锁定字段；Constraint Agent 全量扫描收益表述 |
| 裂变合法性 | 裂变与抽奖玩法在部分地区构成非法促销或博彩 | 地区屏蔽名单由品牌方法务确认后锁定 |
| KYC / AML | 结算涉加密货币的 KYC / AML 义务 | 大额提现强制 KYC；异常入金触发反洗钱校验 |
| 刷量与拆单 | 任务链与冲分玩法吸引脚本刷量；提现环节拆单套利 | 设备指纹 / 行为风控前置；高频小额提现自动合并审核 |
| 品牌资产滥用 | KOL 二次编辑触碰 Logo 规范 / 合规文案 | 锁定字段编辑器置灰；替换自动校验，违规回退 |
| 本地化风险 | 多语言 / RTL 排版错误影响品牌形象 | 语言包切换自动处理 RTL，译文走合规验证 |

## 7. 落地排期建议

以品牌方签约后为 T0，按周推进：

| 阶段 | 周期 | 关键交付 | 责任侧 |
|---|---|---|---|
| W1 · 需求对齐 | 1 周 | 品牌方目标与边界签署（预算池 / 奖励池 / 合规红线 / 锁定字段清单）；选定 1-2 个切入点 | 平台 × 品牌方 |
| W2 · 变体配置 | 1 周 | 塔防变体配置 + 品牌资产包接入 + 合规文案审校定稿 | 平台产品侧 |
| W3 · KOL 匹配 | 1 周 | 按切入点画像匹配 KOL、授权接入生成 `kol_context`、首版生成与模拟测试 | 平台运营侧 |
| W4 · 灰度上线 | 1 周 | 单渠道灰度（建议先 TG）：验证归因链路、核销回传、风控触发器 | 平台 × 品牌方 |
| W5-W6 · 全量投放 | 2 周 | 多渠道全量 + Agent 动态运营；周中数据同步，超边界动作走品牌方确认 | 平台运营侧 |
| W7 · 结算复盘 | 1 周 | 周期结算（归因 + 风控终审 + 核销确认）；复盘报告与模板权重 / KOL memory 沉淀 | 平台 × 品牌方 |

排期原则：灰度先行验证「归因 → 核销 → 结算」全链路，再放全量——结算链路没跑通之前不扩渠道。
