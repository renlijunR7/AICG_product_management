# 约束、合规与质量验证机制结构化梳理

## 1. 核心定义

约束、合规与质量验证机制，是 Airvana Agent OS 的安全阀和质量闸口。

它负责检查 AI 生成的内容、规则、策略和配置，是否可发布、可玩、可追踪、可运营、可审计。

核心产物：

| 产物 | 说明 |
|---|---|
| `validation_report` | 校验报告 |
| `repair_suggestion` | 修复建议 |
| `risk_flags` | 风险标记 |
| `approval_required_items` | 需要人工审核的项目 |
| `audit_log` | 审计日志 |

## 2. 所处位置

| 上游 | 当前环节 | 下游 |
|---|---|---|
| `content_assets`、`game_rules`、`agent_policy` | 约束、合规与质量验证 | H5 Builder 构建 |

没有通过验证的内容不能进入 Builder 和发布。

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 控制合规风险 | 防止收益承诺、投资建议、虚假奖励 |
| 控制玩法风险 | 防止规则不可执行、状态机错误 |
| 控制品牌风险 | 防止项目表达错误 |
| 控制数据风险 | 防止埋点缺失、归因缺失 |
| 控制 Agent 风险 | 防止 Runtime 策略越界 |
| 支持自动修复 | 给出结构化修复建议 |

## 4. 输入数据

| 输入 | 校验重点 |
|---|---|
| `content_assets` | 文案、视觉、分享、CTA、免责声明 |
| `game_rules` | 状态机、完成条件、奖励规则 |
| `agent_policy` | 动态难度、提示、奖励、CTA、风控 |
| `template_config` | 关键变量、目标、渠道、奖励 |
| `tracking_requirements` | 事件和归因 |
| `retrieval_context` | 来源和事实依据 |

## 5. 关键 Agent / 服务

| 模块 | 职责 |
|---|---|
| Constraint Agent | 综合校验和报告生成 |
| Schema Validator | 检查结构是否符合 schema |
| Rule Validator | 检查游戏规则可执行 |
| Compliance Validator | 检查合规表达 |
| Brand Validator | 检查项目和品牌表达 |
| Tracking Validator | 检查埋点和归因 |
| Risk Validator | 检查风控和奖励风险 |
| Critic Agent | 评估潜在问题 |
| Repair Agent | 生成修复建议 |

## 6. 约束库结构

| 约束库 | 内容 |
|---|---|
| Constraint Registry | 所有产品规则 |
| Prompt Template Registry | 生成 Prompt 约束 |
| Compliance Rules | 合规条款和禁止表达 |
| Brand Rules | 品牌、项目、链接、声明 |
| Game Rule Constraints | 状态机、玩法、完成条件 |
| Runtime Boundaries | Agent 运行时可调范围 |
| Negative Examples | 失败、违规、投诉案例 |
| Audit Log | 所有校验和修复记录 |

## 7. 校验类型

| 校验类型 | 示例 |
|---|---|
| Schema 校验 | 字段缺失、类型错误 |
| 内容合规 | 收益承诺、投资建议、夸大奖励 |
| 规则校验 | 状态不可达、完成条件冲突 |
| 奖励校验 | 奖励性质、领取条件、库存 |
| CTA 校验 | 链接授权、展示时机、归因 |
| 风控校验 | 重复领取、高频点击、防刷 |
| 埋点校验 | 曝光、开始、完成、分享、CTA、转化 |
| Agent 策略校验 | 动态策略是否越界 |

## 8. 校验结果分级

| 等级 | 处理方式 |
|---|---|
| `pass` | 可进入下一环节 |
| `warning` | 可继续，但提示风险 |
| `repair_required` | 必须自动修复或人工修改 |
| `manual_review` | 需要人工审核 |
| `blocked` | 阻止构建或发布 |

## 9. 修复路径

| 问题 | 回到哪里 |
|---|---|
| 文案不合规 | Generation Agent |
| 规则不可执行 | Rule Agent |
| 策略越界 | Policy Agent |
| CTA 不合法 | 关键变量或 CTA 配置 |
| 奖励表达风险 | 奖励配置和合规文案 |
| 埋点缺失 | Tracking Agent 或 Builder 配置 |
| 项目事实错误 | Project Context |

## 10. 约束边界

| 边界 | 说明 |
|---|---|
| 约束系统一票否决 | 高风险问题不能发布 |
| Prompt 不是约束系统 | 规则必须在服务端可验证 |
| 负样本必须回写 | 失败案例进入规则库 |
| 校验必须版本化 | 方便回溯 |
| Runtime 也要校验 | 运行时决策也不能越界 |

## 11. MVP 范围

| P0 能力 | 说明 |
|---|---|
| Schema Validator | 保证结构完整 |
| Compliance Checklist | 禁止表达和免责声明 |
| Rule Validator | 基础状态机和完成条件 |
| CTA Validator | 链接和归因 |
| Tracking Validator | 核心事件检查 |
| Validation Report | 输出可读报告 |

## 12. P1 / P2 扩展

| 阶段 | 能力 |
|---|---|
| P1 | Critic Agent、自动修复、负样本库 |
| P2 | 多渠道规则适配、动态合规、自动规则升级 |

## 13. 验收标准

| 验收项 | 标准 |
|---|---|
| 可阻断 | 高风险问题不能进入发布 |
| 可解释 | 每个问题有原因和位置 |
| 可修复 | 能输出结构化修复建议 |
| 可审计 | 所有校验有记录 |
| 可回写 | 失败案例进入负样本和约束库 |

## 14. 最终结论

约束验证是 Airvana Agent OS 的治理核心。

没有它，AI 生成会失控；有了它，Agentic Playable 才能安全生成、构建、发布和运行。
