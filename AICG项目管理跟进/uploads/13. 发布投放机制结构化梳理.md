# 发布投放机制结构化梳理

## 1. 核心定义

发布投放，是指 Agentic Playable 在完成 H5 组装、模拟测试、KOL 二次编辑和平台审核之后，被锁定为正式版本，并通过 Airvana 的发布服务、渠道链接、分享资产和媒体连接器分发到外部渠道，同时回收曝光、点击、开始、完成、分享、CTA、转化和渠道质量数据。

它包含两个连续动作：

| 动作 | 含义 |
|---|---|
| 发布 | Airvana 内部把通过审核的 `playable_version` 锁定为正式版本，生成 `publish_url`、渠道参数、分享资产和发布记录 |
| 投放 | 通过 X、Telegram、Discord、广告平台、官网、社群、KOL 私域等渠道把作品分发出去，并通过连接器或追踪链接回收数据 |

关键前提：

**Airvana 支持媒体连接器，但作品不能绕过平台审核直接投放。必须先通过平台审核，再进入发布和媒体分发。**

一句话：

**发布投放 = 平台审核通过后，把 Agentic Playable 的正式版本、渠道链接、媒体连接器、分享资产、归因参数和数据回收打通。**

## 2. 在完整工作流中的位置

发布投放发生在 KOL 二次编辑和回归测试之后、运行时优化和数据反馈之前。

| 阶段 | 输入 | 输出 |
|---|---|---|
| KOL 身份识别 | KOL 注册、社媒、历史 campaign、风险信号 | `kol_context` |
| 营销目标选择 | 目标、CTA、指标、渠道 | `campaign_goal` |
| 模板推荐 | 目标、KOL、资产、渠道 | `template_schema` |
| 关键变量填写 | 主题、奖励、任务、CTA、风格 | `template_config` |
| Brief 生成 | 上游意图和约束 | `generation_brief` |
| 内容生成 | Brief、模板、资产库 | `content_assets` |
| 游戏规则生成 | Brief、模板、内容、目标 | `game_rules` |
| Agent 运营策略生成 | 目标、规则、用户路径、风险 | `agent_policy` |
| 约束与合规验证 | 内容、规则、策略、目标、资产 | `validation_report` |
| H5 Playable 组装 | 通过验证的对象、模板代码、资产 | `playable_version` |
| 模拟测试 | 可运行版本、模拟用户、关键路径 | `simulation_result` |
| KOL 二次编辑 | 预览版本、KOL 修改、可编辑字段 | `config_patch`、新版本 |
| 平台审核 | 待发布版本、审核材料、渠道计划 | `platform_review` |
| 发布投放 | 审核通过版本、渠道、连接器授权 | `publish_url`、`distribution_record` |
| 运行时优化 | 用户事件、渠道表现、Agent 策略 | `runtime_decision` |
| 数据反馈 | 事件、结果、投放质量、Agent 决策 | `kol_memory`、`template_memory` |

关键原则：

1. 没有平台审核通过，不能进入投放。
2. 没有 `simulation_result`，不能提交正式发布。
3. 审核通过后要锁定版本，不能原地修改。
4. 每个渠道都必须有独立归因参数。
5. 媒体连接器只能发布审核通过的正式版本。

## 3. 发布和投放的边界

| 问题 | 发布 | 投放 |
|---|---|---|
| 发生在哪里 | Airvana 平台内部 | 外部媒体、社群、广告和私域 |
| 核心对象 | `publish_url`、`published_version` | `distribution_record`、`connector_job` |
| 主要目标 | 形成正式可访问版本 | 把版本触达到目标用户 |
| 关键控制 | 审核、版本锁定、链接、归因 | 渠道、排期、连接器、素材、预算 |
| 数据回收 | 页面事件和归因参数 | 渠道数据、互动数据、转化数据 |
| 失败影响 | 不能对外发布 | 某个渠道投放失败或数据异常 |

发布是投放的前置条件。投放不能生成新的业务内容，只能使用发布阶段锁定的版本和素材包。

## 4. 发布投放的核心目标

| 目标 | 说明 |
|---|---|
| 可审核 | 平台能确认内容、规则、奖励、CTA、链接、渠道和风险 |
| 可锁定 | 审核通过后固定版本和素材，防止投放后内容漂移 |
| 可分发 | 支持链接、分享卡、媒体连接器和渠道包 |
| 可归因 | 每个渠道、KOL、版本、活动都能被追踪 |
| 可监控 | 投放后能看到曝光、点击、开始、完成、分享、CTA 和转化 |
| 可风控 | 异常流量、刷量、奖励滥用和违规传播能被识别 |
| 可回滚 | 出现问题时可以暂停、下线、替换或回滚版本 |
| 可复盘 | 投放结果能进入 KOL 记忆、模板优化和 Agent 策略优化 |

## 5. 主要输入

| 输入 | 来源 | 用途 |
|---|---|---|
| `playable_version` | H5 Builder | 待发布的正式版本 |

| `validation_report` | Constraint Service | 确认约束与合规状态 |
| `simulation_result` | 模拟测试 | 确认可玩、可追踪、可发布 |
| `config_patch` | KOL 二次编辑 | 确认最终修改历史 |
| `kol_context` | KOL 身份识别 | 确认 KOL 权限、渠道、风险和授权 |
| `campaign_goal` | 营销目标选择 | 决定目标动作和关键指标 |
| `channel_plan` | KOL / 运营 / 项目方 | 决定投放渠道和排期 |
| `media_connector_auth` | 媒体连接器 | 确认账号授权和发布权限 |
| `share_assets` | 内容生成 / H5 Builder | 分享卡、文案、缩略图和渠道素材 |
| `tracking_map` | H5 Builder / Analytics | 确认事件和归因参数 |
| `risk_profile` | 风控系统 | 决定审核强度和投放限制 |

| 输出对象 | 含义 |
|---|---|
| `publish_request` | 发布申请 |
| `platform_review` | 平台审核记录 |
| `published_version` | 审核通过并锁定的正式版本 |
| `publish_url` | 正式访问链接 |
| `share_url` | 分享入口链接 |
| `channel_links` | 各渠道独立追踪链接 |
| `publish_package` | 发布素材包 |
| `connector_jobs` | 媒体连接器发布任务 |
| `distribution_record` | 投放记录 |
| `attribution_config` | 归因配置 |
| `post_publish_monitor` | 发布后监控配置 |
| `rollback_plan` | 回滚或下线方案 |

## 7. 平台审核的定位

平台审核是发布投放前的最终闸口。它和前面的约束验证不同。

| 对比项 | 约束与合规验证 | 平台审核 |
|---|---|---|
| 发生时间 | 内容、规则、策略生成后 | 正式发布投放前 |
| 主要方式 | 自动校验 + 风险评分 | 平台规则 + 人工/半自动审核 |
| 检查对象 | `content_assets`、`game_rules`、`agent_policy` | 最终版本、渠道计划、连接器、投放素材 |
| 关注点 | 能不能生成和上线 | 能不能对外发布和分发 |
| 输出 | `validation_report` | `platform_review` |
| 阻断权 | 阻止组装或发布 | 阻止投放 |

平台审核重点：

| 审核项 | 说明 |
|---|---|
| 版本一致 | 待发布版本是否就是通过测试的版本 |
| 内容合规 | 文案、视觉、分享卡、CTA 是否仍合规 |
| 奖励安全 | 奖励性质、触发、上限、风控是否清楚 |
| CTA 授权 | 跳转链接是否项目方授权和可追踪 |
| 渠道适配 | X、Telegram、Discord、广告平台等素材是否合适 |
| 连接器授权 | KOL 是否授权 Airvana 连接对应媒体 |
| 埋点完整 | 正式版本事件和渠道参数是否完整 |
| 风控打开 | 高奖励、高传播场景是否开启风控 |
| 发布主体 | 谁发布、发到哪里、是否需要项目方确认 |
| 下线机制 | 出问题能否暂停、撤回或替换 |

## 8. 发布申请 `publish_request`

KOL 或运营点击发布时，不应该直接投放，而是生成发布申请。

| 字段 | 说明 |
|---|---|
| `publish_request_id` | 发布申请 ID |
| `playable_version_id` | 待发布版本 |
| `campaign_id` | 所属 campaign |
| `kol_id` | 发布 KOL |
| `requested_by` | 申请人 |
| `requested_channels` | 申请投放渠道 |
| `publish_mode` | 复制链接、连接器发布、排期发布、广告投放等 |
| `validation_report_id` | 约束验证报告 |
| `simulation_result_id` | 模拟测试报告 |
| `config_patch_ids` | 二次编辑记录 |
| `share_asset_ids` | 分享素材 |
| `cta_url` | 主要 CTA 链接 |
| `risk_level` | 风险等级 |
| `review_required` | 是否需要人工审核 |
| `submitted_at` | 提交时间 |

发布申请必须能回答：

1. 谁申请发布？
2. 发布哪个版本？
3. 发到哪些渠道？
4. 用哪些素材？
5. 目标动作是什么？
6. 是否通过验证和模拟测试？
7. 是否需要平台审核？

## 9. 平台审核 `platform_review`

| 字段 | 说明 |
|---|---|
| `platform_review_id` | 审核 ID |
| `publish_request_id` | 对应发布申请 |
| `playable_version_id` | 被审核版本 |
| `review_status` | pending、approved、rejected、needs_revision、needs_manual_review |
| `review_type` | 自动、人工、项目方、平台运营 |
| `review_scope` | 内容、奖励、CTA、渠道、连接器、数据、风控 |
| `review_items` | 审核项列表 |
| `blocked_items` | 阻断问题 |
| `warning_items` | 警告问题 |
| `required_actions` | 必须处理动作 |
| `approved_channels` | 允许投放渠道 |
| `rejected_channels` | 不允许投放渠道 |
| `reviewer_id` | 审核人 |
| `reviewed_at` | 审核时间 |
| `expires_at` | 审核有效期，可选 |

审核结果处理：

| 审核状态 | 处理 |
|---|---|
| `approved` | 锁定版本，进入发布 |
| `approved_with_warnings` | 可发布，但标记风险和监控 |
| `needs_revision` | 返回 KOL 二次编辑 |
| `needs_manual_review` | 进入人工审核队列 |
| `rejected` | 阻止发布 |
| `channel_limited` | 只允许部分渠道 |

## 10. 审核通过后的版本锁定

审核通过后，平台必须锁定版本。

| 锁定对象 | 说明 |
|---|---|
| `playable_version` | H5 正式版本 |
| `runtime_config` | 运行时配置 |
| `tracking_map` | 埋点和归因参数 |
| `share_assets` | 分享卡、缩略图、渠道文案 |
| `cta_url` | 转化目标链接 |
| `agent_policy` | 运行时策略边界 |
| `game_rules` | 玩法、奖励、CTA、风控规则 |
| `validation_report` | 审核前验证结果 |
| `simulation_result` | 发布前测试结果 |

锁定原则：

1. 审核通过后不能原地修改。
2. 修改必须生成新 `playable_version`。
3. 新版本必须重新审核。
4. 正式投放链接必须绑定固定版本。
5. 数据看板必须能按版本区分。

## 11. 发布包 `publish_package`

发布包是给发布服务和媒体连接器使用的标准产物。

| 内容 | 说明 |
|---|---|
| `publish_url` | 正式 Playable 链接 |
| `channel_links` | 各渠道追踪链接 |
| `share_cards` | 不同渠道的分享图 |
| `post_copy` | 渠道发文文案 |
| `cta_config` | CTA 链接和参数 |
| `utm_config` | UTM 参数 |
| `referral_config` | 邀请和 KOL 归因参数 |
| `thumbnail_assets` | 预览缩略图 |
| `disclaimer_copy` | 必须保留的提示 |
| `platform_notes` | 渠道限制和发布说明 |
| `connector_payloads` | 连接器发布载荷 |
| `tracking_config` | 事件和数据回收配置 |

发布包原则：

1. 不同渠道可以有不同文案和图片，但必须指向同一个审核版本。
2. 分享卡不能和审核通过的奖励、CTA、免责声明冲突。
3. 渠道文案必须带必要披露和风险提示。
4. 每个链接都必须带归因参数。

## 12. 媒体连接器的角色

媒体连接器不是审核工具，也不是内容自由生成工具。它是审核通过后的分发和数据回收工具。

| 能力 | 说明 |
|---|---|
| 账号授权 | KOL 授权 Airvana 访问或发布到指定账号 |
| 渠道识别 | 确认 KOL 可用的 X、Telegram、Discord、广告或私域渠道 |
| 素材适配 | 生成渠道格式的文案、图片、链接 |
| 授权发布 | 在授权范围内发布到对应渠道 |
| 复制发布 | 生成可复制文案和链接，让 KOL 手动发布 |
| 排期发布 | 按指定时间投放 |
| 状态回传 | 返回发布成功、失败、被拒、限流等状态 |
| 数据回收 | 拉取曝光、互动、点击、入群、转化等数据 |
| 授权撤销 | KOL 可断开连接器 |

连接器边界：

1. 未审核通过的作品不能进入连接器发布。
2. 连接器不能自动改写审核通过的关键信息。
3. 连接器只能在 KOL 授权范围内操作。
4. 私域数据采集必须最小化和授权。
5. 连接器失败不能影响已发布版本本身。

## 13. 支持的投放方式

| 投放方式 | 说明 | 适用场景 |
|---|---|---|
| 复制链接发布 | KOL 手动复制 `publish_url` 和文案 | MVP、低风险、无授权连接器 |
| 授权连接器发布 | Airvana 通过 KOL 授权账号发布 | KOL 授权社媒或社群 |
| 排期发布 | 设置发布时间和渠道 | 多渠道 campaign |
| 社群投放 | Telegram、Discord、私域群发布 | Web3 社群增长 |
| 广告投放 | 输出广告落地页链接和素材包 | 付费获客 |
| 官网嵌入 | 项目官网嵌入或跳转 H5 | 项目方自有流量 |
| KOL 联合投放 | 多个 KOL 分发不同渠道链接 | 多 KOL campaign |
| 灰度投放 | 小流量先发，确认数据后扩大 | 高风险或高预算活动 |

MVP 阶段建议先支持：

1. 复制链接发布。
2. X / Telegram / Discord 渠道链接。
3. KOL 授权连接器发布的基础流程。
4. 发布记录和数据回收。

## 14. 渠道链接与归因

每个渠道必须有独立链接或参数，否则无法判断投放效果。

| 参数 | 说明 |
|---|---|
| `campaign_id` | 活动 |
| `playable_version_id` | Playable 版本 |
| `kol_id` | KOL |
| `channel` | X、Telegram、Discord、Ads、Website 等 |
| `source` | 具体来源账号或频道 |
| `medium` | social、community、paid、owned、referral |
| `connector_id` | 媒体连接器 |
| `distribution_id` | 投放记录 |
| `share_card_id` | 分享卡版本 |
| `post_id` | 外部平台帖子 ID |
| `invite_code` | 邀请或裂变码 |
| `experiment_id` | A/B 实验，可为空 |

归因链路：

| 用户行为 | 记录 |
|---|---|
| 用户看到渠道内容 | 外部平台曝光或 Airvana 估算曝光 |
| 用户点击链接 | `publish_url` 访问和渠道参数 |
| H5 加载 | `playable_impression` |
| 用户开始 | `playable_start` |
| 用户完成 | `step_complete` / 结果状态 |
| 用户分享 | `share_click` |
| 用户点击 CTA | `cta_click` |
| 用户转化 | `conversion` |
| Agent 调整体验 | `agent_decision_applied` |

## 15. 渠道一：X / Twitter

| 模块 | 要点 |
|---|---|
| 账号授权 | KOL 授权发布或复制发布 |
| 文案长度 | 需要短文案、强首句、明确 CTA |
| 分享卡 | 图片清晰，避免夸大奖励 |
| 链接 | 使用 X 专属 `channel_link` |
| 披露 | 必要时标记合作或推广 |
| 数据回收 | 曝光、点赞、转发、评论、点击 |
| 风险 | 金融、收益、空投表达容易放大传播风险 |

适合：

1. KOL 公域传播。
2. 竞猜结果分享。
3. 空投任务入口。
4. KOL 专属房间推广。

## 16. 渠道二：Telegram

| 模块 | 要点 |
|---|---|
| 授权方式 | Bot、频道、群组、Mini App 链接或复制发布 |
| 内容形态 | 群消息、频道公告、任务入口 |
| 链接 | Telegram 专属 `channel_link` 或 Mini App 入口 |
| CTA | 入群、查看任务进度、领取资格 |
| 数据回收 | 点击、入群、任务完成、邀请 |
| 风控 | 群内刷量、重复钱包、重复设备 |
| 隐私 | 私域数据必须授权，不默认读取私聊 |

适合：

1. Web3 社群增长。
2. 空投任务。
3. 项目活动群运营。
4. Bot 任务链。

## 17. 渠道三：Discord

| 模块 | 要点 |
|---|---|
| 授权方式 | Server、频道、Bot、角色权限 |
| 内容形态 | 频道消息、活动入口、任务说明 |
| CTA | 加入 Server、领取角色、完成任务 |
| 链接 | Discord 专属 `channel_link` |
| 数据回收 | 点击、成员加入、任务完成、角色领取 |
| 风控 | 虚假邀请、刷角色、重复账号 |
| 权限 | 必须明确 Bot 或连接器权限 |

适合：

1. 社区任务。
2. 角色奖励。
3. 项目 Discord 活动。
4. 长期社区留存。

## 18. 渠道四：广告平台

| 模块 | 要点 |
|---|---|
| 素材包 | 落地页链接、标题、描述、缩略图 |
| 审核 | 广告平台可能有额外审核 |
| 链接 | 广告专属 `channel_link` |
| 数据 | 展示、点击、成本、转化、ROAS |
| 风险 | 金融、博彩、抽奖、收益承诺限制更严格 |
| 归因 | Airvana 事件 + 广告平台数据对齐 |

MVP 阶段可以先输出广告素材包和链接，不必直接对接复杂广告投放 API。

## 22. 发布流程

| 步骤 | 动作 | 输出 |
|---|---|---|
| 1. KOL 点击提交发布 | 选择要发布的版本和渠道 | `publish_request` |
| 2. 系统检查前置条件 | 验证、测试、版本、连接器授权 | 准入结果 |
| 3. 平台审核 | 审核内容、奖励、CTA、渠道、链接、风控 | `platform_review` |
| 4. 审核通过 | 锁定版本和素材 | `published_version` |
| 5. 生成正式链接 | 生成 `publish_url` 和 `share_url` | 正式链接 |
| 6. 生成渠道链接 | 按渠道生成 `channel_links` | 归因链接 |
| 7. 生成发布包 | 文案、分享卡、缩略图、渠道参数 | `publish_package` |
| 8. 创建连接器任务 | 对接 X、Telegram、Discord 等 | `connector_jobs` |
| 9. 发布或排期 | 立即发布、排期、复制发布 | 外部发布结果 |
| 10. 记录投放 | 保存渠道、账号、帖子、链接 | `distribution_record` |
| 11. 开启监控 | 回收事件和外部渠道数据 | `post_publish_monitor` |
| 12. 数据反馈 | 进入看板、Agent 优化、KOL 记忆 | `kol_memory`、`template_memory` |

## 23. 发布前准入条件

| 条件 | 是否必须 | 说明 |
|---|---:|---|
| `playable_version` 存在 | 必须 | 必须发布具体版本 |
| `validation_report` 通过 | 必须 | 约束和合规不通过不能发布 |
| `simulation_result` 通过 | 必须 | 可玩、可追踪、可转化 |
| KOL 二次编辑已关闭 | 必须 | 当前版本不再有未处理 Patch |
| 平台审核通过 | 必须 | 作品必须先审核再投放 |
| CTA 链接授权 | 必须 | 防止错误跳转和安全风险 |
| 关键埋点完整 | 必须 | 防止数据断层 |
| 渠道参数完整 | 必须 | 防止无法归因 |
| 分享素材完整 | 必须 | 防止渠道展示异常 |
| 连接器授权有效 | 连接器发布必需 | 复制发布可不需要 |
| 回滚方案存在 | 建议 | 出现问题可暂停或回退 |

## 24. 平台审核失败后的回流

| 失败类型 | 回流环节 |
|---|---|
| 文案违规 | KOL 二次编辑 / 内容生成 |
| 分享卡误导 | 内容生成 / 视觉生成 |
| 奖励表达风险 | 约束验证 / 游戏规则生成 |
| CTA 链接未授权 | 关键变量 / 项目方配置 |
| CTA 与目标冲突 | 营销目标选择 / Agent 策略 |
| 埋点缺失 | H5 组装 / `tracking_map` |
| 模拟测试过期 | 模拟测试 |
| 连接器未授权 | KOL 授权流程 |
| 渠道不允许 | 渠道计划调整 |
| KOL 风险过高 | 人工审核 / 限制投放 |

平台审核失败不能直接绕过，也不能通过媒体连接器强行投放。

## 25. 投放后监控

发布后必须进入监控，而不是只生成链接。

| 监控项 | 说明 |
|---|---|
| 链接可访问 | `publish_url` 是否正常 |
| 渠道发布状态 | 连接器是否发布成功 |
| 外部互动 | 曝光、点赞、评论、转发、入群 |
| H5 漏斗 | 曝光、开始、完成、分享、CTA、转化 |
| 渠道质量 | 不同渠道的完成率和转化率 |
| KOL 效果 | 不同 KOL 的流量质量 |
| Agent 决策效果 | 动态策略是否提升完成或 CTA |
| 风控信号 | 异常点击、重复领取、刷量 |
| 投诉和举报 | 外部平台或用户反馈 |
| 链接健康 | 404、跳转失败、CTA 失败 |

发布后关键指标：

| 指标 | 含义 |
|---|---|
| Impression | 外部平台曝光或 H5 曝光 |
| CTR | 渠道点击率 |
| Start Rate | 点击后开始率 |
| Completion Rate | 完成率 |
| Share Rate | 分享率 |
| CTA Rate | CTA 点击率 |
| Conversion Rate | 目标转化率 |
| Retention | 回访和复玩 |
| Risk Rate | 异常流量和奖励滥用 |
| ROAS | 付费投放时的投入产出 |

## 26. 暂停、下线和回滚

发布投放必须有事故处理能力。

| 动作 | 说明 |
|---|---|
| Pause | 暂停某个渠道投放 |
| Unpublish | 下线正式链接 |
| Takedown | 撤回或删除连接器发布内容 |
| Rollback | 回滚到上一个已审核版本 |
| Replace Link | 替换渠道链接到新版本 |
| Disable Reward | 临时关闭奖励触发 |
| Disable Agent Policy | 降级为默认策略 |
| Block Channel | 暂停某个渠道 |
| Manual Review | 进入人工复审 |

触发条件：

1. 奖励被刷。
2. CTA 跳转异常。
3. 分享卡被投诉。
4. 外部平台拒绝或限制。
5. 异常流量过高。
6. KOL 发布错误版本。
7. 用户无法完成核心路径。
8. 合规或项目方要求下线。

## 27. 前台 KOL 看到什么

KOL 前台不需要看到复杂发布系统，但需要清楚知道状态和下一步。

| 前台状态 | 展示 |
|---|---|
| 待提交审核 | 当前版本可提交平台审核 |
| 审核中 | 平台正在审核内容和投放渠道 |
| 审核需修改 | 展示具体修改原因 |
| 审核通过 | 可选择投放渠道 |
| 连接器未授权 | 引导授权 X、Telegram、Discord 等 |
| 待发布 | 已生成链接或排期 |
| 已发布 | 展示正式链接、渠道和数据 |
| 投放异常 | 展示失败渠道和修复建议 |
| 已暂停 | 说明暂停原因 |

KOL 的理想流程：

1. 选择最终版本。
2. 提交平台审核。
3. 审核通过。
4. 选择投放渠道。
5. 授权或选择复制发布。
6. 发布或排期。
7. 查看渠道数据和 H5 数据。

## 35. 不建议的做法

| 不建议做法 | 问题 |
|---|---|
| 审核前直接连接器发布 | 平台风险不可控 |
| 生成 `publish_url` 后继续原地修改 | 数据归因和审核失效 |
| 所有渠道共用一个链接 | 无法判断渠道效果 |
| 分享卡不走审核 | 外部传播风险高 |
| CTA 链接不校验 | 安全和归因风险 |
| 媒体连接器默认读取私域数据 | 隐私和信任风险 |
| 发布成功后不监控 | 无法发现刷量、投诉和链接异常 |
| 发布后再补埋点 | 数据断层无法修复 |
| 连接器失败就认为 campaign 失败 | 应降级为复制发布或换渠道 |
| 没有暂停和下线机制 | 出现风险时无法止损 |

## 36. 结论

发布投放是 Agentic Playable 从“可预览版本”走向“真实外部增长”的正式出口。

它要回答五个问题：

| 问题 | 对应机制 |
|---|---|
| 作品能不能对外发？ | 平台审核 `platform_review` |
| 发的是哪个固定版本？ | `published_version` 和版本锁定 |
| 发到哪里？ | `channel_links` 和 `distribution_record` |
| 怎么通过媒体连接器发？ | `media_connector_auth` 和 `connector_job` |
| 发出去以后怎么复盘？ | 归因参数、事件回收和投放监控 |

MVP 阶段最重要的是：

1. 先建立“提交发布 -> 平台审核 -> 版本锁定 -> 生成链接 -> 渠道分发”的硬流程。
2. 媒体连接器只能分发审核通过的版本，不能绕过审核。
3. 每个渠道必须有独立归因链接。
4. 发布包要包含分享卡、文案、CTA、免责声明和追踪参数。
5. 发布后必须能暂停、下线、回滚，并把数据回收到 Airvana 看板和记忆系统。

这样，Airvana 的发布投放就不是简单生成链接，而是把审核、版本、渠道、连接器、归因、监控和数据反馈组成一条可运营的增长链路。
