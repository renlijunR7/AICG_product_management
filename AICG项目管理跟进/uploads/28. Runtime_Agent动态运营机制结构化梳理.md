# Runtime Agent 动态运营机制结构化梳理

## 1. 核心定义

Runtime Agent 动态运营机制，是用户进入 H5 后的在线决策层。

它根据用户行为、分群、渠道、进度、风险和 `agent_policy`，在 `game_rules` 与 `runtime_boundaries` 内动态调整提示、难度、奖励、CTA、分享和风控。

核心产物：

| 产物 | 说明 |
|---|---|
| `runtime_decision` | 单次运行时决策 |
| `agent_decision_applied` | 决策应用事件 |
| `user_segment` | 用户分群 |
| `runtime_metrics` | 运行时指标 |
| `risk_action` | 风控动作 |

## 2. 所处位置

| 上游 | 当前环节 | 下游 |
|---|---|---|
| `publish_url`、`runtime_config`、用户事件 | Runtime Agent 动态运营 | 数据反馈、Memory 与模板更新 |

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 提升完成率 | 降低卡点和流失 |
| 提升分享率 | 在合适节点引导分享 |
| 提升 CTA | 对高意向用户展示转化路径 |
| 控制风险 | 防刷、重复领取、异常流量 |
| 支持复盘 | 每次决策都能被追踪 |

## 4. 输入数据

| 输入 | 用途 |
|---|---|
| `runtime_events` | 用户实时行为 |
| `session_state` | 当前进度、分数、失败次数 |
| `user_segment` | 用户分群 |
| `channel_context` | 渠道来源 |
| `agent_policy` | 可执行策略 |
| `game_rules` | 玩法和奖励边界 |
| `runtime_boundaries` | Agent 可调范围 |
| `risk_signals` | 风险信号 |

## 5. 关键 Agent / 系统

| 模块 | 职责 |
|---|---|
| Runtime Agent | 生成运行时决策 |
| Segmentation Agent | 更新用户分群 |
| Risk Agent | 识别异常和防刷 |
| Recommendation Agent | 推荐下一任务或 CTA |
| Runtime Decision Engine | 执行策略匹配和边界校验 |
| Runtime SDK | 前端应用决策和上报事件 |

## 6. 决策类型

| 类型 | 示例 |
|---|---|
| 动态难度 | 降低障碍、减少题目、增加容忍 |
| 动态提示 | 用户失败后给提示 |
| 动态奖励 | 展示进度或强化完成激励 |
| 动态 CTA | 高意向用户展示入群或领取按钮 |
| 动态分享 | 根据成绩生成分享卡 |
| 动态留存 | 完成后推荐下一挑战 |
| 动态风控 | 延迟发奖、限频、验证 |
| 动态回退 | 策略失败时回默认配置 |

## 7. 用户分群

| 分群 | 动作 |
|---|---|
| 新用户 | 简化引导 |
| 低完成用户 | 提示和降难度 |
| 高参与用户 | CTA 和分享 |
| 分享倾向用户 | 强化分享卡 |
| 奖励敏感用户 | 展示进度并加强风控 |
| 回访用户 | 推荐下一任务 |
| 风险用户 | 验证、限频、延迟发奖 |

## 8. 决策流程

| 步骤 | 说明 |
|---|---|
| 1 | 用户产生事件 |
| 2 | 更新会话状态 |
| 3 | 更新用户分群 |
| 4 | 匹配 `agent_policy` |
| 5 | 检查 `game_rules` 和边界 |
| 6 | 生成 `runtime_decision` |
| 7 | 前端或服务端应用动作 |
| 8 | 记录 `agent_decision_applied` |
| 9 | 观察后续结果 |
| 10 | 进入数据反馈 |

## 9. 约束边界

| 约束 | 说明 |
|---|---|
| 不改主目标 | 不能把教育活动变成交易引导 |
| 不改核心规则 | 完成条件不能被 Runtime Agent 随意改变 |
| 不改奖励性质 | 虚拟积分不能变真实 Token |
| 不绕过风控 | 风控优先于增长策略 |
| 不展示未审核内容 | 动态文案来自审核池 |
| 不删除日志 | 每次决策必须记录 |

## 10. MVP 范围

| P0 能力 | 说明 |
|---|---|
| 动态提示 | 根据失败和停留触发 |
| 动态 CTA | 根据完成和高意向触发 |
| 基础分群 | 新用户、低完成、高意向、风险 |
| 基础风控 | 重复领取、高频点击 |
| 决策日志 | `agent_decision_applied` |
| 默认回退 | Runtime 失败时静态体验 |

## 11. P1 / P2 扩展

| 阶段 | 能力 |
|---|---|
| P1 | 动态难度、动态分享、实验分组 |
| P2 | 自动策略学习、跨活动个性化、预算联动 |

## 12. 验收标准

| 验收项 | 标准 |
|---|---|
| 决策可触发 | 用户事件能触发 Runtime 决策 |
| 决策可应用 | 前端能改变提示、CTA、难度 |
| 决策可追踪 | 有 `agent_decision_applied` |
| 决策不越界 | 通过规则和边界校验 |
| 效果可复盘 | 后续事件能关联决策 |

## 13. 最终结论

Runtime Agent 是 Agentic Playable 区别于静态 H5 的核心。

它让 Playable 在用户真实互动中根据状态动态运营，但必须始终受规则、合规、风控和日志约束。
