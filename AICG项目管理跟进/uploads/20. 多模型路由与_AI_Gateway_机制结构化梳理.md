# 多模型路由与 AI Gateway 机制结构化梳理

## 1. 核心定义

多模型路由与 AI Gateway，是 Airvana Agent OS 的模型调用控制层。

它统一管理模型选择、调用、成本、延迟、重试、降级、日志、安全和评估，避免每个 Agent 直接散乱调用模型。

核心产物：

| 产物 | 说明 |
|---|---|
| `model_route_plan` | 本次任务应该调用什么模型 |
| `llm_call_log` | 每次模型调用日志 |
| `prompt_version` | Prompt 模板版本 |
| `fallback_result` | 降级或重试结果 |

## 2. 所处位置

| 上游 | 当前环节 | 下游 |
|---|---|---|
| Agent 任务、RAG 上下文、风险等级 | AI Gateway 和 Model Router | 多 Agent 执行、生成、校验、复盘 |

AI Gateway 是所有 Agent 调模型的唯一入口。

## 3. 业务目标

| 目标 | 说明 |
|---|---|
| 控制成本 | 不同任务使用不同成本模型 |
| 提升质量 | 高价值策略和诊断用强模型 |
| 提升稳定性 | 模型失败可重试和降级 |
| 强化审计 | 所有调用有日志 |
| 统一 Prompt | 避免 Prompt 散落在代码和 Agent 中 |
| 控制风险 | 高风险内容进入更严格模型和校验链路 |

## 4. 输入数据

| 输入 | 用途 |
|---|---|
| `agent_task` | 判断任务类型 |
| `task_risk_level` | 判断是否需要强校验 |
| `context_length` | 判断模型上下文能力 |
| `latency_requirement` | 判断是否走快速模型 |
| `quality_tier` | 判断输出质量要求 |
| `budget_limit` | 控制成本 |
| `fallback_policy` | 调用失败后的策略 |

## 5. 模型路由策略

| 任务 | 推荐模型策略 |
|---|---|
| 字段抽取 | 小模型、低成本 |
| 目标识别 | 小模型 + 规则 |
| 生成模式判断 | 小模型 + 风险规则 |
| Brief 生成 | 中等模型 |
| 策略规划 | 强推理模型 |
| 文案生成 | 创意模型 |
| 规则生成 | 强推理模型 + schema 约束 |
| 合规校验 | 规则引擎优先，模型辅助 |
| 代码/构建辅助 | 代码模型 |
| 运行时实时决策 | 低延迟模型或规则策略 |
| 数据复盘诊断 | 强推理模型 |
| Embedding | 专用向量模型 |

## 6. 关键模块

| 模块 | 职责 |
|---|---|
| AI Gateway | 统一模型调用入口 |
| Model Router | 根据任务选择模型 |
| Prompt Registry | 管理 Prompt 模板和版本 |
| Cost Controller | 管理预算、token 和频率 |
| Retry Manager | 失败重试 |
| Fallback Handler | 降级策略 |
| Safety Filter | 输入输出安全过滤 |
| Call Logger | 模型调用日志 |
| Eval Service | 模型效果评估 |

## 7. 关键 Agent

| Agent | 职责 |
|---|---|
| Routing Agent | 判断任务与模型匹配 |
| Prompt Builder | 根据任务拼装 Prompt |
| Critic Agent | 对重要输出做二次审查 |
| Cost Agent | 判断是否超预算 |
| Fallback Agent | 模型失败时选择替代路径 |

## 8. 数据对象结构

| 字段 | 说明 |
|---|---|
| `call_id` | 调用 ID |
| `agent_name` | 发起调用的 Agent |
| `task_type` | 任务类型 |
| `model_name` | 使用模型 |
| `prompt_version` | Prompt 版本 |
| `input_tokens` | 输入 token |
| `output_tokens` | 输出 token |
| `latency_ms` | 延迟 |
| `cost` | 成本 |
| `status` | 成功、失败、重试、降级 |
| `validation_result` | 输出校验结果 |

## 9. 约束边界

| 约束 | 说明 |
|---|---|
| Agent 不能绕过 Gateway | 所有模型调用必须被记录 |
| 高风险输出不能直出 | 必须经过约束校验 |
| Prompt 必须版本化 | 方便回溯和评估 |
| 模型输出不能当最终事实 | 关键事实必须有来源 |
| 失败必须可降级 | 不能让单次模型失败中断全链路 |

## 10. MVP 范围

| P0 能力 | 说明 |
|---|---|
| 统一模型调用 API | Agent 统一走 Gateway |
| 3 类任务路由 | 抽取、小创作、强推理 |
| 调用日志 | 记录模型、Prompt、成本、延迟 |
| 基础重试 | 超时和失败重试 |
| Prompt 版本 | 核心 Prompt 可追踪 |
| 风险分级 | 高风险任务进入强校验 |

## 11. P1 / P2 扩展

| 阶段 | 能力 |
|---|---|
| P1 | 多供应商路由、自动降级、离线评估 |
| P2 | 动态成本优化、模型效果排行榜、策略性模型选择 |

## 12. 验收标准

| 验收项 | 标准 |
|---|---|
| 可统一 | 所有 Agent 调用模型都经过 Gateway |
| 可追踪 | 每次调用有日志 |
| 可控成本 | 能按活动、KOL、Agent 统计成本 |
| 可降级 | 模型失败时有备选策略 |
| 可评估 | 能比较不同模型在任务上的效果 |

## 13. 最终结论

AI Gateway 是 Agent OS 的模型基础设施。

它不直接产生业务结果，但决定整个多 Agent 系统是否稳定、可控、可审计、可规模化。
