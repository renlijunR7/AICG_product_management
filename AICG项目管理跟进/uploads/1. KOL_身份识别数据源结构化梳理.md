# KOL 身份识别数据源结构化梳理

## 1. 目标

Airvana 平台里的 KOL 身份识别，不只是确认“这个人是谁”，而是要回答 6 个业务问题：

| 问题 | 业务意义 |
|---|---|
| 他是谁 | 账号主体、平台身份、社交身份、项目关系 |
| 他影响谁 | 粉丝画像、社区类型、地域语言、兴趣标签 |
| 他适合做什么 | 适合的 Playable 类型、营销目标、内容风格 |
| 他有什么风险 | 合规风险、虚假流量、奖励滥用、品牌风险 |
| 他过去表现如何 | 点击、完玩、分享、CTA、转化和用户质量 |
| 系统应该如何生成 | 首屏语气、模板推荐、奖励节奏、CTA、分享卡和运行时策略 |

因此，KOL 身份识别的数据源要分成多层：注册信息只是基础身份，社交媒体连接器只是外部公开影响力，真正有价值的是把平台内行为、历史 campaign、社区资产、Web3 身份、合作关系、风控信号和人工运营沉淀合并成一个持续更新的 `kol_context`。

## 2. 数据源总览

| 数据源类型 | 是否 MVP 必需 | 主要回答什么 |
|---|---:|---|
| 平台注册与 Onboarding | 必需 | KOL 自己声明的身份、行业、目标、联系方式 |
| 社交媒体连接器 | 必需 | 真实账号、粉丝规模、内容主题、互动质量 |
| 平台内创作行为 | 必需 | KOL 实际偏好什么模板、怎么改、愿意发布什么 |
| Campaign 历史表现 | 必需 | 这个 KOL 带来的流量和转化质量 |
| 项目方邀请与合作关系 | P1 | KOL 与项目、品牌、社区的关系强度 |
| 社群与私域连接器 | P1 | Telegram、Discord、微信群、社群活跃度和角色 |
| Web3 身份与链上信号 | P1 | 钱包、链上活跃、NFT/Token/DAO 相关身份 |
| 公开网页与媒体资料 | P1 | 媒体报道、访谈、Newsletter、个人网站、Link-in-bio |
| 人工运营与 BD 记录 | P1 | 合作意愿、报价、沟通质量、禁忌点 |
| 第三方创作者/广告数据 | P2 | 外部影响力评分、受众质量、品牌安全 |
| 风控与合规数据 | P1 | 虚假粉、刷量、违规推广、投诉、异常流量 |
| 结算与商业数据 | P2 | 合作成本、佣金、ROI、付款与合同状态 |

## 3. 数据源一：平台注册与 Onboarding

这是身份识别的最基础数据源，但不能作为唯一真相。它是 KOL 自我声明的数据，适合用于冷启动和后续校验。

| 字段 | 示例 | 用途 |
|---|---|---|
| 基础身份 | 昵称、真实姓名或团队名、头像、邮箱、手机号 | 账号识别、通知、登录安全 |
| 账号类型 | 个人 KOL、机构、项目方、MCN、社区主理人 | 决定权限、合作方式、模板推荐 |
| 语言和地区 | 中文、英文、东南亚、欧美、香港等 | 决定文案、发布时间、合规边界 |
| 行业标签 | Web3、GameFi、交易、NFT、AI、消费品等 | 决定模板和素材库 |
| 粉丝规模自报 | 1 万、10 万、100 万以上 | 初始影响力判断，需要外部校验 |
| 主要平台 | X、TikTok、YouTube、Telegram、Discord 等 | 引导连接器授权 |
| 合作目标 | 拉新、转化、空投预热、社群增长、教育用户 | 决定 Agentic Playable 生成目标 |
| 合作限制 | 不接交易所、不发收益承诺、不做抽奖等 | 进入约束系统 |

推荐在注册后增加一个轻量化 Onboarding 问卷：

| 问卷问题 | 转换成的系统标签 |
|---|---|
| 你主要影响哪类用户 | `audience_segment` |
| 你更擅长哪种内容 | `content_style` |
| 你通常用什么语气表达 | `tone_profile` |
| 你希望粉丝完成什么动作 | `preferred_cta` |
| 你不愿意推广什么内容 | `negative_constraints` |
| 你希望活动多长时间见效 | `campaign_cycle_preference` |

## 4. 数据源二：社交媒体连接器

这是你已经提到的关键数据源。它的核心价值不是“拿到账号链接”，而是验证 KOL 的真实影响力、内容主题、互动质量和粉丝匹配度。

| 平台 | 可采集信息 | 识别价值 |
|---|---|---|
| X / Twitter | 账号、粉丝、发文、互动、转推、话题、Space | Web3 KOL 影响力、项目传播能力 |
| YouTube | 频道、订阅、视频主题、播放、评论、观看趋势 | 长内容教育能力、深度信任 |
| TikTok | 短视频主题、播放、互动、增长趋势 | 快速破圈、娱乐化传播 |
| Instagram | 图片/短视频风格、互动、品牌合作 | 视觉内容和生活方式影响力 |
| Telegram | 频道成员、群活跃、转发、管理员身份 | Web3 私域触达和社群运营 |
| Discord | 服务器角色、活跃频道、成员互动 | 项目社区运营能力 |
| Twitch / Kick | 直播内容、观看时长、互动 | 游戏类 KOL 和实时互动能力 |
| LinkedIn | 专业身份、行业关系、机构背书 | B2B、项目方、机构合作识别 |
| Farcaster / Lens | Web3 原生社交身份、链上社交图谱 | Web3 原生用户影响力 |

社交连接器应该沉淀 6 类标签：

| 标签类型 | 说明 |
|---|---|
| 影响力标签 | 粉丝数、互动率、真实活跃度、增长趋势 |
| 内容标签 | 高频话题、内容类型、项目偏好、语言风格 |
| 受众标签 | 粉丝地域、语言、兴趣、是否 Web3 原生 |
| 传播标签 | 转发能力、评论质量、社群扩散能力 |
| 信任标签 | 历史合作透明度、是否披露广告、粉丝信任度 |
| 风险标签 | 异常涨粉、低质互动、争议内容、违规推广 |

## 5. 数据源三：平台内创作行为

平台内行为比自我声明更可靠，因为它反映 KOL 实际怎么使用 Airvana。

| 行为 | 可识别内容 |
|---|---|
| 选择了哪些模板 | 偏好竞猜、盲盒、答题、抽奖、任务链还是排行榜 |
| 修改了哪些字段 | 最关心标题、奖励、玩法、分享卡还是 CTA |
| 放弃在哪一步 | 是模板不匹配、字段太多、预览不满意，还是发布门槛高 |
| 反复重生成什么 | 对语气、题目、奖励节奏或视觉风格不满意 |
| 是否使用 Agent 建议 | 对自动策略的信任程度 |
| 是否手动覆盖策略 | KOL 对风险、品牌和转化的偏好 |
| 是否保存模板 | 是否适合长期资产化 |

这些行为可以形成 `kol_creation_profile`：

| 字段 | 含义 |
|---|---|
| `preferred_template_types` | 常用模板类型 |
| `editing_focus` | 最常改的字段 |
| `tone_preference` | 喜欢的表达方式 |
| `risk_sensitivity` | 对合规、奖励、品牌风险的敏感度 |
| `automation_acceptance` | 愿不愿意接受 Agent 自动建议 |
| `publish_confidence` | 从生成到发布的完成概率 |

## 6. 数据源四：Campaign 历史表现

这是最重要的身份识别数据之一。KOL 的真实价值不只看粉丝数，而是看他能带来什么质量的用户和结果。

| 指标 | 说明 | 识别价值 |
|---|---|---|
| 曝光量 | Playable 被看到多少次 | 流量规模 |
| 开始率 | 多少人真正开始玩 | 首屏和 KOL 号召力 |
| 完成率 | 多少人走到结果页 | 用户质量和玩法匹配度 |
| 分享率 | 多少人愿意传播 | 社交裂变能力 |
| CTA 点击率 | 多少人点击转化按钮 | 商业转化意图 |
| 最终转化 | 注册、入群、领取、购买、关注等 | campaign 目标达成 |
| 用户留存 | 是否复玩、复访、持续参与 | 长期用户质量 |
| 异常率 | 刷量、重复领取、无效点击 | 风控风险 |

建议把 KOL 分成效果类型：

| 类型 | 特征 | 推荐策略 |
|---|---|---|
| 高点击低完成 | 有流量，但内容或玩法不匹配 | 优化首屏承诺和游戏难度 |
| 低点击高完成 | 粉丝少但精准 | 做小规模高信任 campaign |
| 高分享低转化 | 传播强但商业意图弱 | 调整 CTA 和奖励结构 |
| 高转化高风险 | 数据好但异常高 | 加强反作弊和奖励限制 |
| 中等流量高留存 | 长期价值好 | 适合做 KOL 专属房间和系列模板 |

## 7. 数据源五：项目方邀请与合作关系

如果 KOL 是从某个项目方活动发起点进入 Airvana，项目方本身也是重要数据源。

| 来源 | 可识别内容 |
|---|---|
| 项目方邀请链接 | KOL 与哪个项目有关联 |
| 项目方白名单 | 是否为官方合作 KOL |
| Campaign Brief | 项目方希望 KOL 触达什么人、达成什么目标 |
| 合作等级 | 核心 KOL、普通 KOL、试合作、社区志愿者 |
| 历史合作记录 | 是否曾经合作、是否按时发布、效果如何 |
| 项目方评价 | 专业度、配合度、风险点、粉丝质量 |

这部分数据可以帮助系统判断：

1. KOL 是否适合这个项目。
2. 生成内容要偏教育、拉新、转化还是社群动员。
3. 是否需要更严格的合规和品牌约束。
4. 是否给 KOL 更多可编辑权限。

## 8. 数据源六：社群与私域连接器

Web3 KOL 很多影响力不在公开粉丝数，而在 Telegram、Discord、微信群、Newsletter、付费社群和直播间里。

| 私域来源 | 可识别内容 |
|---|---|
| Telegram 频道/群 | 成员规模、发言活跃、转发能力、管理员角色 |
| Discord Server | 角色权限、活跃频道、社区任务、项目关联 |
| Newsletter | 订阅规模、打开率、点击率、主题偏好 |
| 直播间 | 同时在线、互动密度、打赏、问答质量 |
| 社群活动 | AMA、任务活动、投票、空投参与度 |
| CRM / 社群表单 | 核心粉丝、白名单用户、历史活动报名 |

注意：私域连接器必须基于授权。不要把未授权的私聊、私密群内容、敏感用户信息作为默认采集范围。

## 9. 数据源七：Web3 身份与链上信号

对于 Web3 / crypto 场景，KOL 身份识别可以引入链上身份，但要谨慎处理隐私和合规。

| 数据 | 可识别内容 | 用途 |
|---|---|---|
| 钱包地址 | 是否绑定 KOL 钱包或项目方钱包 | 身份验证、空投资格、链上活动 |
| ENS / 域名 | Web3 身份名片 | 可信度与公开身份关联 |
| NFT / POAP | 活动参与、社区身份、历史贡献 | 社群影响力和兴趣标签 |
| DAO 投票 | 治理参与、项目偏好 | 专业度和社区角色 |
| 合约交互 | 使用过哪些协议或 GameFi 产品 | 玩法偏好和用户匹配 |
| 链上活动频率 | 活跃链、资产类别、交互周期 | Web3 原生程度 |
| 链上异常 | 批量地址、女巫攻击、异常领取 | 风控与反作弊 |

链上数据不应该直接等同于 KOL 质量。它更适合补充判断：

1. 这个 KOL 是否真正处在 Web3 圈层。
2. 他适合推广哪类链、项目、资产或任务。
3. 奖励和空投活动是否需要更强反作弊。
4. 用户参与后是否能做链上归因。

## 10. 数据源八：公开网页与媒体资料

当 KOL 没有完整授权社交连接器时，可以使用公开资料做弱识别，但要标注置信度。

| 来源 | 可采集内容 |
|---|---|
| 个人网站 | 简介、案例、联系方式、代表作品 |
| Link-in-bio | 多平台账号、社群入口、商业合作链接 |
| Medium / Substack / Mirror | 长文主题、专业度、项目偏好 |
| Podcast / 访谈 | 观点、行业定位、影响圈层 |
| 新闻报道 | 公开背书、争议事件、品牌风险 |
| 项目官网合作页 | 是否为官方 Ambassador 或合作 KOL |
| 活动页面 | 是否参与过 AMA、Space、线下活动 |

这类数据要进入 `public_profile_signals`，并带上：

| 元信息 | 说明 |
|---|---|
| 来源 URL | 数据来自哪里 |
| 抓取时间 | 资料是否新鲜 |
| 可信等级 | 官方、本人、第三方、未知 |
| 可验证性 | 是否能和社媒连接器或平台信息匹配 |

## 11. 数据源九：人工运营与 BD 记录

人工运营记录很重要，因为很多合作质量无法从 API 里直接看出来。

| 人工记录 | 可识别内容 |
|---|---|
| BD 沟通记录 | 合作意愿、报价、排期、偏好 |
| Account Manager 备注 | 配合度、响应速度、禁忌、风格 |
| 合同与报价 | 商业成本、结算方式、权利义务 |
| KOL Media Kit | 自我介绍、案例、粉丝画像、报价 |
| 复盘会议记录 | 哪些玩法 KOL 喜欢，哪些不愿意再做 |
| 客诉与争议 | 品牌安全、粉丝投诉、违规宣传 |

这类数据适合形成：

| 标签 | 含义 |
|---|---|
| `cooperation_quality` | 合作配合度 |
| `commercial_tier` | 商业等级 |
| `communication_style` | 沟通方式 |
| `do_not_use_constraints` | 不要触碰的内容 |
| `account_manager_notes` | 运营补充判断 |

## 12. 数据源十：第三方创作者和广告数据

第三方数据不一定 MVP 必需，但平台化后很有价值。

| 数据源 | 价值 |
|---|---|
| Influencer 数据平台 | 粉丝真实性、受众画像、历史品牌合作 |
| Brand Safety 工具 | 争议内容、违规风险、敏感主题 |
| 广告平台数据 | 投放成本、点击质量、转化归因 |
| Affiliate / Referral 系统 | 佣金、有效转化、复购 |
| CRM / CDP | 与项目方已有用户的重叠关系 |
| 支付/结算系统 | 成本、ROI、账期、历史纠纷 |

这类数据应作为辅助信号，不应该覆盖 Airvana 自己的一方数据。真正决定生成策略的，优先应该是平台内创作行为、campaign 表现和授权社交数据。

## 13. 数据源十一：风控与合规信号

KOL 身份识别必须包含风险画像，否则 Agentic Playable 运行时会把奖励、CTA 和传播策略推向不可控方向。

| 风险类型 | 信号 |
|---|---|
| 虚假影响力 | 异常涨粉、低互动、高重复评论、机器人账号 |
| 刷量风险 | 极短时间大量点击、重复设备、异常 IP、重复钱包 |
| 奖励滥用 | 多账号领取、羊毛党路径、异常完成率 |
| 合规风险 | 收益承诺、误导性推广、未披露广告合作 |
| 品牌风险 | 争议言论、敏感内容、过往投诉 |
| 数据隐私风险 | 未授权采集、超范围使用、敏感信息暴露 |

这些信号要进入 `kol_risk_profile`，并影响：

1. 是否允许发布。
2. 是否需要人工审核。
3. 是否限制奖励类型。
4. 是否降低自动化策略权限。
5. 是否要求更强的披露文案。

## 14. 汇总成 kol_context 的推荐结构

`kol_context` 不应该只是一个个人资料表，而应该是一个可持续更新的身份对象。

| 模块 | 字段示例 | 来源 |
|---|---|---|
| `identity_profile` | 名称、头像、语言、地区、账号类型 | 注册、社媒、公开网页 |
| `social_graph` | 平台账号、粉丝规模、互动率、受众标签 | 社交连接器 |
| `content_profile` | 高频主题、语气、内容形式、专业领域 | 社媒、公开资料、平台创作 |
| `audience_profile` | 用户地域、语言、兴趣、Web3 原生度 | 社媒、社群、campaign 数据 |
| `campaign_profile` | 历史目标、模板偏好、发布频率、转化表现 | Airvana campaign |
| `creation_profile` | 常改字段、模板选择、Agent 建议接受度 | 平台内创作行为 |
| `community_profile` | Telegram、Discord、Newsletter、直播间影响力 | 私域连接器 |
| `web3_profile` | 钱包、ENS、DAO、NFT、链上参与 | 链上数据 |
| `risk_profile` | 刷量、合规、品牌、隐私风险 | 风控系统、人工备注 |
| `commercial_profile` | 报价、合作等级、结算、ROI | BD、合同、结算 |
| `memory_profile` | 成功经验、失败经验、禁忌、长期偏好 | 复盘、运营备注、Diagnosis Agent |
| `data_quality` | 授权状态、更新时间、置信度、来源 | 所有数据源 |

## 15. MVP 优先级

### P0：必须先做

| 数据源 | 原因 |
|---|---|
| 注册与 Onboarding | 没有基础身份无法生成 KOL 专属版本 |
| 至少 1 个社媒连接器 | 验证真实影响力和内容风格 |
| 平台内创作行为 | 判断 KOL 实际偏好，而不是只听自述 |
| Campaign 基础数据 | 识别真实营销效果 |
| 风控基础信号 | 防止刷量、奖励滥用和违规发布 |

### P1：第二阶段补充

| 数据源 | 原因 |
|---|---|
| 项目方合作关系 | 判断 KOL 与项目的真实关联 |
| 社群连接器 | Web3 KOL 的真实影响力常在私域 |
| 公开网页与媒体资料 | 补充没有完整授权的数据 |
| 人工运营备注 | 补充 API 无法判断的合作质量 |
| Web3 钱包与链上身份 | 支撑空投、链上任务和 Web3 原生判断 |

### P2：平台化阶段

| 数据源 | 原因 |
|---|---|
| 第三方创作者数据库 | 做外部影响力校验 |
| 广告平台和 affiliate 数据 | 做更完整 ROI 归因 |
| CRM / CDP 数据 | 打通项目方用户资产 |
| 结算与商业系统 | 做商业价值分层和收益分成 |

## 16. 身份识别流程

推荐流程如下：

1. KOL 注册并填写基础信息。
2. 平台引导连接至少一个主要社媒账号。
3. 系统生成初始 `kol_context`，标注数据来源和置信度。
4. KOL 创建第一个 campaign，系统根据输入更新目标和偏好。
5. Playable 发布后，系统记录真实用户行为和 Agent 决策效果。
6. Diagnosis Agent 复盘 campaign，更新 `kol_memory`。
7. 运营或 BD 可以补充人工标签和合作备注。
8. 下一次生成时，Brief Agent 和 Strategy Agent 读取更新后的 `kol_context`。

## 17. 对 Agentic Playable 生成的直接影响

| 身份识别结果 | 影响的生成模块 |
|---|---|
| KOL 语气偏专业 | 首屏文案、题目解释、结果页文案更理性 |
| KOL 语气偏娱乐 | 玩法反馈、分享卡、排行榜更轻量和社交化 |
| 粉丝是新手 | 降低题目难度，加强教育和提示 |
| 粉丝是交易用户 | 增加行情竞猜、风险提示和策略判断 |
| 私域活跃强 | 强化社群任务、排行榜、邀请机制 |
| 分享能力强 | 强化结果卡、炫耀点和裂变奖励 |
| 转化能力强 | 提前 CTA 或提高 CTA 权重 |
| 风险较高 | 降低奖励强度、增加人工审核、限制自动策略 |
| 历史完成率低 | 缩短流程、降低难度、提前给反馈 |
| 历史分享率低 | 优化分享文案和结果反馈 |

## 18. 权限与数据治理要求

KOL 身份识别的数据源越多，越需要数据治理，否则会影响信任和合规。

| 要求 | 说明 |
|---|---|
| 明确授权 | 告诉 KOL 连接器会读取什么、用于什么 |
| 最小采集 | 只采集生成、运营、风控需要的数据 |
| 来源可追溯 | 每个字段要知道来自注册、连接器、campaign 还是人工备注 |
| 置信度标记 | 自报、公开资料、授权 API、平台一方数据置信度不同 |
| 可撤销授权 | KOL 应能断开连接器 |
| 可更新纠错 | KOL 可修改错误资料 |
| 敏感数据隔离 | 钱包、结算、联系方式、私域数据要权限隔离 |
| 人工备注审计 | 避免不可解释、不可追溯的主观标签滥用 |

## 19. 不建议 MVP 一开始做的事

| 不建议事项 | 原因 |
|---|---|
| 一开始打通所有社媒平台 | 集成成本高，先选择最关键的 1 到 2 个 |
| 采集未授权私域聊天内容 | 隐私和信任风险高 |
| 用链上资产规模判断 KOL 质量 | 容易误判，也可能造成合规风险 |
| 直接相信粉丝数 | 粉丝数不能代表转化能力 |
| 让 AI 自由推断敏感属性 | 容易产生歧视、隐私和合规问题 |
| 只依赖第三方评分 | 平台自己的 campaign 数据更有价值 |
| 没有置信度就写入长期 Memory | 会把错误身份沉淀进后续生成 |

## 20. 结论

Airvana 的 KOL 身份识别应该分成三层：

| 层级 | 说明 |
|---|---|
| 基础身份层 | 注册信息、Onboarding、社媒账号、项目方邀请 |
| 能力画像层 | 内容风格、受众画像、社群影响力、创作偏好、历史效果 |
| 风险与记忆层 | 合规风险、刷量风险、合作质量、成功经验、失败经验、长期偏好 |

MVP 阶段最务实的做法是：

1. 注册 + Onboarding 获取基础身份。
2. 连接一个核心社媒账号，验证真实影响力和内容主题。
3. 用平台内创作行为识别 KOL 偏好。
4. 用 campaign 数据识别真实营销效果。
5. 用基础风控信号保护奖励、CTA 和发布链路。
6. 把所有结果沉淀成带来源、置信度和更新时间的 `kol_context`。

这样，KOL 身份识别就不只是一个用户资料页，而会成为 Agentic Playable 生成、运营、风控和复盘的核心输入。
